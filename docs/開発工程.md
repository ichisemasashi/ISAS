## 1. 開発方針（プロジェクトを貫く原則）

要求定義フェーズで確立し、以降の全フェーズに適用する原則。

1. **反復＋敵対的レビュー**：成果物は「作成→敵対的レビュー（矛盾・欠落・非現実性の摘出）→修正」を反復して確定する。各レビューは記録票に残し、指摘を追跡IDで管理する。
2. **UXを第一級要求**：既存システム（KSAS等）の「機能はあるが使い辛い」を回避し、UXを機能と同格に扱う（要求仕様 4.11／5.1）。設計・実装でも実ユーザー参加型の検証を行う。
3. **技術リスク先行（リスクファースト）**：不確実性の高い部分（オフライン同期・地図性能・RLS×規模）は、本実装前にスパイク（技術検証）で潰す。
4. **食品安全・法令遵守を優先**：農薬記録・トレーサビリティ・GDPr等に関わる要件は優先度Mustとし、フェーズを前倒しする。
5. **段階リリース（フェーズ制）**：MVP（Phase 1）で現場入力の核を最速で価値化し、以降段階的に拡張する。

## 3. 各工程の詳細

### 工程1：要求定義（✅ 完了）

「何を作るか（What）」を合意する工程。**本プロジェクトでは反復＋敵対的レビューで実施した。**

- **進め方**：ドラフト作成 → 未決事項を順次確定（対象作物・農機連携・GAP・オフライン・規模・テナント・多言語・海外対応 等）→ 各版で**敵対的レビュー**を実施し、指摘を全件処置。
- **敵対的レビューの運用**：
  - 「この仕様のまま設計に進むと破綻・紛糾する箇所」を、擁護ではなく攻撃の視点で摘出。
  - 指摘を重大度（Critical/High/Medium/Low）と追跡ID（C-1、R2-M3 等）で管理し、記録票に残す。
  - ユーザーの意思決定で対策方針を確定 → 仕様へ反映 → 再レビュー、を収束するまで反復。
- **結果**：
  - 版：v0.1 → **v1.0**（確定）
  - レビュー：**全11回**、**累計72件**を処置（Critical 3／High 8／Medium 27／Low 34）
  - 収束の証跡：**High指摘が7回連続ゼロ**、指摘が基本設計の粒度に収束
- **成果物**：
  - [要求仕様書 v1.0](農業営農支援システム_要求仕様書.md)
  - レビュー記録票 [第1回](要求仕様書_敵対的レビュー記録票_v0.9.md)／[第2回](要求仕様書_敵対的レビュー記録票_第2回_v0.13.md)／[第3回](要求仕様書_敵対的レビュー記録票_第3回_v0.15.md)／[第4回](要求仕様書_敵対的レビュー記録票_第4回_v0.16.md)／[第5回](要求仕様書_敵対的レビュー記録票_第5回_v0.17.md)／[第6回](要求仕様書_敵対的レビュー記録票_第6回_v0.18.md)／[第7回](要求仕様書_敵対的レビュー記録票_第7回_v0.19.md)／[第8回](要求仕様書_敵対的レビュー記録票_第8回_v0.21.md)／[第9回](要求仕様書_敵対的レビュー記録票_第9回_v0.22.md)／[第10回](要求仕様書_敵対的レビュー記録票_第10回_v0.23.md)／[第11回](要求仕様書_敵対的レビュー記録票_第11回_v0.24.md)
- **完了基準（達成済み）**：全確定事項（9章）の合意／敵対的レビューの収束（High指摘ゼロの継続）／残課題の9.1への集約。

### 工程2：基本設計（← 次に着手）

「どう作るか（How）」の骨格を決める工程。要求仕様の依存関係とリスクから、**データモデルを土台に据え、高リスク項目をスパイクで並行検証**する。

#### 2-0. アーキテクチャ決定記録（ADR）
- **目的**：要求仕様7章の「たたき台」を確定し、以降の判断基準を明文化する。
- **決めること**：フロント（React＋PWA/Service Worker）／地図（MapLibre＋PostGIS、背景衛星の役割分離）／バックエンド（REST or GraphQL・認証・RBAC）／DB（PostgreSQL＋PostGIS）／マルチテナント分離（行レベル＋RLS・セッション変数方式）／1システム=1DB=1国の配備モデル／i18n（ICU/CLDR）。
- **成果物**：`docs/design/ADR/`（決定ごとに1ファイル）
- **完了基準**：主要な技術選定が根拠付きで確定し、レビュー済み。

#### 2-1. データモデル設計＋マルチテナント/RLS権限設計（★最優先の土台）
- **目的**：全機能が乗るスキーマと権限モデルを固める。
- **設計する内容**：
  - 論理ERD → 物理テーブル定義（`tenant_id`・更新時刻・更新者・バージョン番号・deleted_at）
  - **RLSポリシー**：3.2ロール表のDB表現／グループ管理者の横断／**本人起点の横断（user_idベース、労務サマリ限定）**／**個人データ（位置ログ・打刻・労務サマリ）の最小権限**
  - **追記型イベント**（StockEvent・打刻Punch・位置ログ）と競合解決（5.1.1）のテーブル設計
  - **論理削除・版履歴**（復元用、F-D06②）、**監査ログ**（改ざん耐性・仮名化）
  - PostGIS（圃場ポリゴン・メッシュ・GPSログ）、i18n（I18nLabel）
- **成果物**：`docs/design/データモデル設計書.md`＋ERD
- **完了基準**：Phase 1機能を満たすスキーマ確定／RLSポリシー方針確定／敵対的レビュー通過。

#### 2-2. オフライン同期方式設計（技術リスク：高）
- **目的**：5.1.1のデータ分類別ルールを実装可能な同期方式に落とす。
- **設計する内容**：PWA＋Service Worker＋ローカルストレージ／同期プロトコル（差分・追記型）／競合解決（追記型・前進優先マージ・楽観ロック）／端末時刻とサーバー受理時刻の二本立て／端末キャッシュ対象（農薬マスタ・使用履歴・作業リスト・地図タイル・**テンプレート/前回値**）／許容遅延（5.3.1）。
- **成果物**：`docs/design/オフライン同期設計書.md`＋**スパイク結果**
- **完了基準**：競合シナリオが方式で解決できることをスパイクで実証。

#### 2-3. UXデザインシステム＋情報アーキテクチャ（第一級要求）
- **目的**：F-D01（デザインシステム）・F-D11（IA/ナビ）等、Phase 1のUX土台を設計する。
- **設計する内容**：デザイントークン（色・タイポ・余白）／コンポーネント／アイコン・ピクトグラム／状態表示（同期/保存/エラー）／主要タスクのIA・ナビ／多言語・RTL・アクセシビリティ（WCAG 2.1 AA）／現場最適化（手袋・直射日光）。
- **プロセス**：プロトタイプ → **実ユーザー参加型ユーザビリティテスト**（作業員・高齢者・実習生）で検証。
- **成果物**：`docs/design/UXデザインシステム.md`＋プロトタイプ＋UT計画（UX目標：タスク成功率90%・SUS75等）
- **完了基準**：主要タスク（作業確認・日誌・農薬記録）のUXがUT初期目標を満たす見込み。

#### 2-4. 農機共通データモデル（ISOBUS/ADAPT）
- **目的**：ベンダー非依存の共通データモデル＋アダプタ層を設計する（主軸＝ファイル取込）。
- **設計する内容**：共通データモデル（ISOBUS/ISO-XML・ADAPT参照）／アダプタIF（ファイル取込を中核、農機OpenAPI・DataConnectを補助）／日次バッチ取込＋自前永続化。
- **成果物**：`docs/design/農機連携設計書.md`
- **完了基準**：初回アダプタ（ファイル取込＋農機OpenAPI補助）の設計確定。

#### 技術リスクのスパイク（2-1〜2-4と並行）
| スパイク | 検証内容 | 合格基準 |
|---|---|---|
| オフライン同期 | 5.1.1ルールの実装可否・競合解決 | 主要競合シナリオが破綻なく解決 |
| 地図・空間性能 | PostGIS＋MapLibreで数万圃場 | 地図初期表示2秒/p95（5.2.1） |
| RLS×規模 | 1DB=5万ユーザーでRLS性能 | 一覧・空間検索がSLO内 |

### 工程5：リリース・運用・改善

- **段階リリース**：Phase 1（MVP）を優先リリースし、現場に定着させてから拡張。
- **継続改善**：利用データ（離脱・エラー・タスク時間）でUX・性能を継続改善（5.1の反復）。
- **運用者責任の明確化**：OSS（MIT）として、サービス実施範囲・データレジデンシー・法令遵守は運用者責任（要求仕様#13）。

## 4. 横断的活動（全工程に適用）

- **品質保証（敵対的レビュー）**：要求定義で確立した「作成→敵対的レビュー→修正」を、設計書・実装にも継続適用する。
- **UX検証**：プロトタイプ段階から実ユーザー参加型テストを行い、リリース後も継続。
- **セキュリティ／プライバシー**：保存時暗号化・RLS・監査ログ・GDPR権利対応・位置情報の最小権限を全工程で担保。
- **データ移行**：既存Excel/CSV・農薬使用履歴・旧MITサービスデータの回収と取込（清算期限に留意）。
- **国際化基盤**：i18n・UTC・単位/通貨はPhase 1から組み込む（海外はPhase 4だが基盤は先行）。
