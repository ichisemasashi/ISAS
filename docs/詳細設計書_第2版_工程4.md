## 1. この工程で実現すること

狭い画面でも、工程3と同じメモの振る舞いを一通り使えるようにする。あわせて、日次一覧をスマホで閲覧でき、第1版の指示・進捗色・日誌を同じ導線から辿れるように再構成する。

### 1.1 部品

- **メモ（狭幅）。** 工程3の `/memos*` と `/api/memos*` をそのまま使う。パソコン案内を外す。
- **日次閲覧（狭幅）。** 同じ `/daily`。変更 UI は出さない。利用者（圃場0枚含む）は `GET /api/user/gantt/daily`。管理者は `GET /api/admin/gantt/daily`。
- **常設導線。** 狭幅に下部ナビ（メモ／日次／指示）。
- **第1版スマホ。** `/orders`・`/orders/{id}` の進捗色・日誌は残す。作成・修正・閉じはパソコン限定のまま。

## 2. 画面と経路

### 2.1 狭い画面の判定と出し分け

| 幅 | 扱い |
|---|---|
| 800px 未満 | 狭幅。下部ナビ。メモ利用可。`/daily` は閲覧専用。指示は第1版どおり閲覧・日誌可 |
| 800px 以上 | パソコン幅。工程1〜3どおり。管理者・圃場0枚の日次拡大はしない |

### 2.2 ブラウザの経路（この工程で変わる点）

| 経路 | 狭幅 | 役割 |
|---|---|---|
| `/memos` `/memos/drafts` `/memos/bookmarks` | 可 | 工程3と同じ振る舞い。案内ブロックを外す |
| `/daily` | 可（閲覧のみ） | 今日／直近7日／すべて・状態フィルタ・要約。状態・時間・チェックの変更 UI なし |
| `/orders` `/orders/{id}` | 可 | 第1版どおり。進捗色・受けた指示の日誌 |
| `/works` `/gantt` `/map` `/orders/new` 等 | 不可（案内） | 第1版・工程1のパソコン限定を維持 |

利用者・管理者とも、狭幅ログイン後の **既定着地はホーム**（`/home` または `/admin/home`）とする。ホームではメモのタイムラインのみを出す（投稿・検索のフル UI は `/memos`）。下部ナビから日次・指示へ移れる。

共有経路（`/daily`・`/orders`・`/orders/{id}`・`/memos*`）は経路だけで `kind` を利用者に固定しない。管理者セッションのまま日次を開ける（誤って利用者ログインへ落ちない）。

### 2.3 下部ナビ（狭幅のみ・ログイン後）

常設の3入口:

| 入口ラベル | 経路 |
|---|---|
| メモ | `/home`（管理者は `/admin/home`）。フルの投稿・検索は `/memos` |
| 日次 | `/daily` |
| 指示 | `/orders`（利用者）。管理者は案内のみ（利用者 API を呼ばない） |

- 下書き・ブックマークはメモ画面内から辿る（下部ナビに必須では置かない）。
- ログイン後の主要画面（メモ・日次・指示・ホーム・パスワード等）に出す。ログイン／再設定画面には出さない。
- パソコン幅では下部ナビを出さない（既存ホームの出口でよい）。
- 配置のピクセル・アイコンは定めない。ラベルは上表の日本語とする。

### 2.4 `/daily`（狭幅・閲覧専用）

工程1の日次一覧と同じく:

- 期間: 今日／直近7日／すべて（開いた直後は直近7日。工程1と同じ）
- 状態フィルタ: 未着手／着手中／完了のオン／オフ（初期は未着手＋着手中）
- 全オフ: 空一覧＋「状態フィルタを1つ以上オンにしてください」
- 要約: `work_time_count` / `checklist_done` / `checklist_total`（工程2）
- **出さないもの:** 実行状態の変更、作業時間・チェックの編集、ガント棒編集への導線必須化
- 閲覧専用の短い案内（任意だが推奨）: 「スマホでは状態を変えられません」

#### 誰が狭幅で見られるか

| 主体 | 見える作業 | API |
|---|---|---|
| 圃場1枚以上の利用者 | 自分の作業 | `GET /api/user/gantt/daily` |
| 圃場0枚の利用者 | 自分の作業 | 同上（狭幅利用時。`no_fields` をこの GET だけ緩和） |
| 管理者 | 全利用者の作業 | `GET /api/admin/gantt/daily`（各行に `user_id` / `user_email`） |

パソコン幅では:

- 利用者の `/daily` は工程1どおり **圃場1枚以上のみ**（0枚は出口なし／空案内）。
- 管理者ホームに日次を足さない。管理者がパソコン幅で `/daily` を開いたときは「日次一覧はスマホで開いてください」案内（必須機能ではない）。

### 2.5 メモ（狭幅）

- 投稿・下書き・編集窓・入れ子返信・削除・タグ・リンク・添付・検索・高度な検索・ブックマーク・タイムラインは工程3と同じ規則。
- 添付は `input type="file"` で **任意形式** のファイル選択を許す（画像・音声・その他。`accept` で画像に限定しない。`capture` は付けず、端末のファイル選択を優先する）。種類・最大20・サイズ上限なしは工程3のまま。
- 管理者も狭幅で工程3と同じメモ操作ができる。
- 利用者・管理者とも、狭幅ログイン後の既定着地はホーム。ホームはタイムラインのみ。`/memos` は投稿・検索のフル画面。下部ナビ付き。
- 狭幅では画面幅（`window.innerWidth`）を取得し、ルート要素の横幅をその値に合わせる（はみ出しを防ぐ）。

### 2.6 指示（狭幅・再構成）

- 第1版詳細設計どおり、`/orders` と `/orders/{id}` で進捗色・受けた指示の日誌。
- 指示の作成・修正・閉じは狭幅では出さない。
- 下部ナビ「指示」から一覧へ辿れること。見た目は狭幅ナビに合わせて整えてよい（振る舞いの拡大はしない）。

### 2.8 API

#### 2.8.1 メモ

工程3の `/api/memos*` を変更せず使う。狭幅専用 API は作らない。

#### 2.8.2 利用者日次 GET の緩和

`GET /api/user/gantt/daily`:

- クエリは工程1・2どおり（`range` / `statuses`）。要約フィールドも工程2どおり。
- **この工程の追加:** 圃場0枚の利用者でも、自分の未削除ガント行について成功応答を返す（空配列可）。`no_fields` にしない。
- 行の作成・更新・削除 API（`POST/PUT/DELETE /api/user/gantt...`）および作業時間・チェックの変更 API は、圃場0枚では従来どおり `no_fields` でよい（この工程で解禁しない）。
- 実行状態の PUT は、狭幅 UI からは呼ばない。サーバがセッションがあれば受けてもよい（工程1どおり。UA 拒否はしない）。

#### 2.8.3 管理者日次

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/admin/gantt/daily` | GET | 全利用者の作業を横断閲覧。変更なし |

クエリ: 利用者 daily と同じ `range` / `statuses`。

各行は利用者 daily の欄に加え、少なくとも:

```
"user_id": 3,
"user_email": "a@example.com"
```

並び: `start_at` 昇順、同じなら `user_id`、同じなら `id`。

管理者セッション必須。利用者セッションでは `forbidden`。

失敗コードは工程1の `range_invalid` / `statuses_invalid` を流用。

## 3. 処理の規則

### 3.1 メモ

- 工程3の詳細設計を狭幅でもすべて適用する。
- 工程3に書いた「狭い画面ではパソコン案内」は、**この工程で廃止**する。

### 3.2 日次閲覧

- 期間・重なり判定・フィルタ初期値は工程1のまま。
- 変更操作を狭幅 UI に置かない。
- パソコン側の「誰が日次を使えるか」は工程1のまま（管理者・圃場0枚はパソコン日次を持たない）。

### 3.3 解禁しないもの

- 塗り・境界・ガント編集・指示作成／閉じ
- スマホからの実行状態・作業時間・チェック変更
- ガント紐づけ、通知、オフライン同期、ネイティブ／必須 PWA

### 3.4 オンライン

- 第1版どおりオンライン必須。圏外の下書き同期は作らない。

## 4. 残す情報

- 新規の必須テーブルは設けない（メモは工程3、日次は工程1・2の表を読む）。
- 管理者 daily は既存 `gantt_rows` 等の読取のみ。

|---|---|

工程3の「メモはパソコンで開いてください」は、狭幅では使わない。

## 6. この工程で作らないもの

- ガント紐づけ（第2版工程5）
- 通知、オフライン必須、ネイティブアプリ、必須 PWA
- パソコンでの管理者日次・圃場0枚日次の解禁
- 狭幅での実行状態・時間・チェック変更
- 塗り・ガント編集・指示作成／閉じのスマホ解禁
- メモ専用の別 API／別アプリ

## 7. 完了として満たすこと（詳細）

- 狭幅でメモを工程3と同じ規則で投稿・閲覧・返信・検索・ブックマーク・添付できる（管理者含む）。
- 狭幅 `/daily` で今日／直近7日／すべて・フィルタ・要約を閲覧でき、変更 UI が無い。
- 圃場0枚の利用者が狭幅で自分の日次を閲覧できる。パソコン幅では工程1どおり使えない。
- 管理者が狭幅で全利用者横断の日次を閲覧でき、各行の利用者が分かる。パソコンでは日次を必須としない。
- 下部ナビからメモ・日次・指示へ辿れ、指示の進捗色・日誌が第1版どおり使える。
- `/works`・`/gantt`・`/map`・指示作成等が狭幅で解禁されていない。
- ガント紐づけ・通知・オフライン必須が、この工程の必須成果に混入していない。
