# 基本仕様書　工程1　招待とログイン

- 版: 0.3
- 日付: 2026-09-12
- 状態: 合意（管理者は運用専用。利用者と別管理）
- 上位: [要求仕様書.md](../要求仕様書.md)、[工程表.md](../工程表.md) の工程1
- 本書は工程1の **基本仕様（振る舞い）** である。画面レイアウト、API、データベース、ライブラリ等の詳細設計は書かない。

## 1. この工程の目的

イチセが置く1つのISASに、知っている相手だけが入る。公開の入口は無い。

工程1の成果は、招待とログインが成立するWebの入れ物である。地図・ガント・指示・日誌・日英切替の本機能は、後の工程とする。

## 2. 範囲

### 2.1 含む

- Webとして開き、ログインできること
- 管理者アカウントと利用者アカウントを別管理すること
- 管理者はシステムの管理だけを行い、圃場を持たないこと
- 招待した利用者だけが、利用者として入れること
- メールアドレスとパスワードによる認証
- システムが発行する初期パスワード
- 本人によるパスワード変更と、メールを使ったパスワード再設定
- 管理者による招待の取消し
- 圃場を1枚も持たない利用者でも入れること
- ログアウト
- パソコンのブラウザでも、スマホのブラウザでも、同じアカウントでログインできること（工程1のログイン後は入れ物のみ）

### 2.2 含まない

- 公開サインアップ
- 外部の認証サービス、多要素認証
- 地図、圃場台帳、塗り、ガント、指示、日誌
- 画面文言の日英切替の本実装
- パスワード以外の認証（生体、ワンタイム、SNS）
- 招待そのものをシステムがメールで送ること（相手への連絡はシステムの外）

## 3. 管理者と利用者

工程1で区別する相手は次のとおりとする。

| 呼び | 意味 |
|---|---|
| 未招待の人 | 利用者として招待されていない人。利用者としては入れない。 |
| 利用者 | 招待されて入る人。圃場の有無は問わない。他の利用者を招待できる。招待の取消しはできない。後の工程で圃場を持てる。 |
| 管理者 | システムの管理だけを行うアカウント。圃場を持たない。招待できる。招待を取り消せる。利用者の招待フローでは作らない。 |

- 管理者アカウントと利用者アカウントは別管理とする。一方を他方へ転用しない。同一アカウントが管理者と利用者を兼ねない。
- 管理者は、利用者が自分で登録してなるものではない。このISASを置くときに、利用者とは別に用意する。
- 利用者を増やす手段は招待だけとする。招待で増えるのは利用者である。招待で管理者は増えない。
- 同じメールアドレスを、管理者と利用者の両方に置くことはしない。
- 営農する人は利用者アカウントを使う。管理者が営農する場合も、管理者アカウントでは圃場を持たず、別に利用者アカウントを招待する。
- 圃場の有無は、利用者のログイン可否に使わない。台帳が空の利用者でも入れる。管理者はそもそも圃場を持たない。
- 管理者のログインと利用者のログインは別とする。利用者の入口では管理者アカウントでは入れない。管理者の入口では利用者アカウントでは入れない。
- ログイン後の入れ物は、工程1では「入ったことが分かる」で足りる。管理者の入れ物に圃場・地図・ガントは出さない。

## 4. 原則

1. **許可された人だけが入る。** 利用者として招待されていない人は、利用者としては入れない。取り消された招待のアカウントも入れない。
2. **自分から利用者登録できない。** 「新規登録」で誰でも利用者を増やす入口は置かない。
3. **識別子はメールアドレスとする。** ログインに使う識別子はメールアドレスである。任意のIDは使わない。
4. **パスワードで足りる。** 多要素認証はしない。
5. **後工程の画面を先に出さない。** ログイン後に、地図・ガント・指示の本画面は出さない。入ったことが分かれば足りる。
6. **管理者は運用専用である。** 圃場を持たない。利用者アカウントと兼ねない。
7. **オンライン必須。** 通信できないときは使えない。

## 5. ログインとログアウト

- 未ログインの人が保護された画面を開いたときは、その側のログインへ進む。ログインするまで中には入れない。
- 利用者として入れるのは、取り消されていない利用者アカウントのメールアドレスとパスワードが一致したときだけとする。
- 管理者として入れるのは、用意された管理者アカウントのメールアドレスとパスワードが一致したときだけとする。
- 利用者の認証情報で管理者側には入れない。管理者の認証情報で利用者側には入れない。
- 一致しないときは入れない。失敗理由を細かく分けることは、工程1の必須としない。
- ログイン中は、工程1の入れ物を使える。
- ログアウトしたあと、同じ保護画面はログインなしでは開けない。
- 圃場ゼロの利用者でも、利用者としての上記は同じとする。

## 6. 招待

- 招待できるのは、管理者と利用者である。
- 招待する人は、相手のメールアドレスを指定する。公開名簿から選ぶことはしない。
- システムは初期パスワードを生成し、招待した人がその場で確認できるようにする。
- 相手への連絡（メールアドレスと初期パスワードを伝えること）はシステムの外で行う。工程1は招待案内メールを送らない。
- 招待された人は、そのメールアドレスと初期パスワードでログインできる。
- ログイン後、本人はパスワードを自分で変更できる。
- 同じメールアドレスを、取り消されていない利用者として二重に招待することはできない。
- 管理者として存在するメールアドレスを、利用者として招待することはできない。

## 7. 招待の取消し

- 招待の取消しができるのは管理者だけとする。利用者は取り消せない。
- 管理者が招待を取り消すと、その利用者は以後ログインできない。まだ一度も入っていない場合も、入ったあとでも同じとする。
- 取り消したメールアドレスを、あらためて利用者として招待することはできる。そのアドレスが管理者として存在する間は招待できない。

## 8. パスワードの再設定

- 本人は、ログイン前にパスワードを再設定できる。
- 再設定は、そのアカウント種別（管理者または利用者）のメールアドレスへ案内を送り、本人が新しいパスワードを決める。管理者の再設定で利用者アカウントは変わらない。その逆も同じとする。
- 招待の案内は送らないが、パスワード再設定の案内は送る。
- 取り消された利用者は、再設定しても入れない。

## 9. 工程1の完了として満たすこと

- 用意した管理者は、管理者の入口からメールアドレスとパスワードでログインできる。利用者の入口からは入れない。
- 管理者アカウントは圃場を持たない。
- 招待していないメールアドレスでは、利用者としてログインできない。
- 利用者アカウントは、管理者の入口からは入れない。
- 管理者または利用者が招待した人は、メールアドレスと初期パスワードでログインできる。
- 圃場が0枚の利用者でもログインできる。
- ログインした人はログアウトできる。
- 本人はパスワードを変更でき、忘れたときはメールで再設定できる。
- 管理者が招待を取り消すと、その人はログインできない。利用者は取消しできない。
- ログイン後に、地図・ガント・指示の本機能は出ない。
