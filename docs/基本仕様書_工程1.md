# 基本仕様書　工程1　招待とログイン

- 版: 0.1
- 日付: 2026-09-12
- 状態: 要求から落とせる範囲は確定。判断事項は §8 に残し、合意後に改訂する。
- 上位: [要求仕様書.md](../要求仕様書.md)、[工程表.md](../工程表.md) の工程1
- 本書は工程1の **基本仕様（振る舞い）** である。画面レイアウト、API、データベース、ライブラリ等の詳細設計は書かない。

## 1. この工程の目的

イチセが置く1つのISASに、知っている相手だけが入る。公開の入口は無い。

工程1の成果は、招待とログインが成立するWebの入れ物である。地図・ガント・指示・日誌・日英切替の本機能は、後の工程とする。

## 2. 範囲

### 2.1 含む

- Webとして開き、ログインできること
- 招待したアカウントだけが入れること
- パスワードによる認証
- 圃場を1枚も持たないアカウントでも入れること
- ログアウト
- パソコンのブラウザでも、スマホのブラウザでも、同じアカウントでログインできること（工程1のログイン後は入れ物のみ）

### 2.2 含まない

- 公開サインアップ
- 外部の認証サービス、多要素認証
- 地図、圃場台帳、塗り、ガント、指示、日誌
- 画面文言の日英切替の本実装
- パスワード以外の認証（生体、ワンタイム、SNS）

## 3. 利用者

工程1で区別する相手は次のとおりとする。

| 呼び | 意味 |
|---|---|
| 未招待の人 | このISASにアカウントが無い人。入れない。 |
| 招待済みの利用者 | 招待され、ログインできる人。圃場の有無は問わない。 |
| 運用者 | イチセ側で、このISASに人を入れる操作をする人。システム上の表し方は §8。 |

圃場の有無は、ログインの可否に使わない。台帳が空でも入れる。

## 4. 原則

1. **許可された人だけが入る。** 招待されていない人は、正しいパスワードを推測できても入れる対象にしない。アカウントが無ければログインできない。
2. **自分から登録できない。** 「新規登録」で誰でもアカウントを増やす入口は置かない。
3. **パスワードで足りる。** ログインに必要なものは、招待済みの識別子とパスワードである。
4. **後工程の画面を先に出さない。** ログイン後に、地図・ガント・指示の本画面は出さない。入ったことが分かれば足りる。
5. **オンライン必須。** 通信できないときは使えない。

## 5. ログインとログアウト

- 未ログインの人が保護された画面を開いたときは、ログインへ進む。ログインするまで中には入れない。
- 識別子とパスワードが、招待済みのアカウントと一致したときだけログインできる。
- 一致しないときは入れない。失敗理由を細かく分けることは、工程1の必須としない。
- ログイン中は、工程1の入れ物を使える。
- ログアウトしたあと、同じ保護画面はログインなしでは開けない。
- 圃場ゼロでも、上記は同じとする。

識別子の種類（メールかどうか）、パスワードの決め方、期限切れ、同時に何台で入れるかは §8 とする。

## 6. 招待

要求上、人を増やす手段は招待だけである。

- 招待されていない識別子では、ログインできない。
- 招待された識別子は、パスワードが正しければログインできる。
- 相手をシステムが自動で募集したり、公開名簿から選んだりはしない。知っている相手を指定する。

誰が招待できるか、招待を相手へどう伝えるか、招待の取消しは §8 とする。

## 7. 工程1の完了として満たすこと

工程表の完了条件を、基本仕様として次のように読む。

- 招待していない人は、ログインできない。
- 招待した人は、識別子とパスワードでログインできる。
- 圃場が0枚のアカウントでもログインできる。
- ログインした人はログアウトできる。
- ログイン後に、地図・ガント・指示の本機能は出ない。

## 8. 判断待ち

次は要求仕様書に書き切っておらず、工程1の基本仕様を閉じるために利用者が決める。決まったら本書を改訂する。

1. **最初の運用者を、どう存在させるか。** 誰もいない状態からイチセが入る方法。
2. **誰が招待できるか。** 運用者だけか、ログインした利用者なら誰でもか。
3. **招待を相手にどう届けるか。** システムが案内を送るか、運用者が画面で許可したあと、別の手段で相手に伝えるか。
4. **パスワードを誰が決めるか。** 招待された本人か、招待する側か。
5. **ログインの識別子はメールアドレスか。** 任意のIDでもよいか。
6. **パスワードを忘れたとき、工程1で本人が戻せるか。** 戻せないなら、運用者がやり直す。
7. **招待の取消しと、入ったあとの停止を工程1で行うか。**
