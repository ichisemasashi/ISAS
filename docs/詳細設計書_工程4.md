## 1. この工程で実現すること

自分用の工程ガントで予定を持ち、選んだ行について面積のパーセントサークルと地図色を見る。実績の正本は工程3の塗りのままとする。指示とは紐づけない。

工程4で動かす論理ブロックは、基本設計書 §10 のとおり、ガントとパーセントである。

### 1.1 工程4の部品

- **入れ物。** 工程1〜3の Clojure / ClojureScript / API / SQLite / OpenLayers / JTS を足して使う。
- **ガント題名。** 利用者ごとの題名（`gantt_titles`）。一覧・追加・変更・ソフト削除。題名を消すと、その下の作業も一覧から消える（ソフト削除）。
- **ガント作業（行）。** 題名に属する。表示名、開始日時、終了日時、作業名、対象圃場。ソフト削除（`deleted_at`）。指示の列は持たない。時間軸とバーは ClojureScript で出す。専用のガント製品は置かない。
- **日次進捗。** `gantt_progress_days` に暦日ごとの確定％。いまの％は塗りから都度計算。ログインまたはガント一覧時に前日までを自動確定。管理者は `POST /api/admin/gantt/progress/finalize` で全体／利用者指定の確定ができる。
- **日時。** 開始・終了は日本時間の分までとする。保存は `YYYY-MM-DDTHH:MM`（タイムゾーン文字列は付けない）。作成・更新の記録時刻は工程1どおり UTC。
- **パーセントサークル。** 選択中の対象付き行1つだけ。分母・分子は㎡。画面は整数％。描画は ClojureScript の SVG とし、専用製品は置かない。
- **地図色。** 対象付き行を選んでいるあいだはガント側を優先する。対象圃場は工程3と同じ未／一部／済。対象でない自分の圃場は塗りつぶし `#e8e8e8`（一律。進捗は見えない）。
- **パソコン。** ガントの編集はパソコンの `/gantt` だけとする。スマホでは編集しない。管理者は一覧編集を持たないが進捗確定画面は持つ。

## 2. 画面と経路

管理者側には進捗確定を足す。ガント一覧編集は利用者のみ。利用者で入っていないときは、工程1どおり `/` へ進む。

### 2.1 ブラウザの経路（ClojureScript）

| 経路 | 誰 | ログイン | 役割 |
|---|---|---|---|
| `/gantt` | 利用者 | 必要 | ガント、パーセントサークル、振り返り、自分の圃場の地図（色と形。塗りと境界の編集はしない） |
| `/admin/gantt-progress` | 管理者 | 必要 | 日次進捗の確定（日付・利用者メールは任意） |

利用者ホーム `/home` に、ガントへの出口を足す。圃場が0枚のときは出口を出さない（または押せない）。管理者ホームにはガント編集を足さない。

狭い画面で `/gantt` を開いたときは、工程2と同じく「パソコンで開いてください」とし、編集しない。

`/map` の塗り・境界・下地は工程3のままとする。パーセントサークルは `/gantt` にだけ置く。

### 2.2 `/gantt` に出すもの

同じ画面に次を置く。配置のピクセルは定めない。

- **題名の管理。** 題名の一覧、追加、変更、削除。
- **ガント。** 選んだ題名の下の作業がタスク、時間軸が日時。向きは横／縦を切替えられる。同じ時間帯の複数作業を重ねて置ける（禁止しない）。
- **作業の管理。** 選んだ題名の下で作業の一覧、追加、変更、削除。対象圃場はチェックで追加・外し。所属の題名は選択作業の編集で確認・変更できる。
- **作業の編集。** 所属の題名、表示名、開始、終了、作業名、対象圃場。選択作業に削除（確認のうえソフト削除）と振り返り。
- **パーセントサークル。** 対象圃場と作業名がある行を選んでいるときだけ出す。
- **振り返り。** 選択行の日次確定％一覧。適用外の日は「—」。
- **地図。** 自分の全圃場。作業場所の初期位置と下地は工程2のまま。塗り・分割・合筆・取込の道具は出さない。

開いたときは行未選択とする。サークルは出さない。地図は工程3どおり、作業名未選択なら形だけ。前回の選択は残さない。URL に行 ID は付けない。

作った直後の行は、選んだ状態にしてよい。

### 2.3 時間軸と向き

- 開いたときの範囲は、今日 0:00 から 72 時間（今日を含む3日）とする。
- 「日」「週」「8週」「月」へ広げられる。「週」は今日を含む7日。「8週」は今日を含む56日。「月」は今日を含む暦月。
- 時間範囲の切替は1つの選択（日／週／8週／月）とする。範囲ごとに独立したボタンは置かない。
- 時間軸の向きは1つの選択で切替える。「時刻を横」（初期）は行がタスク・横が日時。「時刻を縦」は列がタスク・縦が日時。向きに合わせて目盛とバーの位置も変える。
- スクロールして、範囲の外の行の時刻も直せる。
- 時間軸には日時の目盛（目安の刻みとラベル）を出す。バーの位置が読めること。目盛の間隔は範囲に応じて変えてよい。

### 2.4 API（Clojure）

工程1と同じ JSON の形とする。自分の利用者セッションが必要（管理者 API は管理者セッション）。管理者のガント編集 API は `forbidden`。他人の行・圃場は `not_found`。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/gantt` | GET | 自分の題名一覧と作業（行）一覧（いずれも `deleted_at IS NULL`）。副作用で前日までの未確定日を自動確定 |
| `/api/user/gantt/titles` | GET | 自分の題名一覧 |
| `/api/user/gantt/titles` | POST | 題名を足す。本文は `name` |
| `/api/user/gantt/titles/{id}` | PUT | 題名を直す。削除済みは不可 |
| `/api/user/gantt/titles/{id}` | DELETE | 題名をソフト削除し、その下の作業もソフト削除する |
| `/api/user/gantt` | POST | 1作業を足す。本文は `title_id`、表示名（`title`）、開始、終了、任意の作業名、任意の対象 `field_ids` |
| `/api/user/gantt/{id}` | PUT | 表示名、開始、終了、作業名、対象、`title_id` を直す。削除済みは不可 |
| `/api/user/gantt/{id}` | DELETE | ソフト削除（`deleted_at` を立てる。物理削除しない） |
| `/api/user/gantt/{id}/progress` | GET | その行のいまの％用の面積と、対象圃場ごとの `status`。対象または作業名が無ければ `applicable: false` |
| `/api/user/gantt/{id}/progress-days` | GET | 日次確定％の履歴一覧 |
| `/api/user/work-name-candidates` | GET | 自分が塗った名前と、ガントに出した名前の重複なし一覧 |
| `/api/admin/gantt/progress/finalize` | POST | body: `{ "day"?: "YYYY-MM-DD", "email"?: "..." }`。`day` 省略＝東京の前日。`email` 無し＝全利用者、有り＝その利用者のみ |

利用者の `GET /api/user/session` でも、前日までの未確定日を自動確定する。

工程2の圃場削除に、ガント対象からの除外を足す。

| 経路 | 工程4での追加 |
|---|---|
| `DELETE /api/user/fields/{id}` | その圃場を、どのガント行の対象からも外す。行自体は残す |
| `POST /api/user/fields/{id}/split` | 元の圃場が消えるので、対象からも外れる。ガント対象であることだけでは拒否しない |
| `POST /api/user/fields/merge` | 消える側の圃場 ID を対象から外す。残す側が対象ならそのまま |

`GET /api/user/work-names`（工程3、塗った名前だけ）は意味を変えない。地図 `/map` と `/gantt` の作業名候補は、工程4から `work-name-candidates` を使う。

`GET /api/user/gantt` の成功本文:

```
{
  "ok": true,
  "rows": [
    {
      "id": 1,
      "title": "...",
      "start_at": "2026-09-12T08:00",
      "end_at": "2026-09-12T17:00",
      "work_name": "田植え",
      "field_ids": [1, 2]
    }
  ]
}
```

`work_name` が無い行は `null`。対象が無い行は `field_ids` を空配列とする。並びは `start_at`、同値なら `id`。

`GET /api/user/gantt/{id}/progress` の成功本文:

```
{
  "ok": true,
  "applicable": true,
  "percent": 12,
  "numerator_m2": 1200,
  "denominator_m2": 10000,
  "fields": [
    {
      "id": 1,
      "status": "none" | "partial" | "done",
      "area_m2": 0,
      "field_area_m2": 5000
    }
  ]
}
```

`applicable` が `false` のとき、`percent` は `null`。サークルは出さない。`status` の意味は工程3と同じとする。

失敗の `code` を工程4で足すもの:

| code | 使うとき |
|---|---|
| `no_fields` | 圃場が0枚の利用者がガント API を呼んだ |
| `gantt_not_found` | その行が無い、または他人 |
| `title_required` | 題名または作業の表示名が無い、または空白だけ |
| `title_too_long` | 題名または表示名が200文字を超える（前後空白を除いたあと） |
| `title_not_found` | 題名が無い、または削除済み |
| `time_invalid` | 開始または終了が `YYYY-MM-DDTHH:MM` でない |
| `time_order` | 終了が開始と同じか、より前 |
| `work_name_required` | 対象圃場があるのに作業名が無い（工程3と同じ code） |
| `work_name_too_long` | 100文字を超える（工程3と同じ） |
| `field_not_found` | 対象に他人の圃場、または存在しない ID |

圃場0枚で `/gantt` を開いた画面は、API の `no_fields` に対応する案内を出し、行の作成はしない。

## 3. 処理の規則

### 3.1 誰が使うか

- ガントを使えるのは、圃場を1枚以上持つ利用者だけとする。管理者は持たない。
- 対象に付けられるのは、その利用者自身の圃場だけとする。
- 圃場が0枚になるとガントは開けない。行は消さない。再び1枚以上になれば、残っている行を使える。対象が0枚になった行は、作業名が残っていればラベル付きメモである。

### 3.2 題名と作業の作成と編集

- 題名（`gantt_titles.name`）は必須。前後空白を除いて保存する。空にはできない。一覧・追加・変更・ソフト削除できる。
- 題名をソフト削除すると、その下の作業もソフト削除する。
- 作業は必ず1つの題名に属する（`title_id`）。表示名（`gantt_rows.title`）は必須。前後空白を除いて保存する。
- 画面では選択作業の所属題名を一覧から確認・変更できる。変更するとその題名の下へ移る。
- 開始と終了は必須。分まで。秒は持たない。
- 終了は開始より後であること。同じ時刻は不可。
- 作業名は任意。付けるときは工程3と同じ正規化（前後空白を除き、完全一致。改名しない）。
- 対象圃場は任意。付けるなら1枚以上。同じ行に同じ圃場を二重に付けない。画面ではチェックで追加・外しができる。
- 対象がある行は作業名必須。保存時に対象が1枚以上なら、作業名が空なら保存しない。
- 対象を全部外した行は、作業名が残っていてよい（ラベル付きメモ）。
- 新しい作業名は、行の `work_name` に入れて使える。先にマスタを作る API は置かない。
- 同じ時間帯に複数行あってよい。
- 画面の新規の初期値は、表示名「新しい作業」、開始＝今日 08:00、終了＝今日 17:00、作業名なし、対象なし、としてよい。保存前に直せる。
- バーをドラッグして時刻を直すことは実装してよい。必須は時刻欄の編集とする。
- 画面の「保存」は、`time_order` または `work_name_required` になる入力のあいだは押せない（disabled）。「作業を足す」も、開始・終了が不正なあいだは押せない。API 側の拒否は残す。

### 3.3 パーセント

- 対象は選択中の1行だけ。複数行をまとめた％は出さない。計算しない。
- 対象圃場が無い、作業名が無い、行未選択のときは、サークルを出さない。`applicable: false`。
- 分母は、その行の対象圃場の面積の合計（㎡）。枚数ではない。
- 分子は、各対象圃場について、その行の作業名の塗り面積（工程3どおり、同じ圃場・同じ作業名の和集合。圃場の外側は数えない）。圃場ごとに、その圃場面積を超えない。それを合計する。
- 画面の％は整数とする。`floor(100 * 分子 / 分母)`。対象圃場がすべて `done`（工程3の status）のときだけ 100 とする。それ以外では、たとえ `floor` の結果が 100 でも表示は 99 とする。分母 0 は起きない（対象が無い行はサークル自体出さない）。
  - **100 にする条件:** その行の対象圃場がすべて `done`。
  - **99 にする条件:** すべて `done` ではないのに、整数㎡で計算した `floor(100 * 分子 / 分母)` が 100 になるとき。整数㎡への丸めと工程3の `done` 判定（面積が圃場とほぼ等しい／以上）のわずかな差で起きうる上限である。通常の「一部塗り」では 0〜99 の `floor` 値そのものが出る。
- 日誌の％も手入力の進捗も持たない。サークルを上書きする欄は置かない。
- 全面完了（`done` にする操作）は `/map` の工程3のままとする。`/gantt` では％と色を見るだけで、塗りや全面完了の道具は出さない。

### 3.4 地図の色（`/gantt`）

対象付きの行（対象が1枚以上かつ作業名あり）を選んでいるあいだ:

- 対象圃場は、その作業名の未／一部／済（工程3の色）。
- 対象でない自分の圃場は塗りつぶし `#e8e8e8`。進捗色は付けない。
- 地図側の作業名選択があっても、このあいだは使わない。選択値は捨てなくてよい。

それ以外（未選択、メモ行、対象が0枚の行）:

- 工程3どおり。地図側で作業名を選べば全自分圃場にその塗り色。選ばなければ形だけ。

### 3.5 作業名候補

- `GET /api/user/work-name-candidates` は、`paints.work_name` と `gantt_rows.work_name`（空でないもの）の和集合。重複なし。他人は出さない。並びは文字順。
- 塗りが無くなり、ガント行にも残っていない名前は、候補から消える。
- 工程5の指示名は、この工程では足さない。

## 4. 残す情報（工程4）

工程3の表は壊さない。足す単位は次とする。

### 4.0 ガント題名 `gantt_titles`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `user_id` | INTEGER | 所有者 |
| `name` | TEXT | 正規化した題名。空にしない |
| `created_at` | TEXT | UTC |
| `updated_at` | TEXT | UTC |
| `deleted_at` | TEXT | ソフト削除時刻（UTC）。NULL＝表示中 |

### 4.1 ガント作業 `gantt_rows`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `user_id` | INTEGER | 所有者 |
| `title_id` | INTEGER | `gantt_titles.id` |
| `title` | TEXT | 正規化した表示名。空にしない |
| `start_at` | TEXT | 日本時間 `YYYY-MM-DDTHH:MM` |
| `end_at` | TEXT | 同上。`start_at` より後 |
| `work_name` | TEXT | 正規化した作業名。無い行は NULL |
| `created_at` | TEXT | UTC |
| `updated_at` | TEXT | UTC |
| `deleted_at` | TEXT | ソフト削除時刻（UTC）。NULL＝表示中 |

指示 ID は持たない。いまの％の値は持たない（読むときに塗りの面積から求める）。日次の確定％は `gantt_progress_days` に持つ。

### 4.2 ガント対象 `gantt_targets`

| 列 | 型 | 内容 |
|---|---|---|
| `gantt_id` | INTEGER | `gantt_rows.id` |
| `field_id` | INTEGER | `fields.id` |

主キーは `(gantt_id, field_id)` とする。その利用者の圃場以外は付けない。圃場を消したら、その `field_id` の行を消す。ガント行は消さない（ソフト削除もしない）。

### 4.3 日次進捗 `gantt_progress_days`

| 列 | 型 | 内容 |
|---|---|---|
| `gantt_id` | INTEGER | `gantt_rows.id` |
| `day` | TEXT | 東京暦日 `YYYY-MM-DD` |
| `percent` | INTEGER | 確定％。適用外は NULL |
| `applicable` | INTEGER | 0/1 |
| `finalized_at` | TEXT | UTC |
| `finalized_by` | TEXT | `auto` / `admin`（将来 `user`） |

主キーは `(gantt_id, day)`。既存日は上書きしない。

## 7. 完了として満たすこと（詳細）

基本仕様書 §4.8 に加え、次を満たす。

- メモ行および対象圃場が無い行を選んでも、サークルが出ない。
- 圃場付き行を選ぶと、工程3のその作業名の塗り面積から出した％と、対象圃場の色が一致する。
- API に他人の `field_id` を付けても保存しない。
- 行はソフト削除できる。同じ `start_at`〜`end_at` に複数行を置ける。
- 圃場が0枚の利用者は `no_fields` となり、行を足せない。
- 開いた直後はサークルが出ず、地図は形だけ（作業名未選択）。
- 管理者の入口にガント編集 `/gantt` は出ない。進捗確定と確定 API はある。
- 日次％は二重確定しても既存日を上書きしない。

## 11. 確定した判断

1. **ガントの描画部品。** ClojureScript で時間軸とバーを出す。専用のガント製品は置かない。
2. **対象でない自分の圃場の薄い色。** 塗りつぶし `#e8e8e8` の一律とする。未／一部／済は付けない。
3. **開いたときの時間軸。** 今日 0:00 から 72 時間（今日を含む3日）とする。週・8週・月への拡大と、時間軸の向き（横／縦）の切替は残す。
