## 1. この工程で実現すること

招待利用者と管理者が、パソコンで短いメモを時系列に残し、メンバ間で共有・検索・ブックマークできるようにする。公開 SNS は作らない。塗り・％・指示・日誌・実行状態とは自動連動しない。

### 1.1 部品

- **メモ本体。** 表 `memos`。親も返信も同じ行。`parent_id` で入れ子（深さ上限なし）。
- **タグ・リンク・添付。** 子表。1メモあたりタグ最大20・リンク最大20・添付最大20。
- **ブックマーク。** 表 `memo_bookmarks`。付けた人単位。共通一覧。
- **画面。** `/memos`（タイムライン・投稿・検索）、`/memos/drafts`、`/memos/bookmarks`。利用者・管理者とも同じ経路。
- **編集窓。** 公開後は `content_saved_at` から30分（都度延長）。サーバ時刻が正本。

## 2. 画面と経路

### 2.1 ブラウザの経路（ClojureScript）

| 経路 | 誰 | ログイン | 役割 |
|---|---|---|---|
| `/memos` | 利用者・管理者 | 必要 | 親メモのタイムライン、新規投稿、検索・高度な検索、スレッド閲覧・返信 |
| `/memos/drafts` | 利用者・管理者 | 必要 | 本人の下書き一覧・編集・公開・削除 |
| `/memos/bookmarks` | 利用者・管理者 | 必要 | メンバ共通のブックマーク一覧。自分が付けたものの外し |

利用者ホーム `/home` および管理者ホームに、メモへの出口を足す。

狭い画面で上記を開いたときは、「メモはパソコンで開いてください」とし、この工程では編集・投稿 UI を必須にしない（対等化は第2版工程4。解除後の詳細は [詳細設計書_第2版_工程4.md](詳細設計書_第2版_工程4.md)）。

ガント紐づけ UI は出さない。

### 2.2 `/memos` に出すもの

- **タイムライン。** 未削除の **公開済み親メモ**のみ。`published_at` の新しいものが上。返信は混ぜない。
- **投稿。** 本文・タグ・リンク・添付・下書き保存・公開。
- **スレッド。** 親を開くと、未削除の公開済み子孫を入れ子で表示。返信を追加できる（下書き返信も可。公開するまで他者には出ない）。
- **検索。** キーワード（本文・タグ・添付ファイル名）。高度な検索（期間・除外語・作成者）。
- **ブックマーク付け。** 公開済みメモに付けられる。
- **削除。** 作成者または管理者。

### 2.3 `/memos/drafts`

- ログイン中の作成者本人の、未削除の下書きのみ。
- 編集・公開・ソフト削除。

### 2.4 `/memos/bookmarks`

- 1件以上ブックマークが付いている、未削除の公開メモ。
- 並びは、そのメモに付いたブックマークのうち **最も新しい `created_at` の降順**（同値なら `memo_id` 降順）。
- 各行で、自分が付けたブックマークは外せる。他人が付けた印は外さない（共通一覧にはメモが残る場合がある）。

### 2.5 API（Clojure）

利用者セッションまたは管理者セッションが必要。未ログインは第1版どおり拒否。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/memos` | GET | タイムライン（親・公開・未削除）。ページングは詳細で `limit`/`before_id` 等を定めてよい |
| `/api/memos` | POST | 新規（親または `parent_id` 付き返信）。`status`: `draft` / `published` |
| `/api/memos/{id}` | GET | 1件＋タグ・リンク・添付メタ。権限に応じて下書きは本人のみ |
| `/api/memos/{id}` | PUT | 本文・タグ・リンクの更新（規則は §3.4）。添付の付け外しは専用 API |
| `/api/memos/{id}` | DELETE | ソフト削除（作成者または管理者）。子孫もソフト削除 |
| `/api/memos/{id}/publish` | POST | 下書きを公開 |
| `/api/memos/{id}/replies` | GET | そのメモ直下の未削除・公開返信（入れ子はクライアントが再帰 GET してもよい。一括ツリー GET を足してもよい） |
| `/api/memos/search` | GET | 検索・高度な検索 |
| `/api/memos/drafts` | GET | 本人の下書き一覧 |
| `/api/memos/{id}/attachments` | POST | ファイル1つ追加（multipart。1メモ最大20） |
| `/api/memos/{id}/attachments/{aid}` | GET | ファイル本体の取得 |
| `/api/memos/{id}/attachments/{aid}` | DELETE | 添付の削除（編集可のとき、または下書き） |
| `/api/memos/{id}/bookmark` | POST | ブックマーク付与 |
| `/api/memos/{id}/bookmark` | DELETE | 自分が付けたブックマークを外す |
| `/api/memos/bookmarks` | GET | 共通ブックマーク一覧 |

`author_kind` / `author_id` はセッションから定め、クライアント指定では偽造させない。

#### 2.5.1 メモオブジェクト（例）

```
{
  "id": 1,
  "parent_id": null,
  "status": "published",
  "body": "...",
  "author_kind": "user",
  "author_id": 3,
  "author_email": "a@example.com",
  "published_at": "2026-09-21T03:00:00Z",
  "content_saved_at": "2026-09-21T03:10:00Z",
  "editable_until": "2026-09-21T03:40:00Z",
  "can_edit": true,
  "tags": ["防除", "東"],
  "links": ["https://example.com/a"],
  "attachments": [
    {"id": 1, "filename": "note.pdf", "content_type": "application/pdf"}
  ]
}
```

時刻は UTC の ISO-8601 で返す。`editable_until` は公開済みかつ作成者本人のときのみ意味を持つ（`content_saved_at + 30分`）。期限外・他人・管理者閲覧では `can_edit: false`。

#### 2.5.2 検索クエリ

| 名 | 必須 | 内容 |
|---|---|---|
| `q` | 任意 | キーワード。本文・タグ・添付ファイル名のいずれかに部分一致（大小無視してよい） |
| `exclude` | 任意 | 除外語。ヒットから除く |
| `from` / `to` | 任意 | 公開日のから〜まで（Asia/Tokyo の暦日 `YYYY-MM-DD`。`published_at` を東京日に換算） |
| `author` | 任意 | 作成者メール（完全一致。利用者または管理者） |

対象は、呼び出し手が読める公開メモ。下書きは作成者本人が検索したときだけ、本人の下書きも対象にしてよい（クエリ `drafts=1` を足してもよい。必須は公開検索）。

親のみ／返信込みは `scope=parents|all`（省略時 `parents` をタイムラインに合わせ、検索は `all` を既定にしてスレッド内も拾える、とする）。

#### 2.5.3 失敗の `code`（この工程で足すもの）

| code | 使うとき |
|---|---|
| `memo_not_found` | 無い・削除済み・他人の下書き |
| `body_too_long` | 本文が 2000 コードポイント超 |
| `tag_limit` | タグが 21 件以上 |
| `tag_invalid` | タグが空、または 100 文字超 |
| `link_limit` | リンクが 21 件以上 |
| `link_invalid` | URL が空、または不正（スキームなし等。簡易検証でよい） |
| `attachment_limit` | 添付が既に 20 |
| `edit_window_closed` | 公開後編集が期限外 |
| `forbidden_memo` | 作成者以外が本文編集、他人のブックマーク削除など |
| `parent_not_found` | 返信先が無い・削除済み・下書き（他人） |
| `not_draft` | 公開済みに publish した |
| `bookmark_not_found` | 外す対象の自分のブックマークが無い |

## 3. 処理の規則

### 3.1 誰が使えるか

- 投稿・閲覧・返信: 招待利用者全員（圃場0枚含む）および管理者。
- ソフト削除: そのメモの作成者、または管理者。
- 本文等の編集（下書き、および公開後の編集窓内）: **作成者本人のみ**。管理者は他人の本文を編集せず、削除で対応する。
- ブックマークの外し: 付けた本人のみ。

### 3.2 本文・タグ・リンク

- 本文: Unicode コードポイント最大 2000。空の公開は不可（下書きは空を許してよい）。
- タグ: 最大20。各1〜100文字（前後空白除去）。同じメモ内の重複は保存時に畳んでよい。
- リンク: 最大20。文字列として保存。クリック可能な表示は詳細の UI。

### 3.3 下書きと公開

- `status` は `draft` / `published`。
- 下書きは作成者の GET drafts・本人検索以外に出ない。
- 公開時に `published_at` と `content_saved_at` を現在 UTC で立てる（未設定だった場合）。
- 公開後に下書きへ戻すことはしない。

### 3.4 編集窓

- 公開済みの本文・タグ・リンク・添付の変更は、作成者かつ `now <= content_saved_at + 30 minutes` のときだけ可。
- 成功した保存のたびに `content_saved_at` を更新する（都度延長）。
- 期限後の変更は `edit_window_closed`。直すときはソフト削除して新規作成。
- **返信の新規追加**は、親の編集窓の内外を問わずできる。返信自身のその後の編集は、その返信の `content_saved_at` 規則に従う。

時計の正本はサーバ（UTC で保存し、30分は絶対時間）。

### 3.5 スレッド

- `parent_id` が NULL の行が親。返信は既存の未削除メモを親にできる（公開済み。他人の下書きは不可）。
- **深さの上限は設けない。**
- タイムラインは親のみ。スレッド表示は未削除・公開の子孫。

### 3.6 ソフト削除

- 対象メモに `deleted_at` を立てる。
- そのメモの **すべての子孫**にも `deleted_at` を立てる（まだ無いもの）。
- 通常のタイムライン・検索・ブックマーク一覧・スレッドから除外する。
- ブックマーク行は残してよいが、一覧 API は削除済みメモを出さない。
- 削除済みだけを集めた利用者向け一覧は必須にしない。

### 3.7 添付

- ディレクトリ例: `data/memo-files/{memo_id}/`（起動引数で根を変えてよい）。
- DB に `filename`（元名）、`content_type`、`body_ref`（相対パスまたはファイル名）。
- 種類・1ファイルサイズの上限は設けない。基盤が拒否した場合は汎用の失敗応答でよい。
- 1メモあたり未削除添付は最大20。
- 公開後の追加・削除も編集窓内の作成者のみ。下書きは作成者がいつでも可。

### 3.8 ブックマーク

- 公開済み・未削除メモにのみ付与可。下書き不可。
- 同一作成者（kind+id）が同一メモへ二重付けしない（既にあれば成功のまま戻してよい）。
- 共通一覧の規則は §2.4。

### 3.9 連動の禁止

- 実行状態・作業時間・チェック・塗り・％・指示・日誌と自動同期しない。
- ガント紐づけ列はこの工程では持たない。

## 6. この工程で作らないもの

- スマホでのメモ対等化（第2版工程4）
- ガント作業との紐づけ（第2版工程5）
- いいね、メンション、予約投稿、位置、通知、リポスト、引用、DM、フォロー、おすすめ、トレンド
- 編集窓クローズ後の公開後編集
- 深さ上限による拒否
- 添付の種類・サイズ上限の製品必須化
- 管理者による他人本文の編集（削除は可）

## 7. 完了として満たすこと（詳細）

- 利用者・管理者がパソコンで投稿・閲覧・入れ子返信・下書き・公開できる。
- 公開後、`content_saved_at` から30分以内は作成者が本文・タグ・リンク・添付を直せ、保存で延長される。期限後は `edit_window_closed`。
- ソフト削除で本人または管理者が消せ、子孫も通常操作から消える。
- タグ・リンク各最大20、添付最大20、本文2000コードポイント。
- 検索が本文・タグ・ファイル名を対象とし、期間・除外語・作成者が使える。
- 共通ブックマークがあり、外すのは付けた本人だけ。
- タイムラインは公開親のみ・新しいものが上。SNS 的拡散が無い。
- スマホ専用画面およびガント紐づけが、この工程の必須成果に混入していない。
