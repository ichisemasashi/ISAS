# ISAS システム利用者ガイド

| 項目 | 内容 |
|---|---|
| 文書版 | 1.0 |
| 対象baseline | `v1.0.0` |
| 対象者 | 作業員、受託作業者、現場責任者、組織管理者、グループ管理者 |
| 対象画面 | ISAS Web／PWA（スマートフォン、tablet、PC） |
| 注意 | 利用できる画面・圃場・操作は、所属組織、role、担当圃場、online/offline状態で異なる。表示されない管理機能はシステム管理者へ確認する |

## 1. ISASでできること

ISASは、今日の作業を確認し、打刻、作業日誌、農薬使用、在庫、圃場、予定を一つの流れで扱う営農支援システムである。圃場が圏外でも、担当作業の参照と現場記録を端末へ保存でき、通信が戻ると同期する。

主な機能は次のとおり。

- 今日の担当作業、安全確認、開始／休憩／終了の打刻。
- 作業指示、14日予定、圃場一覧／地図。
- 打刻、指示、template、前回値を使った日誌と写真。
- 農薬masterの鮮度、適用作物、希釈、使用回数、収穫前日数の事前確認。
- 入庫／出庫／棚卸し調整による在庫管理。
- 日誌の承認、理由付き差し戻し、訂正、同期競合の裁定。
- 圃場、作業記録、農薬履歴のCSV取込と、圃場台帳、日誌、農薬記録のCSV出力。

## 2. 最初に確認すること

### 2.1 必要なもの

- 管理者から案内されたISASのHTTPS URL。
- 組織が指定するログインaccountとMFA認証器。
- 画面lock、OS/browser更新、十分な空き容量を設定した個人または管理済み端末。
- 写真、位置、通知等を使う場合のbrowser／OS許可。位置ログはPhase 1で収集しないが、将来利用時も目的と同意を確認する。

共有OS accountやroot／jailbreak端末へ機密dataを長期保存しない。端末を他人へ貸す前にlogoutし、紛失時は直ちに管理者へ連絡する。

### 2.2 初回login

1. 管理者から案内されたURLを開く。検索広告や第三者から届いた似たURLを使わない。
2. 組織の認証画面でloginし、要求されたMFAを完了する。
3. ISASに戻ったら、右上／下部に表示される利用者名、組織名、roleを確認する。
4. 複数組織に所属する場合は「表示する組織」で作業先を選ぶ。別組織の記録を作る前に必ず再確認する。
5. 通信状態が「オンライン」、認証状態が「認証済み」、未同期が0件か確認する。

認証器を失った場合は、別accountを作らず組織管理者の回復手順を使う。回復後は古いsessionが失効し、再loginを求められることがある。

productionでは右上の利用者アイコン→「その他」→「ログアウト」を押す。未同期がある場合は安全のため終了できないので、通信を戻して「未同期 0件」を確認して再実行する。成功すると同期済みcache鍵を暗号消去し、BFF sessionとIdP logoutへ進む。端末紛失や同期不能時はbrowser dataを消さず、管理者へ未同期outbox回復を依頼する。実iOS/Androidと実Cognitoで共有端末試験が合格するまでは共有端末を本番利用しない。

### 2.3 PWAとして追加する

対応browserでは、browser menuの「ホーム画面に追加」「アプリをインストール」等からPWAとして使える。名称はOS/browserで異なる。

- 初回online時に担当作業、圃場、安全masterを開き、必要なcacheを保存する。
- private browsingでは端末保存が消えることがあるため現場記録に使わない。
- OSの自動storage整理でdataが消えないよう、永続storage要求を許可できる場合は許可する。
- browser dataの消去、アプリ削除、端末初期化は未同期0件を確認してから行う。

## 3. Roleと表示範囲

| Role | 主な操作 |
|---|---|
| 作業員 | 自分の担当指示、打刻、自分の日誌／農薬／在庫event、担当圃場 |
| 受託作業者 | 選択中組織で付与された受託範囲。組織ごとにroleとscopeが異なる |
| 現場責任者 | 担当範囲の指示、進捗、日誌確認。経営情報は閲覧限定の場合がある |
| 組織管理者 | 自組織の指示、記録、利用者、master、CSV、競合／在庫裁定 |
| グループ管理者 | 単一法域内の配下組織。複数shard集計は`complete`だけを権威用途に使う |

roleが同じでも担当圃場groupによって表示範囲が異なる。必要な圃場が見えない場合、他人のaccountを借りず管理者へassignment／scopeを確認する。

## 4. 画面の見方

### 4.1 Navigation

| Menu | 内容 |
|---|---|
| 今日 | 今日の打刻、担当作業、安全確認、記録へのshortcut |
| 予定 | 作業指示と同じdataを使う14日timeline／モバイルlist |
| 記録 | 作業日誌の入力。今日の作業から選ぶと指示を引き継ぐ |
| 圃場 | 担当圃場の一覧、検索、地図、offline cache |
| その他 | 表示／言語、同期queue、管理者機能、CSV |

PCでは左側、スマートフォンでは画面下部に同じ順序で表示する。「本文へ移動」linkはkeyboard／screen reader用である。

### 4.2 常時表示される状態

| 表示 | 意味 | 行動 |
|---|---|---|
| オンライン | serverへ接続できる | 通常操作。未同期が減るか確認 |
| オフライン | 通信できない | 許可された現場記録を端末保存。account管理等は待つ |
| 認証済み | 現在の権限をonline確認済み | 通常操作 |
| オフライン記録可 | 認証猶予内 | 現場記録だけ可能。管理操作は行わない |
| オフライン読取のみ | 認証猶予が進んだ | cache参照だけ。再認証まで新規確定不可 |
| 再認証が必要 | 権限変更または猶予終了 | 未同期を消さず、onlineで「再認証する」 |
| 未同期 N件 | N件が端末保存済みだがserver未受理 | app/browser dataを消さず通信回復を待つ |

「端末に保存しました」は「serverへ同期済み」と同じではない。作業終了前に未同期件数を確認する。

## 5. 今日の作業と打刻

### 5.1 作業を確認する

1. 「今日」を開く。
2. 日付、担当作業数、「安全確認が必要」の表示を確認する。
3. 作業cardで時刻、圃場、作物、作業名、状態を確認する。
4. 「予定を見る」で期間／担当を確認するか、「記録する」で日誌へ進む。
5. 「安全確認」が出ている作業は、通常の記録より先に農薬基準を確認する。

### 5.2 打刻する

1. 作業開始時に「作業を始める」。
2. 休憩開始時に「休憩する」、再開時に「作業に戻る」。
3. 終了時に「作業を終える」。
4. 端末保存のmessageと未同期件数を確認する。

打刻は追記recordであり、端末時計とserver受理時刻の両方を残す。時刻が大きくずれている場合もevent UUIDを変えて再登録せず、同期後に責任者へ訂正を依頼する。休憩中は作業時間に含めない。

## 6. 予定・作業指示

### 6.1 作業員が予定を見る

- mobileはlist、広い画面はtimelineを使う。前後14日、今日への移動、予定開始／終了、担当、進捗を確認できる。
- 作業を選ぶと同じ指示IDの日誌へ進める。timelineと「今日」で内容が違う場合は再読込し、直らなければ指示IDを管理者へ伝える。

### 6.2 管理者が指示を発行する

1. onlineで「その他」→「作業指示を発行」を開く。
2. 圃場ID、担当者ID、指示名、作業種別、開始／終了、優先度、詳細を入力する。
3. 終了が開始より後、圃場と担当者が正しいtenant／scopeであることを確認する。
4. 「オンラインで発行」を押し、今日／予定へ反映された指示IDを確認する。

再割当はonline専用である。別管理者の更新と競合した場合、古い画面で上書きせず最新内容を読み直す。

## 7. 作業日誌

### 7.1 新規日誌

1. 今日の作業から「記録する」、または「記録」menuを開く。
2. 圃場、作業種別、開始／終了を確認する。作業指示と打刻から候補が入り、欠落があれば警告される。
3. templateまたは前回値を使い、今回と違う値だけ直す。前回値を無確認で提出しない。
4. memo、数量等の必要項目を入力する。
5. 写真を添付する場合は内容、圃場、個人情報の写り込みを確認する。
6. 保存し、「端末に保存」「まもなく同期」またはoffline保存messageを確認する。
7. online復帰後、未同期が減り、差し戻し／競合がないことを確認する。

時間が未入力または打刻pairが不足する場合は推測で埋めず、実時刻を確認する。日誌は30秒以内を目標にしているが、正確さと安全を優先する。

### 7.2 写真

- JPEG、PNG、WebP、HEIC、1枚10MB以下を対象とする。
- 写真は日誌本文が受理された後に同じattachment IDで冪等uploadされる。本文同期後も写真が保留の場合、app dataを消さず再送を待つ。
- 他人の顔、車番、位置を示す不要物、秘密情報を写さない。業務上必要な写真だけを添付する。
- 同じattachment IDへ違う写真を再利用できない。差し替えが必要なら新しい添付として記録する。

### 7.3 承認・差し戻し・訂正

管理者は「その他」→「日誌の承認・差し戻し」で内容を確認する。

- 承認：作業、圃場、時間、写真、農薬／在庫の関連が正しい場合に行う。
- 差し戻し：理由を具体的に入力する。理由なしでは差し戻せない。
- 訂正：担当者は「訂正が必要な日誌」で理由を読み、「訂正する」から修正内容と訂正理由を入力する。
- 承認済みrecordを消して作り直さず、revisionとして訂正する。

## 8. 農薬記録と安全確認

### 8.1 記録手順

1. 「今日」の安全確認、または「農薬記録を始める」を開く。
2. 圃場、作物、薬剤、散布日、希釈倍率、散布量、使用目的、収穫予定日を確認する。
3. masterのrelease version、最終同期、有効期限、失効日を確認する。
4. 判定結果と理由を読む。
5. 警告がなくても現物label、法令、責任者指示を確認して記録する。
6. offlineでは端末cacheで事前判定し、同期時にserverが再判定する。結果が変わった場合は管理者queueで処置する。

### 8.2 警告の意味

| 警告 | 確認すること |
|---|---|
| master期限切れ／判定不能 | online更新または責任者確認まで安全確認完了とみなさない |
| 登録失効 | 使用を中止し、代替と回収／保管を責任者へ確認 |
| 適用作物外 | 圃場の作物と薬剤登録を再確認。名称が似た作物を選ばない |
| 希釈範囲外 | label、単位、原液／希釈後の区別を確認 |
| 使用回数超過 | 当年履歴と未同期記録を確認。別端末の記録も考慮 |
| 収穫前日数不足 | 散布日と予定収穫日を確認し、使用／収穫計画を責任者へ相談 |

警告は「記録を通すための確認box」ではない。override権限があっても、根拠、責任者確認、理由なしに続行しない。ISASの判定は現物labelや法令確認を置き換えない。

## 9. 在庫

### 9.1 入庫・出庫

1. 資材、event種別、数量、単位、発生時刻、関連作業を確認する。
2. 正の数量で記録する。出庫を負数入力で表さず、種別で区別する。
3. offlineでも端末保存できる。同期前は他端末のeventが未反映の可能性を考える。

### 9.2 マイナス在庫と棚卸し

- 残高はeventから導出され、直接編集できない。
- マイナスalert時は実棚、未同期、重複、単位、入庫漏れを確認する。
- 管理者は実棚数量を基に差分の棚卸し調整eventを追記する。過去eventを削除／改ざんしない。
- 理由と確認者を残し、農薬・法定資材は現物管理手順にも従う。

## 10. 圃場一覧・地図

- 「圃場」で担当範囲の一覧とpolygonを表示する。名前検索と表示範囲bboxで絞り込む。online背景は地理院標準地図で、画面下の「地理院タイル」リンクを常時表示する。
- offlineで背景も使う場合は、Wi-Fi接続中に対象圃場を一覧で選び、「選択圃場周辺をオフライン保存」を1回押す。進捗が「Nタイル・N MiBを端末へ保存しました」になるまで画面を閉じない。保存対象は担当field-groupのbbox＋2km、zoom 8〜16で、日本全体や地理院タイルは保存しない。
- 保存後は「保存済み背景へ切替」で確認する。画面下に「© OpenStreetMap contributors」と保存期限が出ることを確認する。「オンライン背景へ切替」で地理院標準地図へ戻る。
- 圏外では有効期限内かつ現在の担当versionと一致する保存済み背景を自動選択する。期限切れ、割当変更、hash不一致、250MiB不足では背景を使わず、担当圃場polygonを単色背景上へ表示する。未同期日誌や圃場境界は背景削除の対象にならない。
- 圃場が出ない場合は、組織、担当group、検索条件、online/cacheを確認する。別組織の圃場を期待していないか確認する。
- 境界や属性が誤っている場合は、業務開始前に管理者へ圃場ID、場所、正しい内容を伝える。似た名称だけで農薬記録先を決めない。

## 11. 同期・offline・競合

### 11.1 同期の順序

onlineへ戻ると、ISASは原則として次の順に処理する。

1. P0の農薬安全／権限失効を取得。
2. 端末outboxをpush。
3. 通常差分をpull。
4. 差し戻し／競合queueを更新。

未同期はserverが「受理」または「重複」と返すまで消えない。通信中断時に同じ操作を何度も新規入力せず、自動再送を待つ。

### 11.2 差し戻しqueue

「その他」→「差し戻し」で理由と回復操作を確認する。

- 権限変更：再認証し、現在権限で受理できるか確認する。
- scope外：誤った圃場なら正しい記録へ訂正。作成時に正当だった法定記録は管理者回復へ送る。
- 旧version：原文が保全済みか確認し、管理者の変換を待つ。

拒否されたeventを端末から手動削除して件数だけ0にしない。

### 11.3 競合queue

同じfieldを別端末で変更した場合、両方の値を残して管理者が裁定する。

1. 対象field、サーバ値、端末値、時刻、入力者を確認する。
2. 「サーバ値を採用」または「端末値を採用」を選ぶ。
3. 根拠が不明なら当事者へ確認し、推測で選ばない。
4. 裁定後の画面と変更履歴を確認する。

### 11.4 端末／アプリ更新

- 更新通知が出ても、未同期が1件以上または入力中なら更新を保留する。
- 未同期0件を確認し、入力を保存して「今日」へ戻ってから更新する。
- 強制終了、browser data消去、PWA削除、OS初期化を更新手段にしない。
- 更新後に組織、認証、未同期、今日の作業を確認する。

## 12. CSV取込・出力（管理者）

### 12.1 取込

`migration:manage`を持つ管理者だけがonlineで行う。

1. 「その他」→「CSVデータ取込」で圃場、作業記録、農薬履歴を選ぶ。
2. UTF-8 CSVを選び、ISAS項目へ列をmappingする。
3. 検査し、必須、形式、参照、file内／DB内重複を確認する。
4. errorがあれば元fileを直し、新jobとして再検査する。
5. 検査済みだけを「取込を確定」する。圃場→作業記録→農薬履歴の順を守る。

### 12.2 出力

`export:read`を持つ管理者だけが行う。

1. 圃場台帳、作業日誌、農薬記録を選ぶ。
2. 日誌／農薬は開始日・終了日を確認する。
3. 選択中tenantとRLS範囲だけが出ること、件数、文字化け、期間を確認する。
4. fileを安全な保管先へ移し、不要なdownload copyを削除する。

第三者masterはlicenseにより再配布できない場合がある。詳細な列、50,000行／200列上限、重複keyは[CSVデータ移行・出力ガイド](../CSVデータ移行・出力ガイド.md)を参照する。

## 13. 表示・言語・accessibility

- 右上の「表示」で屋外向け→dark→高contrastを切り替える。
- 「EN／日本語」で表示言語を切り替える。baseline 1.0は日英切替基盤を持つが、未翻訳の日本語が残る場合がある。意味が不明な農薬／作業語を推測せず管理者へ確認する。
- browser zoom／OS文字拡大を利用できる。200% zoom、keyboard、skip link、screen readerを想定する。
- 安全状態は色だけでなくicon、見出し、文を読む。色だけで判断しない。
- 屋外、手袋、片手操作では送信結果が出るまで画面を確認し、二重tapを避ける。

## 14. Security・privacyの利用者ルール

- account、MFA、回復codeを共有しない。管理者もpasswordやMFA codeを聞かない。
- URLと鍵markを確認し、不審な再login、証明書警告、MFA連打通知は操作を止めて報告する。
- 作業終了時や共有端末ではlogoutし、画面lockを有効にする。
- CSV、写真、画面captureを私用cloud、SNS、個人messagingへ送らない。
- 必要最小限の写真／memoだけを記録し、個人情報や他tenant情報を含めない。
- 他者の打刻／位置／労務を目的外に見ない。位置履歴の閲覧は限定権限と監査対象である。
- 誤ったtenantで記録した、別組織dataが見えた、知らない圃場が出た場合は即座に操作を止め、時刻と画面だけを管理者へ報告する。dataをさらに開かない。

## 15. よくある問題と対処

| 表示／症状 | 利用者の対処 |
|---|---|
| Loginできない | URL、通信、時刻、MFAを確認。繰り返さず管理者へcorrelation ID／時刻を連絡 |
| 「再認証が必要」 | onlineにして再認証。未同期dataやbrowser dataを消さない |
| 「オフライン読取のみ」 | 新規記録を確定せず、通信回復後に再認証。下書きを保持 |
| 未同期が減らない | 通信、認証、storage空き、差し戻し／競合を確認。appを削除しない |
| 今日の作業が古い | online確認→同期を待つ。担当者／組織が正しいか確認 |
| 圃場が見えない | 組織、検索、担当scope、offline cacheを確認し圃場IDを管理者へ連絡 |
| 写真が送れない | 10MB以下と形式、storage、通信を確認。日誌本文と写真の状態を別々に伝える |
| 農薬判定不能／期限切れ | 使用判断を止め、online更新または責任者へ確認 |
| 競合がある | 管理者が両値を比較するまで同じ内容を新規作成しない |
| CSV error | 行番号、列mapping、必須、参照、重複を直し新jobで再検査 |
| 更新できない | 未同期／入力中を解消し「今日」へ戻る。data消去で直さない |
| 画面が崩れる | zoom、向き、browser更新を確認。端末／OS／browser／画面名を報告 |

## 16. 問い合わせ・障害報告

### 16.1 連絡先

組織の管理者が次を埋めて配布する。

| 窓口 | 連絡先／受付時間 |
|---|---|
| 操作・権限 | `未設定` |
| 農薬／食品安全 | `未設定` |
| 端末紛失・security | `未設定` |
| System障害／夜間 | `未設定` |
| Privacy／開示・訂正・削除 | `未設定` |

`未設定`のまま利用開始しない。

### 16.2 報告する内容

- 発生日時とtimezone。
- 選択していた組織、画面名、操作。ただしpassword、MFA code、tokenは送らない。
- online/offline、認証状態、未同期件数。
- 表示messageと非PII correlation ID。
- 端末種別、OS、browser／PWA、version。
- 再現手順、業務影響、安全への影響、回避策の有無。

画面captureに氏名、圃場名、農薬、位置、写真が含まれる場合は、組織指定の安全な経路だけで送る。

### 16.3 直ちに連絡する事象

- 別組織／別利用者のdataが見える。
- 農薬安全判定が現物label／法令と矛盾する。
- 「端末保存済み」と表示された未同期記録が消えた。
- 不審なlogin、MFA、account変更、端末紛失。
- 誤った大量取込／出力、個人情報の誤送信。

これらは追加操作を止め、時刻と状態を保ったまま緊急窓口へ連絡する。

## 17. 作業終了時checklist

- [ ] 今日の打刻状態が終了または意図した状態になっている。
- [ ] 日誌、農薬、在庫の端末保存messageを確認した。
- [ ] 未同期件数を確認し、0でなければ通信回復予定を把握した。
- [ ] 差し戻し／競合／農薬／在庫alertを確認した。
- [ ] 正しい組織へ記録した。
- [ ] 共有端末はlogoutし、端末をlockした。
- [ ] CSV／写真の不要なlocal copyを残していない。

## 18. Baseline 1.0の既知制限

- production IdP／logout、永続session、実HTTP runtimeは配備前の接続が必要。
- 日本語／英語切替は一部文言が日本語のまま残る。意味が不明な安全項目を推測しない。
- 地理院online背景、private PMTiles／担当範囲cache、写真object storage adapterは実装済みだが、実日本PMTilesのAWS staging公開とiOS／Android実端末試験は未完。production受入前は業務利用しない。
- 表示上の機能があっても、本番環境の管理者がrelease gateを完了するまで業務利用を開始しない。

## 19. 管理者向け機能の早見表
