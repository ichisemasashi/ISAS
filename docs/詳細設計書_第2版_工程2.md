## 1. この工程で実現すること

ガント作業（行）に、任意の **作業時間**（複数件）と **チェック項目**（複数件）を付けられるようにする。無くても実行状態と日次一覧だけで使える。実行状態・塗り・面積％とは自動連動しない。

### 1.1 部品

- **作業時間。** 表 `gantt_work_times`。1行は開始・終了（分まで）。親は `gantt_rows.id`。
- **チェック項目。** 表 `gantt_checklist_items`。1行は項目名と状態（やった／まだ）。親は `gantt_rows.id`。
- **編集画面。** `/works` および `/gantt` の行編集から、子を単独で追加・更新・削除する。
- **日次要約。** `/daily` および `GET /api/user/gantt/daily` に件数要約を足す。一覧上の全編集は必須にしない。

## 2. 画面と経路

### 2.1 ブラウザの経路

| 経路 | 誰 | ログイン | 役割（この工程の追加） |
|---|---|---|---|
| `/works` | 利用者 | 必要 | 作業の編集に、作業時間・チェック項目の一覧と単独追加・更新・削除 |
| `/gantt` | 利用者 | 必要 | 題名配下の行編集に、同上 |
| `/daily` | 利用者 | 必要 | 各行に作業時間・チェックの要約。全編集 UI は必須にしない |

狭い画面では第2版工程1どおりパソコン案内のみ。作業時間・チェックの変更 UI は出さない。ガント棒（横／縦）からは変えない。

### 2.2 `/works`・`/gantt` の行編集に出すもの

- **作業時間。** 未削除の件を開始昇順（同値なら id）で一覧。追加・各件の開始／終了の更新・削除。
- **チェック項目。** 未削除の件を id 昇順で一覧。追加・項目名／状態の更新・削除。新規作業に空の枠を自動で1つ出さない。
- 対象圃場が無い行でも、上記を付けられる。
- 配置のピクセルは定めない。

### 2.3 `/daily` の要約

各行に少なくとも次が分かる。

- 作業時間: 件数（0 なら「なし」または件数 0。画面文言は §5）
- チェック: `やった数 / 総数`（総数 0 のときはチェック要約を出さない、または「なし」）

一覧から `/works` 等へ進む導線はあってよい。一覧上で時間の全件編集やチェック全部を完結させることは、この工程の必須としない。

### 2.4 API（Clojure）

自分の利用者セッションが必要。管理者は `forbidden`。親行が無い・他人・親がソフト削除済みは `gantt_not_found`。圃場0枚は `no_fields`。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/gantt/{id}/work-times` | GET | 未削除の作業時間一覧 |
| `/api/user/gantt/{id}/work-times` | POST | 1件追加 |
| `/api/user/gantt/{id}/work-times/{tid}` | PUT | 1件更新 |
| `/api/user/gantt/{id}/work-times/{tid}` | DELETE | 1件ソフト削除（`deleted_at`） |
| `/api/user/gantt/{id}/checklist-items` | GET | 未削除のチェック項目一覧 |
| `/api/user/gantt/{id}/checklist-items` | POST | 1件追加 |
| `/api/user/gantt/{id}/checklist-items/{cid}` | PUT | 1件更新 |
| `/api/user/gantt/{id}/checklist-items/{cid}` | DELETE | 1件ソフト削除 |
| `/api/user/gantt/daily` | GET | 工程1に加え要約フィールド（§2.5） |
| `/api/user/gantt` | GET | 一覧に要約を含めてよい（任意。日次は必須） |

親の `PUT /api/user/gantt/{id}` で子配列を一括置換することは、この工程の必須としない。

#### 2.4.1 作業時間の本文

POST / PUT:

```
{
  "start_at": "2026-09-21T08:00",
  "end_at": "2026-09-21T10:30"
}
```

成功の1件:

```
{
  "id": 1,
  "gantt_id": 10,
  "start_at": "2026-09-21T08:00",
  "end_at": "2026-09-21T10:30"
}
```

GET 一覧は `{ "ok": true, "work_times": [ ... ] }`。並びは `start_at`、同値なら `id`。

#### 2.4.2 チェック項目の本文

POST / PUT:

```
{
  "label": "油量確認",
  "status": "pending"
}
```

`status` は `pending`（まだ）または `done`（やった）。PUT で `label` または `status` のみ送ってよい（省略した方は維持）。

成功の1件:

```
{
  "id": 1,
  "gantt_id": 10,
  "label": "油量確認",
  "status": "done"
}
```

GET 一覧は `{ "ok": true, "checklist_items": [ ... ] }`。並びは `id` 昇順。

#### 2.4.3 日次一覧への要約

`GET /api/user/gantt/daily` の各行に、工程1の欄に加えて:

```
"work_time_count": 2,
"checklist_done": 1,
"checklist_total": 3
```

いずれも **未削除の子だけ**を数える。親がソフト削除済みの行は工程1どおり日次に出ない。

#### 2.4.4 失敗の `code`（この工程で足すもの）

| code | 使うとき |
|---|---|
| `work_time_not_found` | 作業時間が無い、他人の親、または削除済み |
| `checklist_item_not_found` | チェック項目が無い、他人の親、または削除済み |
| `time_invalid` | 開始または終了が `YYYY-MM-DDTHH:MM` でない（第1版と同名でよい） |
| `time_order` | 終了が開始と同じか、より前 |
| `label_required` | 項目名が無い、または空白だけ |
| `label_too_long` | 前後空白除去後 200 文字超 |
| `checklist_status_invalid` | `pending` / `done` 以外 |

## 3. 処理の規則

### 3.1 誰が使うか

- 第2版工程1と同じく、圃場1枚以上の利用者のパソコンとする。
- 管理者・圃場0枚は使えない。
- 狭い画面（スマホ幅）では、作業・ガント・日次・圃場・地図へのナビ／ホームリンクを出さない（押せずに案内だけになる導線を避ける）。直接 URL で開いたときだけパソコン案内を出す。
- 狭い画面で使える導線は、ホーム・指示・招待・パスワード・ログアウトとする。

### 3.1a 操作結果の表示（flash）

- 成功・失敗の文言は、ページ先頭だけでなく、操作したフォーム／区画の直上にも出せる（flash に `near`＝区画 id）。
- 作業時間・チェックの追加／保存／削除、作業の保存、日次の実行状態保存は、操作箇所寄りに結果を出す。
- `near` 付きのときは先頭の flash は出さない。短い画面（ログイン等）は従来どおり先頭のみ。

### 3.1b 操作ログ（サーバ）

- 追加・更新・ソフト削除・拒否は `isas.log` に残す（画面には出さない）。
- 作業時間・チェックの CRUD、親／題名削除時の子件数、日時不正の拒否を含む。

### 3.2 作業時間

- 1親あたり 0 件以上。件数上限はこの工程では設けない。
- 開始＜終了（同じ時刻は不可）。形式は第1版ガントと同じ `YYYY-MM-DDTHH:MM`（Asia/Tokyo・秒なし）。
- 親ガントの開始〜終了の外側にはみ出してよい。
- 複数件の時間帯が互いに重なってよい。
- 長さは開始と終了から求める（保存列は必須にしない。画面で分または時間を出してよい）。

### 3.3 チェック項目

- 1親あたり 0 件以上。新規に空枠を自動追加しない。
- `label` は前後空白を除いて 1〜200 文字。同じ親内の重複名を許す。
- `status` は `pending` / `done` のみ。
- マスタ／テンプレートは必須にしない。

### 3.4 自動連動の禁止

- 作業時間の追加・更新・削除、チェックの追加・更新・削除・全「やった」でも、`execution_status` は変えない。
- 塗り・面積％・地図色・日次確定％・指示・日誌は変えない。

### 3.5 ソフト削除

- 子の DELETE は、その子に `deleted_at`（UTC）を立てる。物理削除しない。
- 親のガント作業をソフト削除するとき、その親に付く **未削除の子すべて**にも `deleted_at` を立てる。
- 親がソフト削除済みのとき、子の GET/POST/PUT/DELETE は `gantt_not_found`（親が通常操作で見えないのと同じ）。
- 削除済みの子だけを集めた利用者向け一覧画面は、この工程では作らない。
- 親の復活導線は、この工程では作らない。

## 4. 残す情報

### 4.1 `gantt_work_times`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `gantt_id` | INTEGER | `gantt_rows.id` |
| `start_at` | TEXT | 日本時間 `YYYY-MM-DDTHH:MM` |
| `end_at` | TEXT | 同上。`start_at` より後 |
| `created_at` | TEXT | UTC |
| `updated_at` | TEXT | UTC |
| `deleted_at` | TEXT | ソフト削除時刻（UTC）。NULL＝表示中 |

### 4.2 `gantt_checklist_items`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `gantt_id` | INTEGER | `gantt_rows.id` |
| `label` | TEXT | 正規化した項目名。空にしない |
| `status` | TEXT | `pending` / `done` |
| `created_at` | TEXT | UTC |
| `updated_at` | TEXT | UTC |
| `deleted_at` | TEXT | ソフト削除時刻（UTC）。NULL＝表示中 |

外部キーは `gantt_id` → `gantt_rows(id)`。起動時に表が無ければ作る。

## 6. この工程で作らないもの

- 担当・繰り返し・通知
- メモおよびガント紐づけ
- 実行状態・塗り・％との自動連動
- スマホおよびガント棒からの作業時間・チェック編集
- 日次一覧上での全編集の必須化
- チェック項目マスタ／テンプレートの必須化
- 削除済み子だけの利用者向け一覧、親の復活
- 合算％・横断ダッシュボード（要求 §8）

## 7. 完了として満たすこと（詳細）

- ガント作業に作業時間を 0 件以上付けられ、開始＜終了・単独 CRUD・親外側・相互重なり可である。
- チェック項目を 0 件以上付けられ、自由記述名（1〜200）・`pending`/`done`・重複名可・単独 CRUD である。
- 対象圃場の無い行でも付けられる。
- `/works` と `/gantt` の行編集から操作でき、`/daily` に要約が出る。
- 時間・チェックで実行状態・塗り・％が自動では変わらない。
- ガント棒から変えられない。狭い画面では作業・ガント・日次の入口自体を出さない。
- 親ソフト削除で未削除の子もソフト削除され、通常操作から見えなくなる。
- 担当・繰り返し・通知・メモが、この工程の成果に混入していない。
