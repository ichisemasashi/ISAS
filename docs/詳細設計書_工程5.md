## 1. この工程で実現すること

時々の依頼を指示として回し、受け手が対象圃場の進捗色を見て日誌を書けるようにする。所有者がパソコンで地図を塗り、指示を閉じる。自分だけで塗る流れ（工程2〜4）は、指示が無くてもそのまま動く。

工程5で動かす論理ブロックは、基本設計書 §10 のとおり、指示と日誌、関係による見え方、管理者の関係切断、スマホの役割である。

### 1.1 工程5の部品

- **入れ物。** 工程1〜4の Clojure / ClojureScript / API / SQLite / OpenLayers / JTS を足して使う。
- **指示。** 日付（日本時間の暦日 `YYYY-MM-DD`）、同じ日の開始・終了（`HH:MM`）、作業名、依頼文、受け手1人以上、出した人の圃場1枚以上。日をまたがない。ガント行 ID は持たない。閉じは削除ではない。再開しない。
- **日誌。** 指示1件につき受け手1人1通。任意。圃場内訳も％欄も持たない。本文に％を書いても記録だけとする。受けた指示なら、パソコンでも狭い画面でも書ける。
- **見え方。** 受け手が、その指示の対象圃場だけを以降も見られる。関係した作業名の、所有者の塗り色だけを出す。受け手は塗れない。進捗地図は対象が見える位置に合わせ、自分の作業場所の下地を重なる範囲だけ張る。他人の下地は使わない。作業場所の値は変えない。
- **切断。** 管理者だけ。二人のあいだを双方向。どちらの向きでも進行中の指示があれば切れない。
- **通知。** 置かない。相手への連絡は、招待と同じくシステムの外とする。

## 2. 画面と経路

管理者側に、指示・日誌・他人の地図は置かない。関係の切断だけを足す。利用者で入っていないときは、工程1どおり `/` へ進む。

### 2.1 ブラウザの経路（ClojureScript）

| 経路 | 誰 | ログイン | 狭い画面 | 役割 |
|---|---|---|---|---|
| `/orders` | 利用者 | 必要 | 可 | 出した指示と受けた指示の一覧 |
| `/orders/new` | 利用者 | 必要 | 不可 | 指示の作成。圃場が0枚なら使えない |
| `/orders/{id}` | 利用者 | 必要 | 可 | 1件の確認。対象地図と日誌。閉じる前の修正と閉じはパソコン |
| `/others` | 利用者 | 必要 | 不可 | 今見えている他人の対象圃場をまとめて見る。塗れない |
| `/admin/relations` | 管理者 | 必要 | 可 | 二人のメールアドレスを指定して関係を切る |

利用者ホーム `/home` に、出した／受けた指示への出口を足す。指示の作成は、圃場が1枚以上のときだけ出す。管理者ホームには指示を出さない。関係の切断への出口は、管理者ナビの「関係を切る」（`/admin/relations`）を1つだけとする。ホーム本文には重ねて出さない。

狭い画面（工程2と同じ判定）では、次とする。

- `/orders` と `/orders/{id}` は使える（進捗色と、受けた指示への日誌）。
- `/orders/new`、`/others`、`/gantt`、`/map` の編集は、工程2〜4どおり「パソコンで開いてください」。
- `/orders/{id}` の、依頼文・時刻の修正と閉じも、狭い画面では出さない（パソコン案内）。

`/map` には他人の圃場を混ぜない。ログイン直後の地図の主は、工程2どおり自分の圃場とする。

### 2.2 `/orders/{id}` に出すもの

配置のピクセルは定めない。

- 日付、開始、終了、作業名、依頼文、受け手のメール、対象圃場の名前。
- 進行中／閉じた。
- **地図。** 見えてよい対象圃場だけ。その指示の作業名の未／一部／済。初期位置は対象圃場が見える範囲とする。自分の作業場所の下地を、重なる範囲だけ張る。他人の下地は使わない。作業場所の値は変えない。パーセントサークルは出さない。画面の地図要素は `#ol-map`（`data-order-mode`）とし、詳細表示時に作業場所・下地・指示地図 API を読んで色を付ける。狭い画面でも同じ地図と対象の進捗色を出す。
- **詳細の読み込み順。** `/orders/{id}` を開いたときは、ログイン確認のあと `GET /api/user/place` → `GET /api/user/orders/{id}` → `GET /api/user/orders/{id}/map` → `GET /api/user/basemaps` の順で読み、最後に HTML を描く。狭い画面でもこの順とする（修正・閉じの操作だけ出さない）。
- **日誌。** 受け手が書いた本文。出した人は確認できる。受け手は、閉じる前かつ未記入なら、パソコンでも狭い画面でも1通書ける。
- 出した人かつ進行中かつパソコン: 依頼文と日付・時刻の修正、閉じる。受け手の追加・削除、対象圃場の追加・削除は出さない。

関係を切ったあと、記録（依頼文・時刻・作業名・受け手・日誌）は残す。相手の圃場の形と色は出さない。出した人の自分の対象圃場は、出した人には見え続ける。

### 2.3 API（Clojure）

工程1と同じ JSON の形とする。自分の利用者セッションが必要（管理者切断 API を除く）。管理者セッションで利用者の指示 API は `forbidden`。他人の指示は、出した人でも受け手でもなければ `not_found`。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/orders` | GET | 出した指示と受けた指示。`{ "sent": [...], "received": [...] }` |
| `/api/user/orders` | POST | 指示を1件出す。本文は日付、開始、終了、作業名、依頼文、`recipient_emails`、`field_ids` |
| `/api/user/orders/{id}` | GET | 1件。対象の形は、今見えてよい枚だけ |
| `/api/user/orders/{id}` | PUT | 進行中かつ出した人。`body`、日付、開始、終了だけ。受け手と対象は無視して変えない |
| `/api/user/orders/{id}/close` | POST | 進行中かつ出した人。閉じる。本文なし |
| `/api/user/orders/{id}/journal` | POST | 受け手。閉じる前。本文 `{ "body" }`。1通だけ |
| `/api/user/orders/{id}/map` | GET | 見えてよい対象圃場の形と、その指示の作業名の `status` |
| `/api/user/others/fields` | GET | 今見えている他人の圃場（名前、形、所有者のメール） |
| `/api/user/others/work-names` | GET | 見えている他人の圃場について、関係した指示の作業名（重複なし） |
| `/api/user/others/paints` | GET | クエリ `work_name`。見えている他人の圃場の、その作業名の `status`。関係していない名前なら `code: work_name_required` と同じく使えない（`work_name_unrelated`） |
| `/api/admin/relations/cut` | POST | 管理者。`{ "email_a", "email_b" }`。双方向に切る |

`DELETE` で指示や日誌を消す API は置かない。再開の API も置かない。

工程4の作業名候補に、自分が **出した** 指示の作業名を足す。

| 経路 | 工程5での追加 |
|---|---|
| `GET /api/user/work-name-candidates` | 塗った名前、ガントの作業名・表示名、出した指示の作業名。受けた指示の名前は足さない |
| `DELETE /api/user/fields/{id}` | 進行中の指示の対象なら保存せず `field_in_open_order`。そうでなければ消し、他人からの見えからも外す |
| `POST /api/user/fields/{id}/split` | 進行中の指示の対象なら `field_in_open_order` |
| `POST /api/user/fields/merge` | 対象のどれかが進行中の指示の対象なら `field_in_open_order` |

`GET /api/user/orders/{id}` の成功本文（要点）:

```
{
  "ok": true,
  "id": 1,
  "role": "issuer" | "recipient",
  "status": "open" | "closed",
  "work_date": "2026-09-12",
  "start_time": "08:00",
  "end_time": "17:00",
  "work_name": "田植え",
  "body": "...",
  "issuer_email": "...",
  "recipient_emails": ["..."],
  "fields": [ { "id": 1, "name": "...", "visible": true } ],
  "journals": [ { "author_email": "...", "body": "...", "created_at": "..." } ]
}
```

日時は暦日 `work_date`（`YYYY-MM-DD`）と、同じ日の `start_time` / `end_time`（`HH:MM`）とする。日をまたがない。

`visible` が `false` の対象は、名前を出さず `id` も出さない（存在だけ分からないようにする）。切ったあとの受け手向けは `fields` を空にする。出した人には自分の対象が `visible: true` のまま出る。

`GET /api/user/orders/{id}/map` は、`visible` な対象だけを工程3と同じ `status` で返す。パーセントは返さない。

失敗の `code` を工程5で足すもの:

| code | 使うとき |
|---|---|
| `no_fields` | 圃場0枚の利用者が指示を出そうとした |
| `order_not_found` | その指示が無い、または出した人でも受け手でもない |
| `order_closed` | 閉じた指示を直す／閉じる／日誌を書く |
| `order_not_issuer` | 出した人以外が閉じる／直す |
| `order_not_recipient` | 受け手以外が日誌を書く |
| `journal_exists` | その受け手がすでに1通書いている |
| `journal_required` | 日誌本文が無い、または空白だけ |
| `journal_too_long` | 日誌が2000文字を超える |
| `body_too_long` | 依頼文が2000文字を超える |
| `recipients_required` | 受け手が0人 |
| `recipient_self` | 出した人自身が受け手に含まれている |
| `recipient_not_user` | 招待されていない、取り消されている、管理者、形式不正。理由は分けない |
| `fields_required` | 対象圃場が0枚 |
| `field_not_found` | 対象に他人の圃場、または存在しない ID |
| `field_in_open_order` | 進行中の指示の対象である圃場の削除・分割・合筆 |
| `work_name_required` | 作業名が無い（工程3と同じ） |
| `work_name_too_long` | 100文字を超える（工程3と同じ） |
| `work_name_unrelated` | 他人地図で、関係した指示に無い作業名 |
| `time_invalid` | 日付または時刻の形式が違う |
| `time_order` | 終了が開始と同じか、より前 |
| `relation_busy` | どちらの向きでも進行中の指示がある二人を切ろうとした |
| `relation_not_found` | 指定の二人が利用者として無い、同一人、管理者を含む |
| `relation_idle` | 今見えている相手の圃場が、どちらの向きにも無い |

`recipient_not_user` は、存在しないアドレスと取り消された利用者と管理者を文面で分けない（工程1のログイン失敗と同じ考え方）。

## 3. 処理の規則

### 3.1 誰が出すか・誰が受けるか

- 出せるのは、圃場を1枚以上持つ利用者だけとする。管理者は出せない。0枚の利用者は出せない。
- 受け手は、取り消されていない利用者だけとする。メールアドレスで指定する。利用者の全員一覧 API は置かない。
- 出した人自身は受け手にできない。
- 対象は出した人の圃場だけとする。受け手の圃場は混ぜられない。
- 工程3の塗りと工程4のガントは、指示が無くても使える。指示 API を呼ぶことを、塗り・ガントの条件にしない。

### 3.2 指示の作成と修正と閉じ

- 日付は日本時間の暦日 `YYYY-MM-DD`。開始と終了は同じ日の `HH:MM`。終了は開始より後。日をまたがない。
- 作業名は必須。工程3と同じ正規化。新しい名前は指示の欄に入れて使える。
- 依頼文は空でもよい。前後空白を除いて保存する。
- 受け手は1人以上。同じ指示に同じ人を二重に付けない。メールは工程1どおり正規化（前後空白を除き、英字は小文字）。
- 対象圃場は1枚以上。同じ指示に同じ圃場を二重に付けない。
- 閉じる前は依頼文と日付・開始・終了だけ直せる。
- 出した人が `close` する。日誌が0通でも閉じられる。`closed_at` を UTC で残す。以降は直さない・日誌を足さない・再開しない。
- 画面の新規の初期値は、日付＝今日、開始 08:00、終了 17:00、依頼文空、としてよい。保存前に直せる。

### 3.3 日誌

- 受け手本人だけが書ける。出した人は書けない。パソコンでも狭い画面でも、同じ POST を使う。
- 閉じる前かつ、その受け手の行がまだ無いときだけ POST できる。
- 書いたら直せない・消せない。2通目は `journal_exists`。
- ％用の列は持たない。サークルも地図色も変えない。
- 著者と本文と作成時刻（UTC）を残す。

### 3.4 見え方

ある利用者 V に、他人の圃場 F が見えるのは、次をすべて満たすときとする。

1. F の所有者が V ではない。
2. 所有者が出した指示のうち、V が受け手で、F が対象に含まれているものが1件以上ある（同じ所有者の他の圃場が依頼に載っていなくても、載っていない枚は見えない）。
3. その指示の `created_at` が、所有者と V のあいだの最後の切断時刻より後である。切断が無ければ、2 だけでよい。
4. F が台帳に残っている。

見える F について出せる作業名は、上の 2〜3 を満たす指示の `work_name` だけとする。所有者の他の塗り（関係していない作業名）は出さない。

切ったあと:

- 指示と日誌の行は残る。
- V からは、相手の圃場の形も色も出ない（その指示の地図も含む）。
- 新しい指示の対象になった枚だけ、再び見える。以前見えていたが新しい指示に載っていない枚は見えない。

ログイン直後の `/map` は自分の圃場だけとする。`/others` と指示詳細の地図にも、対象外の相手圃場は出さない。

### 3.5 進捗色（他人）

- 色の具体値は工程3のまま（未 `#c8c8c8`、一部 `#e6b800`、済 `#2e7d32`）。
- 指示の詳細地図は、その指示の作業名で色を付ける。
- `/others` は、開いたときは形だけ。関係した作業名を選ぶとその色。選ばなければ形だけ。
- 受け手は塗れない。他人の `paints` への POST は置かない。既存の自分の圃場向け API に他人の ID を付けても `not_found` のままとする。
- 進捗地図（指示の詳細と `/others`）は、対象が見える位置に合わせる。自分の作業場所の下地を、その範囲と重なる部分だけ張る。重ならなければ下地なしとする。他人の下地は使わない。作業場所の保存値は変えない。

### 3.6 関係の切断（管理者）

- 画面はメールアドレス2つとする。関係の一覧表は必須にしない。取り消されていない利用者は、工程1の `GET /api/admin/users` で確認してよい。
- どちらの向きでも、進行中（`closed_at` が空）の指示が、一方を出した人・他方を受け手に含むなら `relation_busy`。
- 切れるときは、その二人の組について切断時刻を残す（§4.5）。以降、切断以前の指示では相手の圃場が見えない。
- 今、3.4 の意味で見えている相手の圃場がどちらの向きにも無い二人は `relation_idle` とし、切る操作はしない。
- 出した人も受け手も、切断 API を持たない。

### 3.7 圃場の削除・分割・合筆

- 進行中の指示の対象になっている圃場は、削除も分割も合筆もできない。
- 閉じた指示の対象だけなら、削除してよい。消えた枚は他人からも見えなくなる。指示の行は残す（対象 ID は残るが、地図には出さない）。
- ガント対象であることだけでは、工程4どおり止めない。進行中の指示があるときだけ工程5で止める。

## 4. 残す情報（工程5）

工程4の表は壊さない。足す単位は次とする。ガント行に指示 ID は足さない。

### 4.1 指示 `orders`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `issuer_id` | INTEGER | 出した人 `users.id` |
| `work_date` | TEXT | 日本時間の暦日 `YYYY-MM-DD` |
| `start_time` | TEXT | 同じ日の `HH:MM` |
| `end_time` | TEXT | `HH:MM`。同じ日で開始より後 |
| `work_name` | TEXT | 正規化した作業名。空にしない |
| `body` | TEXT | 依頼文。空可 |
| `closed_at` | TEXT 空可 | 空なら進行中。値は UTC |
| `created_at` | TEXT | UTC |
| `updated_at` | TEXT | UTC |

### 4.2 指示の受け手 `order_recipients`

| 列 | 型 | 内容 |
|---|---|---|
| `order_id` | INTEGER | `orders.id` |
| `user_id` | INTEGER | 受け手 |

主キーは `(order_id, user_id)` とする。出した人は含めない。

### 4.3 指示の対象 `order_targets`

| 列 | 型 | 内容 |
|---|---|---|
| `order_id` | INTEGER | `orders.id` |
| `field_id` | INTEGER | `fields.id` |

主キーは `(order_id, field_id)` とする。作成時の出した人の圃場だけとする。作成後は行を足さない・消さない（圃場自体の削除は §3.7）。

### 4.4 日誌 `journals`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `order_id` | INTEGER | |
| `user_id` | INTEGER | 書いた受け手 |
| `body` | TEXT | 空にしない |
| `created_at` | TEXT | UTC |

`(order_id, user_id)` を一意とする。訂正列は持たない。

### 4.5 関係の切断 `relation_cuts`

| 列 | 型 | 内容 |
|---|---|---|
| `user_lo` | INTEGER | 二人のうち小さい `users.id` |
| `user_hi` | INTEGER | 大きい方 |
| `cut_at` | TEXT | UTC。同じ組を再度切るときはこの時刻を更新する |

主キーは `(user_lo, user_hi)` とする。見え方は §3.4 のとおり、指示の `created_at` とこの時刻から求める。圃場ごとの見え方表は持たない。

## 6. 工程5で作らないもの

- 通知、写真、チャット
- 指示とガントの自動紐づけ、ガント行番号
- オフライン下書き
- 管理者アカウントが指示を出す／受けること
- 公開名簿からの受け手選択（メール指定のみ）
- 他人の対象外圃場、受け手同士の圃場
- 出した人自身を受け手にすること
- 利用者同士での関係の切断

## 7. 完了として満たすこと（詳細）

基本仕様書 §5.9 に加え、次を満たす。

- 指示が1件も無くても、工程2〜4の API と画面は工程4までどおり動く。
- 招待済みの相手に出し、受け手が `/orders/{id}` で対象の色を見られる。
- 日誌0通でも閉じられる。閉じた指示の PUT / close / journal は失敗する。
- 閉じる前の PUT で受け手と `field_ids` を送っても、保存された受け手と対象は変わらない。
- 対象外の相手圃場は `/others` にも指示地図にも出ない。
- 管理者が切ると、互いに相手の圃場が出なくなる。出した人・受け手の切断 API は無い。
- 進行中の指示がある二人は `relation_busy` である。
- 出した人は狭い画面でも、出した指示の対象色を見られる。日誌の POST は受け手だけが成功する。
- `/map` に他人の圃場が混ざらない。

## 11. 確定した判断

1. **指示の日付と時刻の持ち方。** 暦日 `YYYY-MM-DD` と、同じ日の開始・終了 `HH:MM` とする。終了は開始より後。日をまたがない。
2. **他人の圃場・指示の進捗地図の下地。** 対象が見える位置に合わせ、自分の作業場所の下地を重なる範囲だけ張る。他人の下地は使わない。作業場所の値は変えない。
3. **日誌を書く画面。** 「指示」一覧の「受けた指示」から詳細を開く。受け手で進行中かつ未記入なら「日誌を投稿する」が出る。一覧には「日誌未記入／日誌済」の印を付ける。
