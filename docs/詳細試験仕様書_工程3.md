### 2.2 API（詳細設計 §2.2 の表）

自分の利用者セッションが必要。管理者は `forbidden`。他人の圃場は `field_not_found`（工程2と同じく存在を分けない）。

| 項番 | 出典（経路・方法） | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P3-2.2-01 | `GET /api/user/work-names` | API | 塗ったあと | 自分が塗った作業名。重複なし。塗りが1つ以上残っている名前だけ |
| P3-2.2-02 | `GET /api/user/paints` | API | クエリ `work_name` | 自分の全圃場について状態と塗りポリゴン |
| P3-2.2-03 | `GET /api/user/paints` 空 | API | `work_name` が無い／空 | `work_name_required` |
| P3-2.2-04 | `POST /api/user/paints` | API | `{ field_id, work_name, geojson }` 重ねた下書きを1回 | サーバが JTS で圃場内に切る。面積が取れなければ保存しない。1回の確定は `paints` の1行 |
| P3-2.2-05 | `POST /api/user/fields/{id}/complete` | API | `{ work_name }` | その圃場・その作業名の塗りを現在の圃場形全体に置き換える |
| P3-2.2-06 | `DELETE /api/user/paints/{id}` | API | 自分の塗り | 1つ消える。他人なら見つからない |
| P3-2.2-07 | `DELETE /api/user/fields/{id}/paints` | API | クエリ `work_name` 必須 | その圃場・その作業名の塗りを全部消す |
| P3-2.2-08 | 管理者 | API | 管理者 Cookie | `forbidden` |
| P3-2.2-09 | 他人の field_id | API | POST paints に他人 | 見つからない。存在を分けない |

## 3. 処理の規則

| 項番 | 出典 | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P3-3.1-01 | 所有者だけ | API | 他人の圃場へ POST | できない |
| P3-3.1-02 | 圃場0枚 | API・画面 | 圃場0 | 塗る対象が無い。作業名候補も空 |
| P3-3.1-03 | 下地へは保存しない | 保存 | 確定 | POST の GeoJSON は圃場形との交差だけ |
| P3-3.2-01 | 一筆ごとに API は呼ばない | 画面 | 下書きを重ねて1回確定 | 1回の POST |

| P3-3.4-01 | 改名しない | 禁止 | 別名で塗る | 別の行になる |
| P3-3.5-01 | 境界の修正は許す | API | 塗りがある圃場の頂点 | 保存後に内側へ切り直す。分割・合筆は拒否 |

## 8. 操作シナリオ（一連操作・ブラウザ）

単項目だけでは拾いにくい、画面の一連操作を試験する。API 単体や HTML 断片に代えない。ブラウザ自動試験（Playwright）でも確認する。

| 項番 | シナリオ名 | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P3-S-01 | 作業名は塗り無しで入れる | 画面・自動 | 利用者で `/map` を開く（browse）→ 作業名を入力 →「この作業名で見る」 | 「塗りをする」を押さなくても作業名欄がある。確定後はブラシ等が出る |
| P3-S-02 | ブラシ一筆のあと地図を動かす | 画面・自動 | 作業名を選び → ブラシ → 一筆書く → 地図をドラッグ | 一筆後はパンできる（軌跡がブラシのままにならない）。続けて塗るときは再度ブラシ |
| P3-S-03 | 開き直すと作業名が消える | 画面・自動 | 作業名を選んだあと `/map` を開き直す | 作業名未選択。進捗色なし。browse に戻る |
| P3-S-04 | 圃場を直すと形いじりに戻る | 画面 | 塗り中に「圃場を直す」 | 手描き等が出る。ブラシは出ない。作業名欄は残る |
