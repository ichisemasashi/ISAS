## 2. 画面と経路

### 2.1 ブラウザの経路（詳細設計 §2.1 の表）

未ログインで「必要」の経路を開いたときは、その側のログインへ進む。利用者 Cookie で管理者の保護画面は入れない。その逆も同じ。

| 項番 | 出典（経路） | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P1-2.1-01 | `/` 利用者 不要 ログイン | 画面 | 未ログインで `/` を開く | 利用者ログイン。見出しは「利用者ログイン」 |
| P1-2.1-02 | `/` 入済みなら `/home` | 画面 | 利用者で入った状態で `/` を開く | `/home` へ進む |
| P1-2.1-03 | `/reset/request` | 画面 | `/reset/request` を開く | パスワード再設定の依頼 |
| P1-2.1-04 | `/reset` クエリ `token` | 画面 | 案内リンク（`token` 付き）を開く | 新しいパスワードを決める画面 |
| P1-2.1-05 | `/home` 必要 | 画面 | 未ログインで `/home` | 利用者ログインへ進む |
| P1-2.1-06 | `/home` 必要 | 画面 | 利用者で `/home` | 入ったことが分かる。招待とパスワード変更への出口 |
| P1-2.1-07 | `/invite` | 画面 | 利用者で `/invite` | 招待画面。初期パスワードをその場で見せる |
| P1-2.1-08 | `/password` | 画面 | 利用者で `/password` | 本人のパスワード変更 |
| P1-2.1-09 | `/admin` | 画面 | 未ログインで `/admin` | 管理者ログイン。見出しは「管理者ログイン」 |
| P1-2.1-10 | `/admin` 入済みなら `/admin/home` | 画面 | 管理者で入った状態で `/admin` | `/admin/home` へ進む |
| P1-2.1-11 | `/admin/reset/request` | 画面 | 開く | 管理者の再設定依頼 |
| P1-2.1-12 | `/admin/reset` | 画面 | 管理者案内の `token` 付きで開く | 管理者の新しいパスワード |
| P1-2.1-13 | `/admin/home` | 画面 | 管理者で開く | 入ったことが分かる。招待・取消し・パスワード変更への出口。圃場・地図・ガント・指示は出ない |
| P1-2.1-14 | `/admin/invite` | 画面 | 管理者で開く | 利用者を招待し、初期パスワードをその場で見せる |
| P1-2.1-15 | `/admin/users` | 画面 | 管理者で開く | 取り消されていない利用者の取消し |
| P1-2.1-16 | `/admin/password` | 画面 | 管理者で開く | 本人のパスワード変更 |
| P1-2.1-17 | 種別違い | 画面 | 利用者で `/admin/home`。管理者で `/home` | どちらも入れない。その側のログインへ進む |
| P1-2.1-18 | 再設定リンクの組み立て | 保存 | 再設定依頼してメールを見る | リンクは `public_url` + `/reset` または `/admin/reset` + `token`。API の経路ではない |
| P1-2.1-19 | 公開登録を置かない | 禁止 | `/signup` および誰でも増える入口を探す | 経路も API も無い |

パソコンとスマホで同じ経路を使う。工程1では画面を端末別に分けない。

### 2.2 API（詳細設計 §2.2 の表）

JSON。`Content-Type` は `application/json`。成功は `{ "ok": true, ... }`、失敗は `{ "ok": false, "code": "..." }`。パスワードや取消しを GET で受けない。

| 項番 | 出典（経路・方法） | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P1-2.2-01 | `GET /api/user/session` | API | 未ログインで呼ぶ | `ok: false`, `code: unauthorized` |
| P1-2.2-02 | `GET /api/user/session` | API | 利用者で入って呼ぶ | `ok: true` とメールアドレス |
| P1-2.2-03 | `POST /api/user/login` | API | `{ email, password }` 正しい | Cookie `isas_user`。以降その Cookie で入れる |
| P1-2.2-04 | `POST /api/user/logout` | API | 利用者で呼ぶ | 利用者セッションが消える |
| P1-2.2-05 | `POST /api/user/logout` | API | 未ログインで呼ぶ | `unauthorized` |
| P1-2.2-06 | `POST /api/user/password/reset/request` | API | 存在する／しない／取り消された、各 `email` | 返事は常に `ok: true` |
| P1-2.2-07 | `POST /api/user/password/reset` | API | 有効な `token` と一致する新パスワード | 入れ、ログインへ進める状態になる |
| P1-2.2-08 | `POST /api/user/password` | API | ログイン中。今のパスワードと新・確認 | 変わる。今のログインは維持してよい |
| P1-2.2-09 | `POST /api/user/invite` | API | ログイン中。新しい `email` | 成功時だけ `initial_password` を含む |
| P1-2.2-10 | `GET /api/admin/session` | API | 未ログイン／管理者で入っている | 利用者側と同じ形。Cookie は `isas_admin` |
| P1-2.2-11 | `POST /api/admin/login` | API | 正しい管理者 | Cookie `isas_admin` |
| P1-2.2-12 | `POST /api/admin/logout` | API | 管理者で呼ぶ | 管理者セッションが消える |
| P1-2.2-13 | `POST /api/admin/password/reset/request` | API | 存在する／しない | 常に `ok: true`。利用者アカウントは変わらない |
| P1-2.2-14 | `POST /api/admin/password/reset` | API | 管理者の有効トークン | 管理者パスワードが変わる |
| P1-2.2-15 | `POST /api/admin/password` | API | 管理者で今のパスワードと新・確認 | 変わる |
| P1-2.2-16 | `POST /api/admin/invite` | API | 管理者。新しい `email` | 成功時だけ `initial_password` |
| P1-2.2-17 | `GET /api/admin/users` | API | 管理者 | `{ users: [ { id, email } ] }`。取り消されていない人だけ |
| P1-2.2-18 | `POST /api/admin/users/revoke` | API | `{ user_id }` | 以後その人はログインも再設定もできない |
| P1-2.2-19 | 利用者 Cookie で管理者 API | API | `isas_user` のまま `/api/admin/*` の保護 | `unauthorized` |
| P1-2.2-20 | 管理者 Cookie で利用者 API | API | `isas_admin` のまま `/api/user/invite` など保護 | `unauthorized` |
| P1-2.2-21 | GET でパスワード変更・取消し | 禁止 | `GET` で password / revoke を呼ぶ | 受けない |

失敗の `code` 表:

| 項番 | 出典（code） | 種別 | 手順の要点 | 期待 |
|---|---|---|---|---|
| P1-2.2-c01 | `unauthorized` | API | ログインが必要だが入っていない。または種別が違う Cookie | `code: unauthorized` |
| P1-2.2-c02 | `login_failed` | API・画面 | 無いアドレス、パスワード違い、取り消された利用者でログイン | いずれも `login_failed`。画面は「メールアドレスまたはパスワードが違います」の1通り。理由は分けない |
| P1-2.2-c03 | `reset_invalid` | API・画面 | トークン無し、使済み、期限切れ、種別違い、取消し済み | いずれも `reset_invalid`。画面は「この案内は使えません。もう一度やり直してください」 |
| P1-2.2-c04 | `invite_invalid_email` | API・画面 | 形式でないアドレスで招待 | 招待しない。画面は「メールアドレスの形式ではありません」 |
| P1-2.2-c05 | `invite_duplicate_user` | API・画面 | 取り消されていない利用者と同じアドレスで招待 | 招待しない。画面は「このメールアドレスは、すでに利用者として招待されています」 |
| P1-2.2-c06 | `invite_duplicate_admin` | API・画面 | 管理者と同じアドレスで招待 | 招待しない。画面は「このメールアドレスは管理者のため、利用者として招待できません」 |
| P1-2.2-c07 | `password_mismatch` | API | 確認用が一致しない（変更または再設定） | 変えない |
| P1-2.2-c08 | `password_too_short` | API | 8文字未満 | 変えない |
| P1-2.2-c09 | `password_wrong` | API | 今のパスワードが違う | 変えない |

`/signup` に相当する API は置かない（P1-2.1-19 と同じ）。
