# ISAS 開発工程表（第2版・草案）

- 版: 0.1
- 状態: 草案
- 日付: 2026-09-21
- 要求の正本は [要求仕様書_第2版.md](要求仕様書_第2版.md)（版 1.0・合意）とする。本紙は、第2版をどの順で作るかと、各工程の目的・完了条件だけを定める草案である。
- 第1版は完了している前提とする。第1版の正本は [要求仕様書.md](要求仕様書.md)、工程の順は [工程表.md](工程表.md) とする。
- 工程ごとの振る舞い（基本仕様）と論理構成（基本設計）は、**各工程の着手前に**同じ合意で文書化する。第2版工程1の基本仕様は [基本仕様書.md](基本仕様書.md#第2版-工程1-実行状態と日次一覧) とする。

- 第2版で足すのは、日々の農作業タスク管理と X 型メモの二つだけとする（要求仕様書第2版 §2）。

## 1. 作業手順

毎回、次の順で仕事する。

1. **要求を先に見る。** 作るものは [要求仕様書_第2版.md](要求仕様書_第2版.md) に書いてあることに限る。§2 の対象外は作らない。§8 の任意は、第2版の必須完了条件にしない。
2. **今の工程だけを終わらせる。** 完了条件を満たしたら次へ進む。先の工程の画面やデータ構造を「ついで」に作らない。
3. **仕様変更は文書が先。** 動きを変えたくなったら、実装より先に要求仕様書第2版を直して合意する。工程の振る舞いが変わるなら基本仕様も同じ合意で直す。論理構成が変わるなら基本設計も同じ合意で直す。工程表の工程名・完了条件が変わるなら、本紙も同じ合意で直す。
4. **How の部品名は工程の着手時に最小限。** 全体の基盤製品を先に作り直さない。第1版の入れ物・API の形を壊さない。
5. **終わりに実機で確認する。** パソコン工程はパソコンで、スマホ工程はスマホでも、完了条件を一通り操作して確かめる。
6. **工程の成果物は動くこと。** レビュー記録や運用書の整備を工程の完了条件にしない。第2版の受入は工程5だけとする。

## 工程1　実行状態と日次一覧

基本仕様: [基本仕様書.md](基本仕様書.md#第2版-工程1-実行状態と日次一覧) の第2版工程1

基本設計: 着手前に必要なら更新する

**目的:** パソコンで、今日／今週のガント作業を未着手／着手中／完了で回せる。

**作るもの**

- 既存のガント作業（行）への **実行状態**（未着手／着手中／完了）
- パソコンの **日次一覧**（今日／今週）
- 実行状態による **フィルタ**
- 一覧および作業編集からの **実行状態の変更**

**完了条件**

- ガント作業に実行状態が付き、三値だけである。
- パソコンで今日・今週の日次一覧が出せる。
- 実行状態でフィルタでき、状態を変えられる。
- 面積％の規則は第1版のままである（実行状態で上書きしない）。
- スマホから実行状態を変えられない。

**この工程でやらないこと**

- 作業時間・チェック項目（工程2）。
- メモ全般（工程3以降）。
- 担当・繰り返し・通知。
- 予定と塗りの同期・必須リンク。
- カレンダー専用 UI の新設。

## 工程2　作業時間とチェック項目

基本仕様: [基本仕様書.md](基本仕様書.md#第2版-工程2-作業時間とチェック項目) の第2版工程2

**目的:** 面積では測れない作業も、同じ実行状態に加え、任意の作業時間・チェック項目で扱える。

**作るもの**

- ガント作業に付けられる **作業時間**の記録（任意）
- ガント作業に付けられる **チェック項目**（任意）
- パソコンからの入力・更新・削除

**完了条件**

- 対象圃場の無い行でも、実行状態に加え、作業時間・チェック項目を付けられる。
- 作業時間・チェック項目が無くても、実行状態だけで日次一覧が使える（任意である）。
- 担当の割当は無い。

**この工程でやらないこと**

- 担当・繰り返し・通知。
- メモ全般。
- 合算％・横断ダッシュボード（要求 §8 の任意。受入必須にしない）。

## 工程3　メモ（パソコン）

基本仕様: 着手前に作成する（第2版・工程3）

**目的:** 招待メンバがパソコンで、短いメモを時系列に残し、共有・検索できる。

**作るもの**

- メモの投稿（本文は日本語 2000 文字まで）
- スレッド、下書き、ソフト削除（公開後編集はしない）
- リンク添付、ファイル添付（1 メモあたり最大 20。サイズ上限なし）
- 自由記述のタグ
- メンバ全員の閲覧・返信
- 検索および高度な検索（期間・除外語など）
- ブックマーク（自分用）
- パソコンの時系列一覧（おすすめ・トレンド・フォロー網は置かない）

**完了条件**

- 招待メンバがメモを投稿・閲覧・返信できる。
- 公開後に本文を編集できない。削除（ソフト削除）と作り直しで直せる。
- タグ・検索・高度な検索・ブックマークが使える。
- リンクとファイル添付が、上限どおり動く。
- 公開 SNS 的な拡散（リポスト・引用・フォロー等）が無い。

**この工程でやらないこと**

- スマホ専用の確認・調整（工程4）。
- ガント作業との紐づけ（工程5）。
- いいね、メンション、予約投稿、位置、コミュニティ、通知（要求の後回し／対象外）。
- メモの公開後編集。

## 工程4　メモ（スマホ）

基本仕様: 着手前に作成する（第2版・工程4）

**目的:** スマホでもメモの投稿・閲覧・返信・検索・ブックマークができる。

**作るもの**

- 工程3のメモ機能のスマホ画面（ファイル添付を含む）
- 狭い画面でも一通り操作できること

**完了条件**

- スマホでメモの投稿・閲覧・返信・検索・ブックマークができる。
- ファイル添付ができる。
- スマホからガント作業の実行状態は変えられない（工程1の制約のまま）。

**この工程でやらないこと**

- スマホでの塗り・境界編集・ガント時刻編集など、第1版でパソコン限定の操作の解禁。
- ガント作業との紐づけ（工程5）。
- 通知。

## 工程5　任意紐づけと第2版の受入

基本仕様: 着手前に作成する（第2版・工程5）

**目的:** メモとガント作業を任意で紐づけられるようにし、第2版として一通り使えることを確認する。

**作るもの**

- メモとガント作業（行）の **任意紐づけ**（必須ではない）
- 紐づけても実行状態・塗り・％が自動では変わらないことの確認
- 工程1〜4を通した受入操作の確認

**完了条件**

- メモとガント作業を任意で紐づけ／外せる。
- 紐づけても塗り・％・実行状態は自動同期しない。
- 要求仕様書第2版 §10 の成功条件を、実データ（自分の圃場と、招待した別メンバ）で操作して満たせる。
  - (a) パソコンで今日／今週のガント作業を未着手／着手中／完了で回せる
  - (b) 面積以外の作業も同じ実行状態と任意の時間・チェックで扱える
  - (c) メンバ全員が読めるメモをパソコンとスマホで残し共有できる
- 要求仕様書第2版 §2 の対象外が、画面にも工程にも混入していない。
- §8 の任意（作業名マスタ、横断ダッシュボード等）が未実装でも、受入を止めない。

**この工程でやらないこと**

- 対象外機能の復活。
- §8 の任意を必須化すること。
- 運用マニュアルや本番多重化の整備を第2版の必須にしない。

## 3. 工程をまたいで守ること

- 実績の正本は地図の塗りである。実行状態もメモも、塗りを置き換えない。
- 予定はガントと指示の二冊のままとし、第2版でも自動同期しない。
- タスクの本体はガント作業（行）である。実行状態は三値のみである。
- 担当・繰り返し・通知、スマホでの実行状態変更は作らない。
- メモはメンバ全員が閲覧・返信できる。公開後は編集しない。
- 作業名は一致キーのままとする。メモのタグは自由記述であり、作業名規則を変えない。
