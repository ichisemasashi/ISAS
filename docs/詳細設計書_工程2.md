## 1. この工程で実現すること

利用者が、自分の農地を名前と形で地図に載せる。下地は作業場所範囲の画像3種（自動取得または手作業）である。作業場所の決定には国土地理院タイルを使う。管理者の入口に台帳も地図も出さない。

工程2で動かす論理ブロックは、基本設計書 §10 のとおり、作業場所と下地、圃場台帳と地図（自分の圃場、パソコン）である。

### 1.1 工程2の部品

- **入れ物。** 工程1の Clojure / ClojureScript / JSON API を足して使う。新しい別アプリは置かない。
- **形の保存。** 閉じた形は GeoJSON の Polygon または MultiPolygon を TEXT で SQLite に残す。座標は経度緯度（WGS84）とする。取込が他の座標系なら、保存する前に経度緯度へ直す。
- **面積。** 保存しない。読むときに形から㎡を求め、一覧では ha（㎡ ÷ 10000）を小数第2位まで出す。詳細では㎡を整数で出す。手入力の面積欄は置かない。
- **下地画像。** 利用者1人につき3種（`standard` / `aerial` / `satellite`）。作業場所の東西南北に張り付ける。同じマシンのファイル `data/basemaps/` に置く。SQLite の中には入れない。Git に画像は入れない。自動取得（eMAFF 優先、不可時は地理院タイル合成）と手作業取込の両方。
- **地図の描画部品。** OpenLayers とする。GeoJSON の表示、境界の手描きと頂点の直し、画像を範囲に張る。**作業場所決定画面では地理院 XYZ タイルを出す。** OSM タイルは出さない。
- **パソコン。** 地図と台帳の編集はパソコンの画面とする。スマホでは工程1のログイン・招待・パスワードは使えるが、地図編集は出さない。狭い画面で地図の経路を開いたときは「パソコンで開いてください」とする。

## 2. 画面と経路

管理者側に工程2の経路は置かない。利用者で入っていないときは、工程1どおり `/` へ進む。

### 2.1 ブラウザの経路（ClojureScript）

| 経路 | 誰 | ログイン | 役割 |
|---|---|---|---|
| `/fields` | 利用者 | 必要 | 圃場台帳（名前と ha の一覧。削除。地図へ） |
| `/map` | 利用者 | 必要 | 自分の地図。作業場所、下地、手描き、修正、分割、合筆、区画取込 |
| `/map/place` | 利用者 | 必要 | 作業場所の範囲を決める／変える |

利用者ホーム `/home` に、台帳と地図への出口を足す。管理者ホームには足さない。

作業場所が未設定のとき、`/map` は `/map/place` へ進む。台帳 `/fields` は開ける（0枚でよい）。

### 2.2 API（Clojure）

JSON は工程1と同じ `{ "ok": true }` / `{ "ok": false, "code": "..." }` とする。区画ファイルと下地画像の送信だけは `multipart/form-data` とする。

自分の利用者セッションが無い呼び出しは `unauthorized` とする。管理者セッションでは工程2の API に入れない（`forbidden`）。他人の圃場 ID は `not_found` とし、存在を分けて出さない。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/place` | GET | 作業場所。未設定なら `ok: false`, `code: place_unset`。設定済みなら東西南北。下地を合わせたあとなら `image_west` ほかも返す |
| `/api/user/place` | PUT | `{ "west", "south", "east", "north" }`。範囲を置き換える。古い下地と合わせた四隅は使えない状態にする |
| `/api/user/place/image` | PUT | `{ "west", "south", "east", "north" }` で下地の四隅を残す。`{ "reset": true }` で作業場所の範囲に戻す |
| `/api/user/basemaps` | GET | 3種それぞれが取り込済みかどうか |
| `/api/user/basemaps/{kind}` | PUT | 画像ファイル。`kind` は `standard` / `aerial` / `satellite` |
| `/api/user/basemaps/{kind}` | GET | 画像本体。Cookie 付き。未取込は `not_found` |
| `/api/user/place/preview` | POST | `{ "west","south","east","north" }`。最終確認用。成功時 `{ ok, source: "emaff"|"gsi", kind: "aerial" }` |
| `/api/user/emaff/import` | POST | 作業場所が必要。下地3種の自動保存。筆ポリゴンは手作業取込。部分成功可 |
| `/api/user/fields` | GET | 自分の圃場一覧。`id`, `name`, `area_ha`, `area_m2`, `geojson` |
| `/api/user/fields` | POST | `{ "name", "geojson" }`。手描きの新規 |
| `/api/user/fields/{id}` | PUT | `{ "name" }` および／または `{ "geojson" }` |
| `/api/user/fields/{id}` | DELETE | 削除 |
| `/api/user/fields/{id}/split` | POST | `{ "polygons": [ geojson, ... ] }`。2つ以上。元を消し、仮名で新規にする |
| `/api/user/fields/merge` | POST | `{ "keep_id", "ids" }`。`ids` に残す側を含む2つ以上。残す側の名前で1枚にし、他を消す |
| `/api/user/fields/import` | POST | GeoJSON ファイル。複数ポリゴンは1枚ずつ |

`kind` 以外の下地名は受けない。OSM タイル URL を返す API は置かない。地理院タイルはクライアントが公開 XYZ を直接参照する（API で URL を配らない）。

失敗の `code` を工程2で足すもの:

| code | 使うとき |
|---|---|
| `forbidden` | 管理者セッションで利用者の地図 API を呼んだ |
| `place_unset` | 作業場所がまだ無い |
| `place_invalid` | 東西南北が閉じていない、または西≥東、南≥北 |
| `shape_not_area` | 点や線など、面積が取れない |
| `basemap_kind` | 3種以外 |
| `basemap_missing` | その種がまだ無い |
| `emaff_unavailable` | eMAFF／代替取得が使えない |
| `emaff_empty` | 範囲内に取れる筆が無い |
| `emaff_partial` | 一部だけ取れた（warnings あり） |
| `emaff_busy` | 同じ利用者の自動取込がすでに進行中 |
| `field_not_found` | 自分の圃場として無い |
| `split_too_few` | 分割結果が2枚未満 |
| `merge_too_few` | 合筆対象が2枚未満 |
| `merge_keep_missing` | 残す側が対象に含まれない |
| `import_invalid` | GeoJSON として読めない |
| `phone_map` | 使わない（画面側の案内用。API では出さない） |

### 2.3 作業場所

- 利用者に1つとする。東西南北（経度緯度）で範囲を持つ。地名検索は置かない。
- 決め方は、パソコンの地図をパンとズームし、「この範囲を作業場所にする」で PUT する。
- 未設定のときは `/map/place` で国土地理院タイル（標準地図）を東経129〜146・北緯26〜46 で開き、自分で動かす。OSM は出さない。
- **変更するとき**は `/map` の「作業場所を変える」から `/map/place` を開く。画面はいま保存している東西南北で開き、「いまの作業場所を変えられます…」と案内する（未設定用の「先に作業場所の範囲を…」は出さない）。
- 範囲を候補にしたあと、最終確認として空中写真を一時表示する（eMAFF 優先。不可時は地理院空中写真）。**表示範囲は直前に地図で見ていた東西南北とする。** 確定してから作業場所とする。確認用の案内はエラーではない。
- 空中写真の最終確認画面では、「地理院地図に戻って範囲を直す」で標準地図に戻れる。戻ったあとも候補の東西南北は保持する。
- 確定（PUT）のあと下地3種の自動取込を始める。取込中は画面に待ち案内を出し、確定ボタンを出さない。同じ利用者の自動取込が重なったときは `emaff_busy` とし、進行中の1件だけを続ける。
- 変更したら、以前の3種の下地は使わない（削除する）。新しい範囲の3種を取り直す（自動取得を勧める）。圃場の行は消さない。
- 地図 `/map` を開いた位置は、必ずこの範囲とする。圃場の広がりでは変えない。既定の下地は空中写真とする。空中写真がまだなら下地なしで同じ範囲を出す（地理院を常時下地にはしない）。

### 2.4 下地

- 3種は、作業場所の範囲に合わせて張る。画像の四隅の初期値は作業場所の東西南北とする。OpenLayers の画像レイヤとして出す。
- **自動取得**では、可能な限り座標付きで保存し、手動の移動・拡縮を必須にしない。手作業で入れた座標無し画像だけ、従来どおり合わせ操作を出す。
- eMAFF から取れないときの下地自動生成は、国土地理院の公開 XYZ を作業場所の東西南北で合成した JPEG とする。**合成結果は候補範囲どおりに切り出す**（タイル全体を無理に伸ばさない）。空中写真はズーム14以上、衛星はズーム9〜13（ランドサット）を使い、見た目が同じにならないようにする。帰属は画面に出す。
- 筆ポリゴン（区画）の自動取得は行わない。区画は手作業の GeoJSON 取込を使う。作業場所確定後の自動取込は下地3種のみとする。
- 農地ナビの iframe 埋め込みと画面キャプチャ専用操作は置かない。受け付ける手作業画像は JPEG と PNG とする。
- 切替は画面の操作で、表示する `kind` を変えるだけとする。既定は `aerial`。

### 2.5 台帳 `/fields`

- 自分の圃場だけを出す。名前と ha。詳細を開くと ㎡ と地図への入口。
- 名前の重複を許す。削除できる。
- 作物・地番・所有者欄は置かない。面積の編集欄は置かない。

### 2.6 地図 `/map`

- 自分の全圃場の形を出す。他人は出さない。
- **道具は段階表示とする。** 一度に全部の保存・取込ボタンを並べない。メニュー（browse）から作業を選び、その作業に必要な操作だけを出す。「やめる」でメニューに戻る。
- メニュー（browse）に出す入口: 塗りをする、手描き、修正、分割、合筆、区画取込、下地。下地種の切替（ready なものだけ）。
- 手描き: 閉じた多角形を描き、名前を付けて POST する。閉じる前は破棄できる。
- 修正: 頂点を動かして PUT する。
- 分割: 1枚を2枚以上の閉じた形にする。API は新しい多角形の配列を受ける。切り方の道具の見た目は定めない。新しい各枚の名前は `仮-` に通し番号を付ける。あとで台帳または地図から直せる。
- 合筆: 2枚以上を選び、残す側を1つ指定する。形は合わせる（離れていれば MultiPolygon でよい）。名前は残す側。他の行は消す。
- 区画取込: GeoJSON ファイル。FeatureCollection / Feature / Geometry を受ける。Polygon と MultiPolygon だけを圃場にする。MultiPolygon は、中の Polygon ごとに1枚とする。名前はプロパティ `name` があれば使い、無ければ `仮-` 通し番号。点・線は飛ばす。
- 下地: 取込と位置調整・保存は下地モードのときだけ出す。
- 塗り、作業名、色分け、ガント、指示は出さない。形だけとする（塗りは工程3）。

### 2.7 仮の名前

その利用者の台帳で `仮-` のあとが数字のものを数え、使っていない番号を付ける。重複してよい本名前とは別に、仮名は一意でなくてよい。

## 3. 処理の規則

### 3.1 所有者

- 圃場と作業場所と下地は、ログイン中の利用者にだけ紐づく。
- 管理者は持たない。招待の取消し（または再招待）では、その利用者の作業場所・下地・圃場・塗りをすべて消す。利用者の行は再利用する（工程1）。

### 3.2 形と面積

- 面積が 0 または計算できない形は保存しない。
- 同じ利用者の圃場が重なってもよい。
- 分割・合筆のとき、工程2には塗りが無いので、塗りの有無は見ない。工程3で、塗りが残っている圃場の分割・合筆を拒否する。

### 3.3 作業場所と下地の順序

1. 作業場所を決める。
2. その範囲の3種を取り込む（全部揃う前でも地図は開ける。無い種は切り替えられない）。
3. 圃場を描く・取り込む。

3種が揃っていなくても、圃場の編集はできる。下地が空中写真で無いときは、ある種を出すか下地なしとする。初期表示の指定は空中写真なので、あればそれを出す。

## 11. 確定した判断

1. **地図の描画部品。** OpenLayers とする。作業場所決定では地理院 XYZ。OSM は使わない。
2. **下地画像の保存先。** 同じマシンのファイル `data/basemaps/` とする。SQLite の中には入れない。
3. **作業場所未設定の初期範囲。** 東経129〜146、北緯26〜46 とする。地理院標準地図で開く。
4. **下地の自動取得。** サーバが範囲限定で地理院タイルを合成する（空中は高ズーム、衛星はランドサット帯）。公式 eMAFF 画像 API が無い場合も同様。筆ポリゴンは手作業の区画取込のみとし、自動では取らない。
