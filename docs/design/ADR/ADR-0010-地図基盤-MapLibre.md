## 1. 背景

圃場境界は認可・検索・作業記録に使う権威データである一方、背景地図・写真・生育画像は交換可能な表示資料である。両者を同じデータ源や利用条件に従わせると、外部サービス停止、規約変更、画像の位置ずれが業務データの正しさへ波及する。

## 2. 決定

- Web地図はリポジトリで固定する`maplibre-gl` 6.3.0を使用する。描画ライブラリ更新は視覚回帰、キーボード操作、CSP、タイル互換性をrelease gateで確認する。
- 圃場境界の正本はPostgreSQL 16＋PostGISのSRID 4326 geometryとする。BFFのRLS適用済みREST APIからGeoJSONを返し、MapLibreへoverlayする。背景地図から境界や面積を逆生成しない。
- 日本のオンライン背景は地理院タイル標準地図を既定、写真を利用者が明示的に切り替える補助layerとする。クライアントが国土地理院からリアルタイム取得し、画面上に出典とリンクを常時表示する。法務承認なしにproxy cache、再配布、事前取得を行わない。
- 高精細写真は圃場境界の描画補助、Sentinel-2等は生育分析用と役割を分ける。撮影日、解像度、雲量、位置精度を表示し、どちらも所有権、農薬適否、法定記録の根拠にしない。
- Google Maps PlatformはPhase 1で採用しない。provider固有の利用制限・課金・offline制約を中核業務へ持ち込まない。
- 外部背景が失敗しても、担当圃場一覧、境界、選択、距離・面積、記録作成は継続する。背景なしをエラーで隠さず表示する。
- CSPは地図style・tileの送信先をallowlist化する。任意URL入力、tile応答中のHTML実行、認証Cookieの外部送信を許さない。

## 3. 選択肢

| 選択肢 | 結論 |
|---|---|
| MapLibre GL JS＋PostGIS | 採用。OSS、WebGLベクトル描画、既存React/PWAと整合 |
| Google Mapsを業務基盤にする | 不採用。offline・再配布・provider lock-inが要件と不整合 |
| Leaflet＋ラスタだけ | 小規模には単純だが、ベクトルstyle・大規模overlayで劣後 |
| 背景画像を圃場境界の正本にする | 不採用。撮影時点・位置精度・規約が権威データへ混入 |

## 4. 帰結と受入条件

- 地理院タイルの出典表示と利用条件の確認を配備台帳・release checklistへ含める。
- 日本以外は国別配備ごとに、法域・利用規約・帰属表示を審査したproviderを別profileで選ぶ。日本profileを無断転用しない。
- MapLibreで担当圃場を表示し、背景停止時にもGeoJSON overlayと一覧操作が成立する統合試験を維持する。
- offline背景はADR-0011の自己生成PMTilesだけを対象とする。本ADRに方式上の未解決事項はない。
