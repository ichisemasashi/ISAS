## 1. 背景・課題（Context）

フロントエンドは、本システムの最大の技術リスク（現場のオフライン利用）とUX目標（KSASより使いやすく）を同時に満たす必要がある。満たすべき要件：

- **現場＝モバイルでオフライン利用**（要求仕様5.1.1）：圏外の圃場で作業日誌・農薬使用基準チェック・在庫出庫・打刻・位置ログを行い、復帰時に同期。オフライン中も**事前警告**（農薬使用基準 F-41）が要る。
- **UX目標**（5.1／4.11）：作業日誌入力30秒、タスク成功率90%、SUS 75。片手・手袋・屋外日光下でも使える。
- **2つの利用文脈**：**現場（スマホ・オフライン・素早い入力）**と**オフィス（PC・大画面・計画/分析/管理）**。
- **地図/GIS**（4.1／ADR-0010）：圃場ポリゴン描画・オフラインタイル。
- **多言語・多地域**（ADR-0015）：全世界の言語、圃場ローカル暦日、通貨/単位。
- **配信＝MITのOSS**（1.3）：運用者が自前ホスト可能な構成。
- **大量データ**：圃場数万・位置ログ多数を端末側に持ち得る（同期＝ADR-0007）。

これらを、**単一コードベースで保守可能**かつ**現場のオフライン要件を破綻させない**形にする。

## 2. 決定（Decision）

**React＋TypeScript の単一コードベースを、PWA を既定として構築する。** モバイル（現場）とデスクトップ（オフィス）を**レスポンシブな単一コードベース**で提供する。**offline-first は「現場の運用サブセット」に限定**し、オフィスの分析/一覧は**オンライン・サーバ集計**とする（A6-M1）。**PWA を既定・ネイティブ（Capacitor）は端末能力が要る場合のオプション**と位置づけ、どこまでをPWAで賄うかは端末能力スパイクS6で確定する（A6-H1）。

> **用語の正確化（A6-H1）**：本ADRは「PWA中心」ではなく「**PWAを既定、ネイティブは能力要件があるときのオプション**」を採る。「純PWAで全要件を満たす」とは主張しない。

### 2.0 適用範囲の二層（A6-M1／M2）

| 層 | 対象 | データの真実源 | オンライン前提 |
|---|---|---|---|
| **現場・運用UI**（offline-first） | 作業日誌・在庫出庫・打刻・位置ログ・**安全基準参照(F-41)** | **端末IndexedDB が真実源**（同期エンジンがIndexedDBを更新） | 不要（圏外可） |
| **オフィス・分析UI**（online） | 計画・一覧・集計・帳票（数万件） | **サーバが真実源**（Queryキャッシュは揮発） | 必要 |

- **読取の真実源をデータ種別ごとに固定**（A6-M2）：運用データ＝IndexedDB、分析データ＝サーバ。UIは自層の真実源のみを読む。二層はコンポーネント/デザインを共有するが、データパスは分離する。

- **言語/型**：**TypeScript**（型安全・大規模保守）。
- **UIライブラリ**：**React**。代替（Vue/Svelte/SolidJS）と比較のうえ採用（A6-L1）：**地図（MapLibreのReactバインディング）・i18n（ICU系）・オフライン/Query（TanStack）・Capacitor連携のエコシステム成熟と採用実績**が最も厚く、多人数・長期保守の人材確保にも有利。Svelte/Solidはバンドル/性能で魅力だがライブラリ成熟でReactに劣後、Vueは有力だが本要件での優位が決定的でない。具体のコンポーネント体系は **ADR-0016（UXデザインシステム）** で確定。
- **レンダリング＝クライアントサイドSPA**：オフライン起動が必須のため、**アプリシェルを端末にキャッシュして起動をサーバ非依存にする**。SSR/SSGは初期表示に有利だが、**オフライン起動・端末ローカルデータ駆動**の要件と噛み合わないため主軸にしない（マーケ用公開ページ等が必要なら別建て）。
- **PWA**：
  - **Service Worker**（**Workbox** で生成）＝アプリシェル（HTML/JS/CSS）と静的資産の**プリキャッシュ**、実行時キャッシュ戦略（地図タイル等）。
  - **インストール可能**（ホーム画面追加）。オフラインでも起動・入力可能。
  - **更新戦略**：SWの更新は**明示的な更新通知＋リロード**（勝手に画面が変わらない）。**リロードは「未確定入力なし」の安全なタイミングに限る／未確定入力は下書き（④）へ退避してからリロード**（A6-L3）。破壊的スキーマ変更時のバージョン整合はADR-0007と連携。
- **オフラインファーストのデータ層（現場・運用UI）**：
  - 端末ローカルの一次ストア＝**IndexedDB**（作業日誌・在庫イベント・位置ログ・マスタキャッシュ・**農薬使用基準の事前キャッシュ**）。**現場・運用UIは IndexedDB を真実源として読む**（オンライン/オフラインでコードパスを分けない）。オフィス・分析UIはこの限りでない（§2.0）。
  - サーバとの**差分同期は ADR-0007** に委譲。フロントは「ローカルに書く→同期エンジンが送る」を前提に設計（楽観的更新）。冪等キー＝**UUIDv7**（データモデル設計書§5：`event_uuid`）をクライアントで採番し、`event_ts` も `uuidv7_time` 相当をクライアントで算出して送る（スパイクS1で確定した経路）。
  - **未同期データの保護（A6-H3）**：**「未同期の書込は消えてはいけない」を不変条件**とする。(a) `navigator.storage.persist()` を要求し**インストールPWA/ネイティブで永続性を確保**（各OSの実効性はS6で実測）、(b) **接続が一瞬でも回復したら未同期キューを最優先で送る**、(c) **未同期件数・最終同期時刻をUIで常時可視化**し長期未同期を警告（F-D系）、(d) 冪等（UUIDv7）は**重複を防ぐが消失は防げない**ため、エビクション耐性が不足する運用者はネイティブ（下記）へ。保持責務はADR-0007と接合。
  - **安全criticalデータの鮮度契約（A6-H2）**：F-41の安全/法令基準キャッシュは**版・有効期限・最終同期時刻**を持つ。**期限切れ/長期未同期は「基準が古い可能性」を明示し、判定をfail-safe側**（警告を強める／確定を保留し要オンライン再確認）にする。**登録失効・回収は復帰時に最優先同期**。オフライン警告は**参考**とし、**最終確定はオンライン再検証を要する機微操作**と位置づける（ADR-0015「安全ラベルはレビュー済みのみ」と整合）。
- **地図**：**MapLibre GL JS**（ADR-0010）。オフラインタイルは対象国分＋端末は圃場周辺のみ（ADR-0011）。
- **国際化**：**ICU MessageFormat（CLDR）** ベースのi18n（ADR-0015）。日付は「時点=UTC表示変換／暦日=圃場TZ」をフロントでも遵守。
- **状態管理（3層・真実源はデータ種別で固定）**：**①分析データ＝サーバ状態（TanStack Query 等・揮発キャッシュ）**、**②運用データ＝永続ローカル（IndexedDB・真実源、同期エンジン経由で更新）**、**③UI状態＝軽量ストア**。§2.0の二層に対応させ、①と②を混在させない（A6-M2）。
- **位置ログの取得方式（A6-M3）**：**打刻（F-74）連動を既定**（作業開始打刻→位置ログON、休憩/終了打刻→OFF）で「作業中ON/休憩中OFF」を実現。取得は**適応間隔**（移動時は密・静止時は疎）でバッテリ/データ量を抑制。バッテリ・IndexedDB書込量の目安はS6で実測。ネイティブ時はバックグラウンド最適化APIを利用。
- **バンドル分割（A6-M4）**：**文脈単位のコード分割（現場・運用UI／オフィス・分析UI）**と、**地図・i18n・分析の遅延読込**。現場UIは最小構成で起動し、初期JS上限＝**性能予算**を定義・計測（ADR-0020）。
- **ビルド/ツール**：**Vite**（高速・PWAプラグイン）。E2E/単体テストの土台も用意（ADR-0021）。
- **アクセシビリティ/現場UX**：大きいタップ標的・高コントラスト・片手操作・オフライン状態の明示（F-D系）。
- **native は「能力オプション」＋配布の条件分岐（A6-H1）**：**iOS Safari の PWA 制約**（バックグラウンド位置取得が実質不可、ストレージのエビクション、Background Sync 非対応、プッシュ制約）により、**F-08a の継続位置ログ等がブラウザPWAだけでは満たせない可能性**がある。対応を**配布経路とセット**で分岐する：
  - **(a) PWAで賄える範囲**（オフィス全般＋現場のフォアグラウンド操作）＝**運用者が自前ホストするPWA**（MIT・1.3に適合）。
  - **(b) バックグラウンド位置ログ等ネイティブ必須機能**が要る運用者向け＝**同一Reactコードを Capacitor で薄くネイティブ化**。ただし**ネイティブ配布は App Store/Play・コード署名・開発者登録が必要で「サーバに置くだけ」では配れない**。よって**公式が署名済みアプリを別チャネルで提供 or セルフビルド手順を提供 or MDM/エンタープライズ配布**、という配布形態を**S6で必須範囲を確定してから**選ぶ。
  - **単一コードベースは維持**（能力差はプラグイン層で吸収）。「PWAで全部」とは主張しない。

## 3. 検討した選択肢（Options）

| 観点 | 選択肢 | 評価 |
|---|---|---|
| 配布形態 | **PWA既定＋ネイティブは能力オプション（採用）** ／ フルネイティブ（iOS/Android別） ／ React Native | ◎ PWAは単一コード・自前ホスト（MIT）・即時配信。ただし**ネイティブが要る範囲は自前ホストで配れない**ため配布を条件分岐（A6-H1）。フルネイティブは2文脈×2OSで工数肥大。RNはオフィスWebと二重管理 |
| ラッパ | **Capacitor（必要時のみ・採用）** ／ ラッパなし ／ 最初からRN | ◎ 同一Reactコードを必要時のみネイティブ化。ラッパ無しだとiOS制約でF-08aが破綻。ただしネイティブ配布は署名/審査が要る（A6-H1）。最初からRNはオフィスWebと乖離 |
| レンダリング | **CSR/SPA（採用）** ／ SSR（Next.js等） | ◎ オフライン起動・ローカルデータ駆動にはCSRが自然。SSRはサーバ依存で圏外起動と相性が悪い |
| 言語 | **TypeScript（採用）** ／ JavaScript | ◎ 大規模・多人数・長期保守で型が効く |
| ローカル永続 | **IndexedDB（採用）** ／ localStorage ／ SQLite(wasm) | ◎ IndexedDBは大容量・構造化・非同期。localStorageは容量/同期API不足。SQLite-wasmは有力だがまず標準のIndexedDBで、必要ならADR-0007で再評価 |
| 状態 | **層分離（サーバ/永続/UI）（採用）** ／ 単一グローバルストアに全部 | ◎ オフライン同期を単一ストアに混ぜると複雑化。関心を分離 |

**却下理由**：フルネイティブ2OSは工数と二重保守。純SSRはオフライン起動に不向き。ラッパ無しPWAはiOSの位置ログ制約で現場要件（F-08a）を落とす。

## 4. 影響・帰結（Consequences）

**良い影響**
- 単一コードベースで現場/オフィス両文脈をカバー。**PWAで賄える範囲は自前ホスト（MIT）に適合**。
- 現場・運用UIの一貫したデータパス（IndexedDB真実源）で、圏外/圏内のコード分岐を排除しバグ面を縮小。分析UIはオンライン・サーバ集計に分離し過剰なローカルミラーを回避。
- スパイクS1で確定した冪等（UUIDv7＋CHECK）とフロントの採番が一致し、同期の芯がぶれない。

**悪い影響・制約**
- **配布の二経路化（A6-H1）**：ネイティブ必須機能が要る運用者には自前ホストPWAだけでは足りず、署名済みネイティブ配布（別チャネル）が要る。OSSの提供形態が二経路になる。
- **安全データの鮮度管理コスト（A6-H2）**：オフライン安全警告にfail-safe・優先同期・版管理が要る（実装/運用の負荷）。ただし安全側に倒すのは必須。
- **未同期保護の運用（A6-H3）**：persist()・優先同期・未同期可視化が要り、エビクション耐性が不足する運用者はネイティブが要る。
- **オフライン同期の複雑性**はADR-0007へ集約されるが、楽観的更新・競合表示（5.1.1）はUX（ADR-0016）と密結合。

## 5. 未解決事項（設計/スパイクで詰める）

- **端末能力スパイク（新規 S6）**：iOS/Android の PWA で **バックグラウンド位置取得・Background Sync・ストレージ永続（persist()）・エビクション閾値・Web Push** を実測し、**PWAで賄える範囲とネイティブ（Capacitor）が要る範囲**、および**それに応じた配布形態（自前ホストPWA／署名済みネイティブ別チャネル）**を確定する（A6-H1/H3・F-08a/5.1.1直結）。
- **対応ブラウザ/OS下限マトリクス（A6-L2）**：iOS Safari最低版・Android・デスクトップ各ブラウザの下限を定義し、Background Sync/persist()/Web Push の可否を版ごとに整理（S6の実測対象）。
- 安全基準キャッシュの**版・失効・優先同期**の具体（A6-H2・ADR-0007/0015と一体）。
- IndexedDB のデータ量・クエリ性能（数万件のローカル圃場/イベント）の実測（ADR-0007のローカルスキーマと一体）。
- 楽観的更新と競合表示（管理者裁定＝5.1.1 M-5）のUXパターン（ADR-0016）。
- SW更新とローカルスキーマ・マイグレーションの整合（ADR-0007）。
- コンポーネント/デザイントークンの具体（ADR-0016）。
- 認証トークンのフロント保持方式（メモリ/Cookie・オフライン時の扱い）（ADR-0009）。
