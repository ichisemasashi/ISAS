## 指摘と処置

| ID | 重大度 | 攻撃／破綻 | 処置 |
|---|---|---|---|
| A21-H1 | High | stagingで検証後にproduction用として再buildすると、別依存・別source・侵害済みrunnerのartifactを無検証で出せる | review commitから一度だけbuildし、署名digestを環境間promote。再build禁止 |
| A21-H2 | High | application rollback可能でもcontract migrationで列を消した後は旧appが壊れ、down migrationはdataを戻せない | expand/migrate/観測/contract、N/N-1 contract test、14日offline client確認、原則roll-forward |
| A21-H3 | High | PWA rollbackでcacheをpurgeすると、server障害の是正が未同期日誌のdata lossを起こす | SW待機・未同期確認、旧新asset保持、kill switchはnetwork停止のみでoutbox purge禁止 |
| A21-M1 | Medium | 公開DTOで内部modelのfieldを自動serializeすると、新規PIIがtestなしで公開される | 公開field allowlistとの完全一致contract test。新fieldは既定非公開 |
| A21-M2 | Medium | flaky testを再実行passで隠すと、安全raceや時間依存障害がreleaseへ混入する | 初回失敗を保持。安全/RLS/migration/PWA/SLOは隔離不可、その他もowner＋期限必須 |
| A21-M3 | Medium | canaryをtenant単位の別security設定にすると、特定tenantだけRLSや農薬安全が異なる実験になる | 同一security不変条件でinstance割合を段階化。不可逆業務だけ明示opt-in＋監査 |
| A21-M4 | Medium | 合成試験だけで低traffic canaryを進めると実payload/tenant分布の欠陥を見逃す | 合成と実trafficを分離表示し、event数／時間の長い方を観測。低trafficの限界を承認に明示 |
| A21-M5 | Medium | PR runnerへproduction secretを渡すとforkや依存scriptから持出せる | build/testは短寿命・最小権限、production credentialなし。deploy identityを分離 |
| A21-L1 | Low | feature flagが残り続けると組合せ爆発と非再現状態を生む | owner、期限、削除条件、scope、auditを必須化。security迂回禁止 |

## 収束確認

- **test範囲**：unit／contract／PG16+PostGIS／RLS構造／E2E／PWA／WCAG／security／supply chain／SLO／DR／S6/S9／実UTをrelease gateに含めた。
- **offline互換**：14日端末、N/N-1、quarantine、cursor単調性、同一idempotency結果、SW rollbackを一つのrelease契約にした。
- **配備・監視**：ADR-0019の同一digest・recovery set・poolと、ADR-0020のerror budget・`no_data`・P0/WAL即時停止をpromotion条件へ接続した。
- **例外統制**：RLS越境、data loss、農薬安全、Critical/High脆弱性、未処置Mediumはwaiver不可。緊急hotfixもartifact identityと最低gateを省略しない。

よって**ADR-0021 v1を採用（クローズ）とする**。現実装にCI/CDがないことは未達として残し、設計文書の採用をrelease済みと誤表示しない。
