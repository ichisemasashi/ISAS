## 1. 決定

- Phase 1のoffline背景は、OpenStreetMapの対象国extractをPlanetilerの固定版・固定profileでMapLibre互換ベクトルPMTilesへ生成する。生成物、style、font、spriteのversion・SHA-256・入力日時・ライセンスをmanifestへ記録する。
- 国全体のarchiveは日本regionのprivate S3へversion付きで置く。端末へ国全体を配らず、担当圃場のbbox＋2 km、zoom 8〜16の必要rangeだけをsame-origin BFF経由で取得する。BFFはRLSで担当割当を再検証し、短期URLを公開共有しない。
- 端末パックは`tenant_id`、`user_id`、`assignment_version`、`tileset_version`、bbox、zoom、hash、bytes、作成・期限を持つ。既定上限250 MiB／installation、Wi-Fi時の明示取得、差分更新、LRU削除とする。上限変更は配備profileで管理する。
- 圃場GeoJSON、outbox、安全マスタを背景tileより優先する。容量不足時は背景だけを削除し、未同期記録を削除しない。tenant切替・権限失効時は対象パックを即時に読取不可として削除queueへ入れる。
- 画面に「© OpenStreetMap contributors」とODbLへの導線を常時表示する。Planetiler、OpenMapTiles profile、style、font、spriteを含むNOTICEとSBOMを生成し、それぞれの帰属・share-alike条件を守る。
- 地理院標準地図・写真はoffline packへ含めない。衛星写真もPhase 1ではoffline保存しない。
- pack生成失敗、hash不一致、期限切れでは古い背景を「最新」と偽装せず、圃場境界のみで継続する。端末側は取得完了と検証成功後にmanifestを原子的に切り替える。

## 2. 選択肢

| 選択肢 | 結論 |
|---|---|
| OSM→Planetiler→PMTilesを法域内配信 | 採用。国別生成、HTTP range、版固定、offline再利用を管理可能 |
| 地理院タイルをそのまま事前取得 | 不採用。リアルタイム利用と複製・再配布を分離できない |
| 端末へ日本全体を配布 | 不採用。容量・更新・漏えい範囲が過大 |
| online背景だけ | 不採用。F-09aと圏外現場を満たさない |

## 3. 運用・受入条件

1. build jobは入力・tool・profileを固定し、hash、NOTICE、SBOM、coverageを出す。変更時はsample圃場の視覚差分と欠損を承認する。
2. 取得APIは本人の担当圃場外rangeを拒否し、tenant切替、失効、assignment縮小を試験する。
3. 250 MiB不足時は必要圃場・zoomを利用者に示し、無言で途中成功にしない。
4. 圏外再起動後に担当圃場の背景と境界が表示され、期限・未同期状態が区別できることをE2Eで確認する。

private S3、artifact公開／read-back、same-origin BFF Range認可、端末のbbox tile抽出・hash検証・原子的切替・LRU／期限処理は2026-08-15に実装済みである。実日本PMTiles／NOTICE／SBOMの生成・AWS staging公開と実端末E2Eはrelease gateとして残るが、方式と製品選定に未解決事項はない。
