## 1. 決定

- ISASが独自に作成するsource codeとdocumentationはrepository rootのMIT License（SPDX `MIT`）で配布する。配布物の全体または主要部分にcopyright noticeとpermission noticeを同梱する。
- MITは第三者component、font、icon、地図、衛星画像、OSM database、利用者データへ上書き適用しない。それぞれのlicense、帰属、再配布、share-alike、利用規約を`THIRD_PARTY_NOTICES`、SBOM、地図UI、配備台帳で維持する。
- release artifactはSPDXまたはCycloneDX SBOM、source revision、dependency lockfile、OCI digest、license report、provenance attestationを持つ。unknown license、禁止license、NOTICE欠落、source offer等の条件未処置をrelease blockerとする。
- Phase 1の直接依存はpermissive licenseを原則とする。AGPL、SSPL、Commons Clause、source-available、用途制限付きdataを新規採用する場合は、配布・network利用への影響を法務確認した個別ADRなしにmergeしない。
- service運用者は、個人情報、農薬・労務・税務記録、地図利用、輸出管理、契約、可用性について、自身の法域・提供形態に応じて適法性を判断する。MITの無保証条項は法令・契約上の義務を免除しない。
- 利用者が投入した業務データの権利をISASのMITへ移転しない。export・削除・保持は契約と法令に従う。
- 外部contributionは、contributorが権利を有し、repositoryのMIT条件で提供できることをPRで表明する。第三者codeの無断copyを受け入れない。

## 2. 選択肢

| 選択肢 | 結論 |
|---|---|
| MIT | 採用。既存LICENSE・要求と一致し、商用／自己hostを妨げない |
| Apache-2.0へ変更 | patent条項は明確だが、既存決定を変える必要性がない |
| AGPL | service改変公開を促せるが、要求する利用自由度と不整合 |
| proprietary | OSS配布要件に反する |

## 3. 受入条件

release pipelineでSBOM・license report・NOTICE・attestationを生成し、地図帰属をE2Eで確認する。自動化の実装はrelease残作業だが、ライセンス方式の未解決事項はない。本ADRは法的助言の代替ではなく、例外採用時は運用者が資格ある専門家の確認を得る。
