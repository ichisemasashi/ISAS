## 1. ADRの運用ルール

- **1決定＝1ファイル**。ファイル名は `ADR-0001-<スラッグ>.md`。
- **ステータス**：`提案中` → `承認` →（必要なら）`廃止`／`置換（ADR-XXXXへ）`。
- **記載項目（テンプレート）**：
  1. タイトル／ステータス／日付／関連（要求仕様の該当箇所・関連ADR）
  2. **背景・課題（Context）**：なぜ決める必要があるか
  3. **決定（Decision）**：何を選んだか
  4. **検討した選択肢（Options）**：比較・却下理由
  5. **influence・帰結（Consequences）**：良い/悪い影響、以降に生じる制約
  6. **未解決事項**：この決定に紐づき設計フェーズで詰める点（9.1へ）
- **由来の区別**：
  - 【確定済み】＝要求仕様9章で方向性が確定 → ADRは根拠・代替案・帰結を正式記録（追認）。
  - 【要裁定】＝要求仕様では「たたき台/選択肢」止まり → ADRで初めて確定する。

## 3. 起票の推奨順序

「他の設計が乗る土台」から書く。**P0の6本**を最初に確定させる：

1. **ADR-0001 マルチテナント/RLS**（権限・データ分離の根幹）
2. **ADR-0002 配備モデル（1DB=1国）**（データ所在・システム境界）
3. **ADR-0003 データライフサイクル（追記型/論理削除/版履歴/監査）**（不変性方針）
4. **ADR-0004 DB（PostgreSQL+PostGIS）**（中核ストレージ）
5. **ADR-0005 権限モデル（RBAC+メンバーシップ+本人起点横断）**（ADR-0001の権限面）
6. **ADR-0006 フロント構成（React+PWA）** と **ADR-0007 オフライン同期方式**（現場UX・最大の技術リスク）
7. **ADR-0015 国際化基盤**（Phase 1から組み込むため早期に）

> ADR-0001〜0005＋0015 が固まれば、**M3（データモデル設計）**に着手できる。ADR-0006/0007 は**オフライン同期スパイク**の前提となる。

> **次アクション**（**第9回＝独立レビュー ＋ PostgreSQL実挙動検証の結果により全面組み替え**）：
> **前提**：2つの独立レビューが**独立に同じ穴を指摘した3件**（IND3-H3↔PG-M3 restrictive の WITH CHECK／IND3-H1↔PG-H5 ブートストラップの自己矛盾／IND3-M6↔PG-H4 ビューの評価主体）は**確度が最も高い**ので最優先。
> 1. ~~**裁定（ロール別権限をどの層で強制するか）**~~ → **(a) を採用し反映済み**（ADR-0001 v15 §2.9／ADR-0005 v7 §2.6-2.7／データモデル v8 §4）。**権限を `app.caps`／`app.employer_subject_users` で表現し、絞りをすべて restrictive に集約**（permissive は `USING(true)` 固定）。**IND3-H3（WITH CHECK）と IND3-H4（雇用主横断）も同時に処置**。**RLS が守らない範囲（操作の可否＝アプリ層）も明記**した。**PG-H1（セッション変数の正規化）も同時に処置し実測で検証**。
> 2. **PG-H1（「未設定は全拒否」が成立しない）**：述語を `COALESCE(NULLIF(current_setting(...), ''), '{}')::uuid[]` 等の正規化形に改め、**「未設定＝0行／空・不正＝例外」**と正しく書き直す。**注入漏れが例外になる**ことを前提に、握り潰し実装（＝フェイルオープンへの反転）を禁じる規約を置く。
> 3. **PG-H6（FORCE RLS の非伝播）**：§5 の「伝播する」を撤回。**全パーティションに個別設定するか、子へ一切 GRANT しない**。**パーティション自動作成ジョブに RLS 設定を必須手順として組み込む**。検査に「子に通常ロールの権限が無いこと」を追加。
> 4. **IND3-H3／PG-M3（WITH CHECK）**：述語形を「USING 形」「WITH CHECK 形」の**対**にする。検査に「restrictive に WITH CHECK が明示されていること」「`tenant_id IS NULL` を許す WITH CHECK が無いこと」、振る舞いテストに**書込側**（他テナント名義の INSERT／行移送の拒否）を追加。
> 5. **IND3-H1／PG-H5（ブートストラップ）**：`auth_role` が直接 SELECT する形を正とし「テーブル権限ゼロ」を「membership の SELECT のみ」に緩めるか、**述語のキーを専用の関数所有者ロールにする**か。ADR-0001 §2/§5 と ADR-0002 §2/§4 を**同時に**直す。
> 6. **IND3-M6／PG-H4（ビュー）**：**`security_invoker`（PG15+）を設計規約化**し、検査に追加。**最低要求 PostgreSQL バージョンを ADR-0004 に明記**（実質 PG15 に固定される）。
> 7. **IND3-H5（`event_ts` が端末時計由来）**：冪等（再送で同値）と物理配置（サーバ権威）を**別機構に分離**。DEFAULT パーティション（または受理保留表）を定義し「**どんな時刻でも受理はできる**」を不変条件にする。
> 8. **IND3-H4（雇用主横断）**：要求#18 を改訂するか、述語形に第6形（`app.employer_subject_users`）を新設するか裁定。
