## 1. ADRの運用ルール

- **1決定＝1ファイル**。ファイル名は `ADR-0001-<スラッグ>.md`。
- **ステータス**：`提案中` → `承認` →（必要なら）`廃止`／`置換（ADR-XXXXへ）`。
- **記載項目（テンプレート）**：
  1. タイトル／ステータス／日付／関連（要求仕様の該当箇所・関連ADR）
  2. **背景・課題（Context）**：なぜ決める必要があるか
  3. **決定（Decision）**：何を選んだか
  4. **検討した選択肢（Options）**：比較・却下理由
  5. **influence・帰結（Consequences）**：良い/悪い影響、以降に生じる制約
  6. **未解決事項**：この決定に紐づき設計フェーズで詰める点（9.1へ）
- **由来の区別**：
  - 【確定済み】＝要求仕様9章で方向性が確定 → ADRは根拠・代替案・帰結を正式記録（追認）。
  - 【要裁定】＝要求仕様では「たたき台/選択肢」止まり → ADRで初めて確定する。

## 3. 起票の推奨順序

「他の設計が乗る土台」から書く。**P0の6本**を最初に確定させる：

1. **ADR-0001 マルチテナント/RLS**（権限・データ分離の根幹）
2. **ADR-0002 配備モデル（1DB=1国）**（データ所在・システム境界）
3. **ADR-0003 データライフサイクル（追記型/論理削除/版履歴/監査）**（不変性方針）
4. **ADR-0004 DB（PostgreSQL+PostGIS）**（中核ストレージ）
5. **ADR-0005 権限モデル（RBAC+メンバーシップ+本人起点横断）**（ADR-0001の権限面）
6. **ADR-0006 フロント構成（React+PWA）** と **ADR-0007 オフライン同期方式**（現場UX・最大の技術リスク）
7. **ADR-0015 国際化基盤**（Phase 1から組み込むため早期に）

> ADR-0001〜0005＋0015 が固まれば、**M3（データモデル設計）**に着手できる。ADR-0006/0007 は**オフライン同期スパイク**の前提となる。
