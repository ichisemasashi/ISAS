## 1. 目標と設計原則

ISASのUXは「機能を探す画面」ではなく、**今日の仕事を安全に終える画面**を起点にする。高齢者・ITに不慣れな作業員・技能実習生が、屋外・手袋・通信不安定という条件でも、説明なしに主要タスクを完了できることを目指す。

1. **今日から始める**：初期画面は機能一覧でなく、担当作業・打刻・要安全確認を時間順に示す。
2. **次の一手を一つにする**：カードごとの主要操作は原則1つ。安全確認が必要なら通常の「記録する」より先に示す。
3. **端末保存とサーバ同期を分けて伝える**：「保存できた」と「同期できた」を混同せず、オンライン状態と未同期件数を全画面で表示する。
4. **入力済みから直す**：打刻、作業指示、前回値、テンプレートで下書きを作り、利用者は差分だけ直す。
5. **食品安全は摩擦を許容する**：農薬警告は色だけに頼らず、理由・次の行動・明示確認を要求する。安全確認を入力短縮より優先する。
6. **消さずに回復する**：下書きはUndo、可逆データはゴミ箱/版履歴、法定・追記型記録は訂正イベントで回復する。
7. **屋外で読める**：高コントラスト、16pxを基準とする本文、太い見出し、48px以上の主要操作、色＋形＋ラベルを併用する。
8. **言葉を短くする**：やさしい日本語を既定にし、アイコン単独操作を避ける。初期提供言語は日本語・英語、構造はRTLへ拡張可能にする。

|---|---|---|---|

## 3. 情報アーキテクチャ

### 3.1 ナビゲーション

モバイルは親指到達域に4項目の下部ナビ、幅761px以上は同じ順序の左ナビを使う。現在地は背景・アイコン・ラベル・`aria-current`で示す。

```text
ISAS
├── 今日（ホーム）
│   ├── 今日の打刻
│   ├── 今日の作業
│   ├── 要安全確認
│   └── すぐに記録
├── 記録
│   ├── 作業日誌
│   ├── 農薬記録
│   └── 未同期・差し戻し
├── 圃場
│   ├── 担当圃場一覧
│   └── 地図（PostGIS/MapLibre）
└── その他
    ├── 表示テーマ・言語
    ├── 端末/同期状態
    ├── CSV取込（列マッピング→検査→確定）
    ├── CSV出力（期間指定）
    └── アカウント
```

高度な横断検索、ナビ編集、分析ダッシュボードはPhase 2へ送る。位置ログは消費先F-73と同時にPhase 2で導入し、Phase 1では収集しない。

### 3.2 主要タスクフロー

#### 作業確認 → 打刻 → 日誌

```text
今日の作業を開く
  → 次の作業と安全状態を確認
  → 「作業を始める」
  → 作業カードの「記録する」
  → 打刻・指示・前回値入りの下書きを確認
  → 端末へ保存（圏外でも完了）
  → オンライン復帰後に同期
```

目標は作業確認3タップ以内、日誌30秒以内。日誌は圃場・作業・開始/終了を事前入力し、自由入力は任意メモだけにする。

#### 農薬記録

```text
要安全確認カード
  → 圃場・作物・薬剤・量を入力/確認
  → 端末キャッシュで適用作物・倍率・回数・収穫前日数を判定
  ├─ 適合：基準内の根拠を表示 → 記録
  └─ 警告：理由と次の行動を表示 → 履歴確認を明示 → 記録/中止
```

警告は隠さず、オフラインでも基準版・更新日時を表示する。鮮度期限切れ時のfail-safe詳細はADR-0006に従う。

## 4. デザイントークン

実装上の正本は`apps/web/src/styles.css`のCSSカスタムプロパティとし、値の変更は本表と同時に更新する。

### 4.1 色

| 用途 | Token | 値 | 規則 |
|---|---|---:|---|
| ブランド/主要操作 | `forest-800` | `#174F3A` | 白文字との組合せ。装飾だけでなくラベルを併記 |
| 深い背景 | `forest-900` | `#0D3327` | デスクトップナビ、通知 |
| 強調 | `leaf-400` | `#DCE94F` | 主要打刻。本文文字色には使わない |
| 警告 | `amber-600` | `#A84F11` | 警告アイコン＋見出し＋説明と併用 |
| 情報 | `blue-600` | `#17658B` | 圃場/情報状態 |
| 本文 | `ink` | `#17211C` | 通常テーマの本文 |
| 背景 | `canvas` | `#F4F1E8` | 屋外で白面積の眩しさを抑える |
| 面 | `paper` | `#FFFEFA` | カード・フォーム |

テーマは屋外向け、ダーク、高コントラストの3種。重要状態は色のみで表現せず、接続点・アイコン・「オフライン」等の文字を必ず併用する。

### 4.2 タイポグラフィ・余白・形

- 書体：`Noto Sans JP`を優先し、OS日本語ゴシックへフォールバック。外部フォント取得を必須にしない。
- 本文：16px相当を基準。補助情報は11〜13pxだが主要判断には使わない。
- 見出し：27〜40px（h1）、22px（h2）、16px以上（カード見出し）。
- 余白：4px基準、主系列は8/12/16/24/32/48px。
- タッチ対象：主要操作48px以上、補助操作44px以上。隣接操作間8px以上。
- 角丸：12px（入力）、18px（カード）、26px（主要面）。角丸だけで状態を表現しない。

## 5. コンポーネントと状態

| コンポーネント | 用途 | 必須状態/挙動 |
|---|---|---|
| SystemStatus | 接続・同期の常時表示 | online/offline、未同期件数、同期中、差し戻し |
| PunchCard | 作業/休憩の追記イベント | 未開始、作業中、休憩中。現在状態ごとに次の操作だけ表示 |
| TaskCard | 今日の指示 | 時刻、圃場、作物、作業、安全状態、主要操作1つ |
| RecordForm | 日誌・農薬記録 | 自動保存、必須/任意の明示、端末保存、送信状態 |
| SafetyResult | 農薬基準判定 | 適合、警告、期限切れ、判定不能。理由と次アクションを含む |
| Toast | 操作結果 | 結果＋次の状態を平易な文で示し、閉じられる |
| Theme/Locale | 表示設定 | 屋外/ダーク/高コントラスト、日本語/英語 |

### 5.1 保存と同期の文言

| 状態 | 表示例 | 利用者が取る行動 |
|---|---|---|
| 下書き保存済み | 「下書きを端末に保存しました」 | なし。アプリを閉じてもよい |
| 未同期 | 「未同期 2件」 | 通常はなし。通信回復を待つ |
| オフライン記録完了 | 「端末に保存しました。電波が戻ると自動で同期します」 | なし |
| 差し戻し | 「記録を送れませんでした。権限を確認してください」 | 理由別アクションへ進む |
| 農薬基準期限切れ | 「基準データが古いため安全を確認できません」 | 更新または責任者へ確認 |

## 6. アクセシビリティと国際化

- WCAG 2.1 AAを目標とし、キーボードフォーカスを3px輪郭で可視化する。
- `main`、`nav`、`header`、見出し階層、fieldset/legendを使い、スクリーンリーダーで構造を辿れるようにする。
- 動的な同期状態・保存結果は`aria-live`/`role=status`、安全警告は`role=alert`を使う。
- アイコンだけのボタンはアクセシブル名を持たせ、主要ナビはアイコン＋ラベルにする。
- OSの文字拡大、200%ズーム、320px幅で横スクロールなしを確認する。
- 初期翻訳は日英。文言はコンポーネントから翻訳辞書へ段階移行し、論理方向プロパティでRTLを支える。
- 動きは`prefers-reduced-motion`を尊重する。操作結果をアニメーションだけで示さない。

## 7. 実装境界

### 7.1 今回実装した縦切り

- React 19＋TypeScript＋ViteのPWAシェル、manifest、Service Worker。
- レスポンシブな左/下ナビと、屋外・ダーク・高コントラストテーマ。
- 今日の作業、打刻状態機械、当日作業時間の簡易表示。
- 日誌の前回値/打刻補完、下書き保存、IndexedDB outbox。
- 管理者の作業指示発行・担当者再割当、担当者の指示一覧、日誌の承認・理由付き差し戻し・訂正再提出。
- テンプレート／前回値のオフラインcache、写真のIndexedDB保持と日誌受理後の冪等アップロード。
- 担当圃場別の農薬マスタ／使用履歴cache、版・有効期限・失効日の鮮度表示、適用作物・希釈・使用回数・収穫前日数のオフライン判定、警告時の明示確認。
- 追記型の在庫入出庫、マイナス在庫の管理者通知、実棚数量から差分を作る棚卸し調整導線。
- online/offline、未同期件数、保存結果の常時フィードバック。
- ADR-0009に従う同一オリジンBFFクライアント契約、タブ単位context、組織切替、認証状態表示。
- outboxへのtenant・認可Snapshot・membership版の保存と、オフライン猶予後の読取専用／ロック縮退。
- 認証/API応答とAuthorization付き要求をService Workerキャッシュから除外。
- 主要導線の自動テスト。

## 8. ユーザビリティテスト計画

### 8.1 対象者

初回は6〜9名を目安に、現場作業員2〜3名、高齢作業員2〜3名、技能実習生2〜3名を含める。管理者は別セッションで2〜3名。スマホは実際に使うiPhone/Android、可能なら屋外・手袋・機内モードで実施する。

### 8.2 タスクと合格基準

| # | シナリオ | 観測指標 | 初期合格基準 |
|---|---|---|---|
| UT-01 | 今日の最初の作業を確認する | 成功、タップ数、迷い | 成功率90%以上、3タップ以内 |
| UT-02 | 作業開始→休憩→再開→終了 | 成功、誤打刻、回復 | 成功率90%以上、状態を説明できる |
| UT-03 | 打刻済み状態から日誌を記録 | 時間、入力数、エラー | 30秒以内を目標 |
| UT-04 | 農薬を選び安全基準を確認して記録 | 時間、警告理解、見落とし | 60秒以内、警告見落とし0 |
| UT-05 | 圏外で日誌を保存し、未同期状態を説明 | 保存成功、状態理解 | 全員が「端末保存済み・未同期」を区別 |
| UT-06 | 文字拡大/高コントラストへ変更 | 成功、可読性 | 補助なしで変更できる |

セッション後にSUSを測り75以上を目標とする。成功/失敗だけでなく、最初の躊躇、戻る操作、誤タップ、発話、介入回数を記録する。

### 8.3 実施手順と判定

1. 目的説明と同意。機能説明はしない。
2. Think-aloudでUT-01〜06を実施。進行役は行動を誘導しない。
3. タスク時間・タップ・エラー・介入を記録し、終了後SUSと半構造化インタビューを行う。
4. 食品安全の誤解、記録消失の誤認、タスク完遂不能はSeverity 1としてMVPリリース前に必ず修正する。
5. 改善後に同一条件で再テストし、主要タスク成功率90%・SUS75・時間目標が収束するまで反復する。
