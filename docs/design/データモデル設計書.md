## 1. 設計原則（P0からの継承）

このデータモデルは以下を貫く（各ADRの決定）：

- **テナント分離**：全テナント固有テーブルに `tenant_id`、RLS（USING＋WITH CHECK・FORCE RLS・フェイルクローズ）（ADR-0001）。
- **テーブル4分類**：①テナント固有／②システム共有／③共有＋テナント上書き／④ユーザー所有（ADR-0001 v7）。
- **不変性3層**：①イベント（①-a法定/①-b PII）／②可逆確定（deleted_at＋版履歴）／③下書き（ADR-0003）。
- **型の区別**：時点＝`timestamptz`（UTC）／暦日＝`date`（圃場ローカル・圃場TZ基準）（ADR-0015）。
- **PK＝UUID（非連番）**、FKは同一テナント内（ADR-0001 A1e-L1/L2）。
- **時系列は時間主軸パーティション＋サブパーティション**（ADR-0004）。
- **単位＝原値権威＋正規化導出**、金額＝同一通貨内集計（ADR-0015）。

## 2. 論理ERD（概念→論理）

```
System/国(1DB=1法域)
  └─* Tenant/Group ─* Organization ─┐
                                     ├─* Field(圃場) ─* Cropping(作付) ─* WorkOrder(作業指示)
User *─┬─* Membership(role,perm,scope) ┘                                   │
       ├─* Punch(打刻)                                                     ├─* WorkLog(作業日誌)  ← 複合(①-a農薬記録/①-b PII)
       ├─* LaborSummary(労務サマリ)                                        │      └─* PesticideRecord(農薬使用記録①-a)
       └─* Draft(下書き④)                                                 │      └─* Photo(写真①-a/①-b)
Crop(作物マスタ) ─* Variety(品種)                                          │
AgroChemical(農薬肥料マスタ②/③) ─* Material(資材使用)                      └─* Harvest(収穫)
  └─* I18nLabel(多言語:共有/テナント上書き)                          StockEvent(入出庫①-a) ← 在庫は導出
Machine(農機) ─* MachineLog(稼働ログ・時系列)
AuditLog(監査①-a・追記型・ハッシュチェーン)   ← 全エンティティの変更を記録
```

### エンティティ分類（4分類 × 3層）

| エンティティ | テーブル分類 | 不変性層 | 主な型 |
|---|---|---|---|
| Organization / Field / Cropping / WorkOrder | ①テナント固有 | ②可逆確定 | id:uuid, tenant_id, deleted_at, version, geom(Field) |
| WorkLog（作業日誌） | ①テナント固有 | 複合（①-a法定/①-b PII） | 実施日:date, 作業者:uuid(スナップショット名), 更新時刻:timestamptz |
| PesticideRecord（農薬使用記録） | ①テナント固有 | ①-a法定 | 散布月日:**date**, 収穫前日数計算, 作業者:実値保持 |
| StockEvent / Punch / MachineLog / 位置ログ | ①テナント固有 | ①-a(在庫)/①-b(打刻位置) | 発生時刻:timestamptz, 時系列パーティション |
| LaborSummary | ①テナント固有（本人起点RLS例外） | 導出/②相当 | user_id, 稼働のみ（業務内容なし） |
| AgroChemical / Crop / 作業種別 | ②共有 or ③共有+上書き | ②可逆確定 | 共有(tenant_id NULL可) |
| I18nLabel | ③共有+上書き | ②可逆確定 | (対象, 言語, 表示名, レビュー状態, 安全フラグ) |
| Draft（下書き） | ④ユーザー所有 | ③下書き | user_id, 確定でtenant固有へ移送 |
| AuditLog | ①テナント固有（書込は監査トリガのみ） | ①-a追記 | 変更前後, 実施者:仮名化ID, ハッシュチェーン |

## 3. 型の適用ルール（ADR-0015：暦日/瞬間）

| 用途 | 型 | 根拠 |
|---|---|---|
| イベント発生時刻・ログ・監査・打刻・同期時刻 | `timestamptz`（UTC保存・表示時変換） | 時点。DST/多TZに頑健 |
| 散布月日・収穫日・作業適期・作付年度 | `date`（圃場TZ基準の暦日） | 収穫前日数（法定）を日跨ぎでずらさない |
| 暦日の確定 | 端末の瞬間 → **圃場属性のTZ** → その暦日 | 越境作業者・深夜でもずれない |
| 金額 | `numeric` ＋ 通貨コード（テナント/圃場設定） | 同一通貨内集計 |
| 単位付き数量（面積等） | 原値＋原単位（権威）＋正規化値（生成列） | 往復丸め防止 |

## 4. RLSポリシー設計（ADR-0001/0005）

**接続前提**：全DBアクセスは明示トランザクション＋`SET LOCAL app.tenant_id`／`app.user_id`／`app.allowed_tenants[]`／`app.scope_field_groups[]`（**すべてサーバ側で導出・注入時検証**）。トランザクションプーリング。アプリは非所有者・非BYPASSRLSロール。全テーブル `FORCE ROW LEVEL SECURITY`。

| 分類 | USING（読取） | WITH CHECK（書込） |
|---|---|---|
| ①テナント固有 | `tenant_id = current_setting('app.tenant_id')::uuid`（未設定/不正は全拒否） | 同左（詐称・越境移送を拒否） |
| ②システム共有 | 全テナント可（読取のみ） | 特権ロールのみ（別接続） |
| ③共有+上書き | `tenant_id IS NULL OR tenant_id = current`（上書き優先はビュー側） | 一般は `tenant_id = current`（NULL共有書込は特権のみ） |
| ④ユーザー所有 | `user_id = current_setting('app.user_id')::uuid` | 同左（確定でtenant固有へ移送） |
| グループ管理者横断 | `tenant_id = ANY(current_setting('app.allowed_tenants'))`（集合は注入時にメンバーシップで検証済み） | 対象組織のみ |
| 本人起点（LaborSummaryのみ） | `user_id = current`（労務サマリテーブル限定） | 参照専用 |
| 受託者の業務記録参照 | `created_by = current`（自作成分のみ・テナントAの許可制と併用） | — |
| スコープ（担当圃場グループ） | 上記に **AND** `field_group_id = ANY(current_setting('app.scope_field_groups'))` | 同左 |
| 個人データ（位置ログ軌跡） | 最小権限（本人＋業務上必要な管理者のみ、現場責任者は原則×） | — |

> 複数ポリシーは permissive の OR 結合になるため、**テナント分離を restrictive で常時強制**しつつ、横断/本人/作成者/スコープを permissive で足す構成をスパイクで検証（ADR-0001 A1-M2）。

## 5. パーティション設計（ADR-0004）

**対象**：時系列・高頻度追記（位置ログ・打刻・MachineLog・StockEvent・AuditLog）。

- **主軸＝時間レンジ**（月/週）：retention（古いパーティションをドロップ/アーカイブ）を成立させる（ADR-0003 A3-L1）。
- **副軸（サブパーティション）＝tenant_id のハッシュ/リスト**：RLSプルーニング・空間性能（各サブパーティション内は単一テナント寄り）。
- **一意制約**：`UNIQUE(event_uuid, 時間キー)`（パーティションキー包含）。**冪等dedup**は「同じイベント→同じ時間パーティション」を、**サーバ受理時刻 or UUID埋め込み時刻で決定的に固定**（端末クロックずれで別パーティションに入らない）。
- **RLS**：親に定義＋全パーティションに FORCE RLS。
- **監査ハッシュチェーン**：パーティション/期間単位のチェーン＋**期間末尾ハッシュのアンカ署名を外部保存**（ドロップ後も改ざん証明）。

## 6. 主要テーブル定義（抜粋・物理）

```sql
-- ①テナント固有・②可逆確定：圃場
CREATE TABLE field (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     uuid NOT NULL,
  field_group_id uuid,                       -- スコープ（担当エリア）
  name          text NOT NULL,
  geom          geometry(MultiPolygon, 4326) NOT NULL,  -- PostGIS(4326保持)
  area_input    numeric, area_unit text,      -- 原値（権威）
  area_sqm      numeric GENERATED ALWAYS AS (...) STORED, -- 正規化(導出)
  timezone      text NOT NULL,                -- 圃場TZ（暦日確定用・ADR-0015 A15c-L1）
  deleted_at    timestamptz,                  -- ソフトデリート
  version       bigint NOT NULL DEFAULT 1,    -- 楽観ロック
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz
);
-- 複合索引の先頭にtenant_id、空間索引はtenant_id含む複合（S2で検証）
CREATE INDEX ON field (tenant_id, field_group_id);
CREATE INDEX ON field USING gist (tenant_id, geom);  -- btree_gist（要スパイクS2）
ALTER TABLE field ENABLE ROW LEVEL SECURITY;
ALTER TABLE field FORCE ROW LEVEL SECURITY;
-- USING/WITH CHECK ポリシーは §4 のとおり

-- ①-a法定：農薬使用記録（暦日はdate）
CREATE TABLE pesticide_record (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id     uuid NOT NULL,
  worklog_id    uuid NOT NULL,
  field_id      uuid NOT NULL,
  applied_on    date NOT NULL,               -- 散布月日（圃場ローカル暦日）
  chemical_id   uuid NOT NULL,
  dilution      text, amount numeric, target_pest text, tool text,
  applicant_name text NOT NULL,              -- 作業者：法定・実値スナップショット保持
  applicant_user_id uuid,                    -- 参照（削除でNULL化可・法定名は残る）
  created_at    timestamptz NOT NULL DEFAULT now()
);  -- ①-aのため更新/削除しない（訂正は訂正イベント追記）

-- 時系列・追記：位置ログ（パーティション）
CREATE TABLE location_log (
  event_uuid    uuid NOT NULL,               -- クライアント生成（冪等dedup）
  tenant_id     uuid NOT NULL,
  user_id       uuid NOT NULL,
  occurred_at   timestamptz NOT NULL,        -- 時点(UTC)
  geom          geometry(Point, 4326),
  PRIMARY KEY (event_uuid, occurred_at)       -- パーティションキー包含
) PARTITION BY RANGE (occurred_at);           -- 主軸=時間、副軸=tenant(サブパーティション)
```

## 7. S1/S2 スパイク方針（M3で固める）

| ID | 検証内容 | 方法 | 合格基準 | 中止/代替 |
|---|---|---|---|---|
| **S1** | パーティション×RLS×一意×FORCE RLS | 時間レンジ＋tenantサブパーティションを作り、RLS（テナント分離・許可集合横断）と `UNIQUE(event_uuid,時間)` を張り、他テナント参照遮断・冪等dedup・FORCE RLSの子適用を自動テスト | 他テナント遮断100%、リトライで重複0、FORCE RLS有効 | 破綻時は「1国=単一パーティション木＋別dedupテーブル」等へ |
| **S2** | 空間×RLS性能 | 数万圃場（複数テナント）で `gist(tenant_id, geom)` の複合索引 vs 分離索引でプラン・実測比較。RLS述語込みで近傍・包含クエリ | 地図初期表示2秒/p95、tenant絞り→空間の順でプルーニング | 未達時はtenant別パーティション＋geom単独GiSTでプルーニング |

- **共通データセット**：合成データ（テナント数十、圃場数万、位置ログ数百万）を投入。
- **計測**：`EXPLAIN (ANALYZE, BUFFERS)`、p95レイテンシ、パーティションプルーニングの有無。
- **成果物**：スパイク結果を各ADRの未解決事項へフィードバック（ADR-0004/0001）。

## 8. 未解決事項（実装/後続設計へ）

- RLSポリシーの完全な文（restrictive/permissiveの組合せ）とポリシーテストスイート。
- 版履歴の物理（別テーブル vs システムバージョニング）と保持世代。
- 監査ハッシュチェーンの具体（アルゴリズム・アンカ署名の外部保存先）。
- 圃場TZ解決に用いるTZ境界データセットの選定・更新（ADR-0015 A15c-L1）。
- I18nLabelの共有/上書き解決ビューと安全フラグ運用。
- 通貨・単位の正規化生成列の具体式と丸め。
- パーティション自動作成・アーカイブのジョブ（ADR-0019/0017）。
