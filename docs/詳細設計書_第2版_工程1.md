## 1. この工程で実現すること

既存のガント作業（行）に実行状態（未着手／着手中／完了）を付け、パソコンで今日／今週／先週／前後7日／すべての日次一覧から回せるようにする。遅れた未完了の作業も一覧に出す。実績の正本は地図の塗りのままとする。実行状態は面積％を置き換えない。

### 1.1 部品

- **実行状態。** `gantt_rows.execution_status` に三値のみを持つ。別テーブル・暦日ごとの状態は作らない。
- **日次一覧画面。** 利用者パソコンの `/daily`。今日／今週／先週／前後7日／すべての切替、状態フィルタ、遅れの印、状態変更。
- **状態変更の入口。** `/daily` は状態専用 API（`PUT /api/user/gantt/{id}/status`）を使う。`/works` の作業編集、`/gantt` の行編集および棒（行）選択後の状態操作は、行更新 API（`PUT /api/user/gantt/{id}`）に版を添えて使う。
- **版。** `gantt_rows.version` で行の変更回数を数え、古い画面からの行更新を断る（楽観ロック）。
- **日時。** 開始・終了・期間判定は Asia/Tokyo。保存形式は第1版どおり `YYYY-MM-DDTHH:MM`（タイムゾーン文字列なし）。

## 2. 画面と経路

### 2.1 ブラウザの経路（ClojureScript）

| 経路 | 誰 | ログイン | 役割 |
|---|---|---|---|
| `/daily` | 利用者 | 必要 | 日次一覧（今日／今週／先週／前後7日／すべて）、状態フィルタ、遅れの印、実行状態の変更 |
| `/works` | 利用者 | 必要 | 第1版どおり。作業の追加・変更に実行状態の表示と変更を足す |
| `/gantt` | 利用者 | 必要 | 第1版どおり。行編集および棒／行の選択後に実行状態を変えられる |

利用者ホーム `/home` に、日次一覧への出口を足す。圃場が0枚のときは出口を出さない（または押せない）。管理者ホームには日次一覧を足さない。

狭い画面で `/daily`・`/works`・`/gantt` を開いたときは、第1版どおり「パソコンで開いてください」とし、実行状態の変更 UI は出さない。第2版工程4のスマホ日次閲覧は、この工程では作らない。

### 2.2 `/daily` に出すもの

- **期間の切替。** `今日` / `今週` / `先週` / `前後7日` / `すべて` の五者択一。開いた直後は `前後7日`。
- **遅れの印。** 行の `overdue` が真なら、表示名の前に赤地の「遅れ」を出す。
- **状態フィルタ。** `未着手` / `着手中` / `完了` をそれぞれオン／オフ。開いた直後は未着手と着手中がオン、完了がオフ。
- **すべてオフのとき。** 行は出さず空一覧とし、「状態フィルタを1つ以上オンにしてください」と案内する。どれか1つだけの選択 UI にはしない。最後の1つをオフにすることは許す。
- **一覧。** 期間条件とオン中の状態に属する、削除されていない自分の作業。各行に少なくとも表示名・開始／終了・実行状態。並びは `start_at` 昇順、同じなら `id`。
- 一覧は曜日セクションに分けず、1本の平坦な一覧とする。
- **空のとき。** フィルタ結果が0件で、登録作業が1件以上あるときは、「選んだ期間・状態に重なる作業がありません」と案内し、作業画面（`/works`）への出口を出す。登録作業が0件のときは「該当する作業はありません」とする。
- **ページ案内。** 見出しの直下に、日次一覧の目的（今日／今週／先週／前後7日／すべての予定を実行状態で回す。遅れた作業も出る）を短く出す。
- **状態変更。** 各行から三値を選べる（セグメントまたは同等）。選ぶと `PUT /api/user/gantt/{id}/status` に `{"execution_status": ...}` だけを送って保存する。一覧を読み込んだ時点の表示名・時刻などは送らない。
- **作業を開く。** 各行の「作業を開く」は `/works?id={id}` へ移り、その作業を選んだ状態（編集欄と明細が出た状態）で開く（レビュー記録票 RV-V2-001 R-10）。画面内リンクの `?` 以降は検索部として扱う。`id` が数字でない、または一覧に無い（削除済み等）ときは選ばずに開く。

配置のピクセル、コンポーネント名は定めない。

### 2.3 `/works` への追加

- 一覧および追加・変更フォームに、実行状態の表示と変更を足す。
- 新規作成の初期表示は未着手とする（保存時も `not_started`）。
- **新規追加フォーム**は「新しい作業を追加」など独立した見出しの下に置き、開始・終了の初期値は Asia/Tokyo の今日 08:00〜17:00 とする（空欄のままにしない）。
- **表示名**の画面ラベルは「作業タイトル」とし、「一覧・ガントの棒に出る名前（題名・塗り用の作業名とは別）」と分かる短い注記を付ける。
- その他の欄・対象圃場・題名の規則は第1版工程4の詳細設計のままとする。
- **日時の入力（R-10）。** 作業の開始・終了（新規・編集）、および作業時間の開始・終了は、ブラウザ標準の日時選択部品（`input type="datetime-local"`）とする。値の形式は `YYYY-MM-DDTHH:MM` のままで、API は変えない。`/gantt` の同じ欄も同じ。
- **一覧の絞り込み（R-11）。** 一覧の上に、期間（今日／今週／先週／前後7日／すべて）と状態（未着手／着手中／完了のオン／オフ）の絞り込みを置き、「絞り込む」で反映する。
  - 開いた直後は **すべての期間・すべての状態**（従来どおり全件が見える）。`/works` を開き直すと初期値に戻る。
  - 期間の意味と遅れの扱いは `/daily` と同じ（期間と重なる作業に加え、現在を含む期間では期間より前に終わった未完了も出す）。遅れの行には「遅れ」の印を出す。
  - 期間の境界と現在時刻は、`GET /api/user/gantt` の `windows`（§2.5）を使い、読み込み済みの一覧を画面側で絞る。`windows` が無いときは期間では絞らない。実行状態が欠けた行は未着手として扱う。
  - 条件に合う作業が無いときは「選んだ期間・状態に重なる作業がありません。期間または状態を変えてください」と出す。作業が1件も無いときは絞り込みを出さない。
  - 選択中の作業が絞り込みで一覧から外れても、編集欄はそのまま使える。

### 2.4 `/gantt` への追加

- 題名配下の作業編集に、実行状態の表示と変更を足す。
- 棒（または行）を選んだあと、状態を選ぶ操作を出す。横軸・縦軸どちらでも同じ。色クリックによる三値サイクルは置かない。
- **ページ案内。** 見出しの直下に、この画面が「題名ごとに作業を時間軸で見る・進捗％と地図を確認する」ためのものであることを短く出す。
- **題名なしの作業**があるときは、ガントには出ない旨と `/works` への出口を出す。
- 新規作業フォームも「この題名に作業を足す」見出しの下に置き、開始・終了の初期値は今日 08:00〜17:00 とする。表示名ラベルは §2.3 と同じ。
- 時間軸の範囲・向き・％・地図色は第1版のままとする。日次一覧は `/daily` 側とする。

### 2.4b 共通の画面の分かりやすさ（この工程で直す範囲）

利用者ナビに **日次** と **ガント** を足す（圃場がある利用者向けの作業導線）。ホームの各出口には短い説明を添えてよい。`/daily`・`/works`・`/gantt` では、一覧・新規・編集を見出しで区切る。招待・パスワード変更・圃場台帳・指示作成など、追加・変更フォームがある画面でも、目的の短い案内と見出しで区切る。

### 2.5 API（Clojure）

工程1（第1版）と同じ JSON の形とする。自分の利用者セッションが必要。管理者のガント API は `forbidden`。他人の行は `gantt_not_found`。圃場0枚は `no_fields`（第1版ガントと同じ）。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/gantt` | GET | 第1版どおりの一覧。各行に `execution_status` を含める。応答に `windows`（作業一覧の絞り込み用。`now` と `today` / `week` / `last_week` / `around7` の `[開始, 終了)`。いずれも Asia/Tokyo の `YYYY-MM-DDTHH:MM`）を足す |
| `/api/user/gantt` | POST | 行を作る。`execution_status` は常に `not_started` で保存する（クライアントが他値を送っても採用しない） |
| `/api/user/gantt/{id}` | PUT | 第1版の欄に加え、任意で `execution_status` を更新できる。省略時は既存値を維持する。任意で `version` を送ると版照合する（§2.6） |
| `/api/user/gantt/{id}/status` | PUT | 実行状態だけを変える。本文は `{"execution_status": "..."}`。ほかの欄は変えない。版照合はしない（最後の操作が勝つ） |
| `/api/user/gantt/{id}` | DELETE | 第1版どおりソフト削除 |
| `/api/user/gantt/daily` | GET | 日次一覧。クエリで期間と状態フィルタ |

`GET /api/user/gantt/daily` のクエリ:

| 名 | 必須 | 内容 |
|---|---|---|
| `range` | 必須 | `today` / `week` / `last_week` / `around7` / `all` |
| `statuses` | 任意 | カンマ区切り。`not_started` / `in_progress` / `done` の部分集合。省略時は `not_started,in_progress`（画面初期と同じ）。空文字または要素0件のときは行を返さず、成功の空配列とする |

期間の計算（サーバ・Asia/Tokyo）:

- `today`: その日の 0:00 から翌日 0:00 まで（終端は含まない窓）。
- `week`: 今週の月曜 0:00 から翌週の月曜 0:00 まで。
- `last_week`: 先週の月曜 0:00 から今週の月曜 0:00 まで。
- `around7`: 今日の7日前の 0:00 から、今日の8日後の 0:00 まで（今日を含む15暦日）。
- `all`: 期間窓なし。開始・終了による絞り込みをしない。
- 旧 `days7` は廃止し、`range_invalid` とする。

重なり判定（`all` 以外。開始・終了は行の `start_at` / `end_at`）:

- 窓を `[window_start, window_end)`、行を `[start_at, end_at]`（終了時刻を含む）とみなす。
- **重なる**のは `start_at < window_end` かつ `end_at > window_start` のときとする。
- `all` のときは重なり判定を行わず、状態フィルタとソフト削除だけを適用する。

遅れ（`now` は Asia/Tokyo の現在時刻を `YYYY-MM-DDTHH:MM` にしたもの）:

- 行が **遅れ** なのは、`execution_status` が `done` でなく、かつ `end_at <= now` のときとする。
- 窓が現在を含む（`window_start <= now < window_end`。`today` / `week` / `around7` が該当）とき、重ならなくても遅れの行を載せる。`last_week` には足さない。
- 状態フィルタは遅れの行にも効く。遡る期間の上限は置かない。
- 並びは変えない（遅れの行は `start_at` が早いので先頭側に来る）。
- ソフト削除行（`deleted_at` 非 NULL）は出さない。
- 題名の有無は問わない。

並び: `start_at` 昇順、同じなら `id`。

`GET /api/user/gantt` および `GET /api/user/gantt/daily` の行オブジェクト（第1版の欄に足す）:

```
{
  "id": 1,
  "title": "...",
  "title_id": 1,
  "start_at": "2026-09-21T08:00",
  "end_at": "2026-09-21T17:00",
  "work_name": "田植え",
  "field_ids": [1, 2],
  "execution_status": "not_started",
  "version": 1
}
```

`title_id` が無い行は `null`。`work_name` が無い行は `null`。対象が無い行は `field_ids` を空配列。`GET /api/user/gantt/daily`（および管理者の横断一覧）の行には、あわせて `overdue`（真偽値）を足す。

### 2.6 版照合（楽観ロック）

- 行を作ると `version` は 1。行更新 API・状態専用 API で更新するたびに 1 増える。
- 行更新 API に `version` があれば、保存時の `version` と一致するときだけ更新する（`UPDATE ... WHERE id = ? AND version = ?`）。一致しなければ何も変えずに `gantt_conflict` を返す。`version` が整数として読めないときも `gantt_conflict`。
- `version` を省略した行更新は照合しない（既存の呼び出しとの互換）。画面（`/works`・`/gantt`）は、読み込んだ行の `version` を必ず添える。
- 状態専用 API も `version` を進めるので、日次一覧で状態を変えた後、古い作業画面から保存すると `gantt_conflict` になる（古い状態で戻さない）。
- 画面は `gantt_conflict` を受けたら、「ほかの画面でこの作業が変更されています…」と出し、`GET /api/user/gantt` で最新を読み込み直す。

`PUT` で `execution_status` を送るとき、値が三値以外なら `execution_status_invalid`。

`GET /api/user/gantt/daily` で `range` が欠ける・不正なら `range_invalid`。`statuses` に未知のトークンがあれば `statuses_invalid`。

失敗の `code` をこの工程で足すもの:

| code | 使うとき |
|---|---|
| `execution_status_invalid` | 三値以外を保存しようとした |
| `range_invalid` | `range` が `today` / `week` / `last_week` / `around7` / `all` でない |
| `statuses_invalid` | `statuses` に未知の値がある |
| `gantt_conflict` | 行更新の `version` が保存時と一致しない、または整数でない |

第1版の `no_fields` / `gantt_not_found` / `time_*` 等はそのまま使う。

## 3. 処理の規則

### 3.1 誰が使うか

- 日次一覧と実行状態を使えるのは、圃場を1枚以上持つ利用者だけとする。管理者は持たない。
- 圃場0枚の利用者は `/daily` を開けない（案内のみ）。API は `no_fields`。
- スマホ幅では変更 UI を出さない。サーバはセッションがあれば PUT を受けてよい（第1版と同じ。User-Agent では拒否しない）。

### 3.2 実行状態

- 値は次の三つのみとする。

| 保存・API | 画面（日本語） |
|---|---|
| `not_started` | 未着手 |
| `in_progress` | 着手中 |
| `done` | 完了 |

- 新規行の初期は `not_started`。
- この工程の導入時、既存行はマイグレーションですべて `not_started` とする。
- 三値のあいだの遷移は自由（完了→未着手も可）。開始・終了時刻や塗り％から自動推定しない。
- 塗り・面積％・日次確定％・指示・日誌とは同期しない。

### 3.3 日次一覧の対象

- §2.5 の重なり判定とフィルタに従う。
- 題名なしの作業も含む。選んだ題名配下に閉じない。

### 3.4 第1版機能との関係

- 面積％・地図色・日次確定％・ガント時間軸（日／週／8週／月／3ヶ月／6ヶ月、向き）は第1版のままとする。
- `/map` の塗り規則は変えない。

## 4. 残す情報

第1版の `gantt_rows` を壊さない。列を1つ足す。

### 4.1 `gantt_rows` への追加

| 列 | 型 | 内容 |
|---|---|---|
| `execution_status` | TEXT NOT NULL | `not_started` / `in_progress` / `done`。既定 `not_started` |
| `version` | INTEGER NOT NULL | 版。既定 1。更新ごとに 1 増える（§2.6） |

起動時マイグレーション:

1. 列が無ければ追加する（`execution_status` は既定 `not_started`、`version` は既定 1）。
2. 既存で NULL または空、または未知値の行は `not_started` に直す。

別テーブルは作らない。指示 ID・作業時間・チェック用の列はこの工程では足さない。

## 6. この工程で作らないもの

- 作業時間・チェック項目（第2版工程2）
- メモおよびガント紐づけ（第2版工程3以降）
- 担当・繰り返し・通知
- 予定と塗りの自動同期、必須リンク
- スマホでの実行状態変更、およびスマホでの日次一覧閲覧（第2版工程4）
- カレンダー専用 UI（曜日分割の週カレンダーを正本にすること）
- 管理者の日次一覧・実行状態
- 棒のクリックサイクルによる状態変更

## 7. 完了として満たすこと（詳細）

- `gantt_rows.execution_status` があり、三値だけである。既存・新規の初期は `not_started`。
- `/daily` で今日・今週・先週・前後7日・すべてを切り替えられ、重なり判定・遅れ・並びが §2.5・§3.3 どおりである。
- 状態フィルタが複数オン／オフでき、初期は未着手＋着手中。全オフは空＋案内である。
- `/daily`・`/works`・`/gantt`（編集および棒選択後）から状態を変えられる。`/daily` は状態専用 API でほかの欄を変えず、`/works`・`/gantt` は版照合つきの PUT で保存される。
- `/daily` の「作業を開く」で、その作業を選んだ状態の `/works` が開く。開始・終了は日時の選択部品である。
- `/works` の一覧を期間・状態で絞り込め、初期はすべてが見える。期間と遅れの扱いは `/daily` と同じである。
- 面積％・地図色の規則が第1版のままである。
- 狭い画面では日次・ガント・作業の編集案内のみで、状態変更 UI が無い。
- 管理者および圃場0枚は日次一覧・実行状態を使えない。
- 作業時間・チェック・メモ・担当・繰り返し・通知・予定と塗りの同期が、この工程の成果に混入していない。
