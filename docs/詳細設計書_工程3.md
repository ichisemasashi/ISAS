## 1. この工程で実現すること

作業結果の正本を、自分の圃場ポリゴンの上の塗りとする。進捗色は、地図側で選んだ作業名に対する塗りだけで付ける。

工程3で動かす論理ブロックは、基本設計書 §10 のとおり、塗りと地図側の作業名色である。

### 1.1 工程3の部品

- **入れ物。** 工程1・2の Clojure / ClojureScript / API / SQLite / OpenLayers を足して使う。
- **作業名。** マスタ表は持たない。塗り行が持つ文字列とする。前後空白を除き、完全一致。保存は除いたあとの文字列。改名 API は置かない。
- **塗り。** 確定したポリゴンだけを SQLite に残す。下書きは残さない。座標は工程2と同じ経度緯度（WGS84）の GeoJSON。
- **切り取りと和集合。** 正本は Clojure 側で JTS を使い、圃場の内側に切り、同じ圃場・同じ作業名の重なりを二重に数えない。
- **ブラシ下書き。** ClojureScript と OpenLayers の画面上だけとする。下書きを重ね、まとめて1回確定する。確定するまで API に送らない。破棄できる。
- **パソコン。** 塗りはパソコンの `/map` だけとする。スマホでは塗らない。

## 2. 画面と経路

新しいブラウザ経路は置かない。工程2の `/map` に、作業名の選択、ブラシ、確定、全面完了、塗りの削除を足す。管理者側には足さない。

### 2.1 `/map`（工程3で足すもの）

- 開いたときは作業名未選択。進捗色は付けず形だけ。前回の作業名は残さない。メニューは圃場側（browse）。
- **作業名はメニュー（browse）からも入れる。** 「塗りをする」を押さなくても作業名を入力・選択できる。作業名を確定すると塗り用の操作が前面に出る。
- **塗り優先の段階表示。** 作業名を選んでいるあいだは塗り用の操作を前面に出す。手描き・修正・分割・合筆・区画取込は「圃場を直す」でメニュー（browse）に入ってから出す。下地は塗り中からも「下地」で入れる。
- **作業名ありのときのボタン並び。** 上から (1) 作業名・凡例 (2) 「塗る」（ブラシ → 塗りを確定する → 下書きを捨てる） (3) 「選んだ圃場」（全面完了・全部消す） (4) 「選んだ塗り」（この塗りを消す） (5) 「ほか」（圃場を直す・下地）。確定と下書き破棄は下書きがあるときだけ、全面完了と全部消すは圃場選択後、この塗りを消すは塗り選択後だけ押せる。
- 作業名を選ぶ（候補から、または新規入力）。選んでいるあいだ、各圃場に未／一部／済の色を付ける。
- 作業名が空のままでは塗れない・全面完了できない。
- ブラシはボタンを押したときだけ描画を始め、**一筆が終わったら描画を外して地図のドラッグ（パン）とズームを使える**ようにする。重ね塗りするときは再度ブラシを押す。
- 下書きは重ねてよい。まとめて1回「塗りを確定する」まで正本にしない。破棄すると下書き全部を捨てる。
- 確定した塗りは、地図上で1つずつ消せる。その圃場・その作業名を全部消して未に戻せる。
- 地図クリックの選択表示は次とする。塗りをクリックしたときは「選んでいる塗り: {圃場名}」。圃場（塗り以外）をクリックしたときは「選んでいる圃場: {圃場名}」。いずれも内部 ID（`paints.id` / `fields.id`）は出さない。
- 全面完了は、選んだ作業名について、対象の1圃場の塗りを圃場の形全体にする。
- ガント、パーセントサークル、指示は出さない。

### 2.2 API（Clojure）

工程1・2と同じ JSON の形とする。自分の利用者セッションが必要。管理者は `forbidden`。他人の圃場は `not_found`。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/user/work-names` | GET | 自分が塗った作業名の一覧（重複なし。塗りが1つ以上残っている名前だけ） |
| `/api/user/paints` | GET | クエリ `work_name`。自分の全圃場について、その作業名の状態と塗りポリゴン。`work_name` が無い／空なら `code: work_name_required` |
| `/api/user/paints` | POST | `{ "field_id", "work_name", "geojson" }`。重ねた下書きを1回確定した多角形（MultiPolygon 可）。サーバが JTS で圃場内に切り、面積が取れなければ保存しない。1回の確定は `paints` の1行とする |
| `/api/user/fields/{id}/complete` | POST | `{ "work_name" }`。その圃場・その作業名の塗りを、現在の圃場形全体に置き換える |
| `/api/user/paints/{id}` | DELETE | 確定した塗りを1つ消す。自分の塗りでなければ `not_found` |
| `/api/user/fields/{id}/paints` | DELETE | クエリ `work_name` 必須。その圃場・その作業名の塗りを全部消す |

工程2の次の API に、塗りの有無を足す。

| 経路 | 工程3での追加 |
|---|---|
| `POST /api/user/fields/{id}/split` | その圃場に塗りが1つでもあれば保存せず `field_has_paint` |
| `POST /api/user/fields/merge` | 対象のどれかに塗りがあれば保存せず `field_has_paint` |
| `PUT /api/user/fields/{id}`（`geojson` を含む） | 保存したあと、その圃場の塗りを新しい形の内側に切り直す。面積が取れなくなった塗り行は消す |
| `DELETE /api/user/fields/{id}` | その圃場の塗り行も消す |

`GET /api/user/paints` の成功本文:

```
{
  "ok": true,
  "work_name": "...",
  "fields": [
    {
      "id": 1,
      "name": "...",
      "status": "none" | "partial" | "done",
      "area_m2": 0,
      "field_area_m2": 0,
      "paints": [ { "id": 1, "geojson": {} } ]
    }
  ]
}
```

`name` は圃場名。地図の「選んでいる塗り」表示に使う。`status` は次とする。

| status | 意味 |
|---|---|
| `none` | その作業名の塗り面積が 0 |
| `partial` | 0 より大きく、圃場面積より小さい |
| `done` | 全面完了した、または塗り面積と圃場面積の差が 1㎡ 未満 |

失敗の `code` を工程3で足すもの:

| code | 使うとき |
|---|---|
| `work_name_required` | 作業名が無い、または空白だけ |
| `work_name_too_long` | 100文字を超える（前後空白を除いたあと） |
| `field_has_paint` | 塗りが残っている圃場の分割・合筆 |
| `paint_not_found` | その塗りが無い、または他人 |
| `paint_empty` | 切り取り後に面積が取れない |

### 2.3 作業名の扱い

- 候補は `GET /api/user/work-names` のみ。工程3ではガントも指示も無いので、塗った名前だけである。
- 新しい名前は POST の `work_name` に入れて使える。先にマスタを作る API は置かない。
- 塗りが1つも無くなった名前は、候補から消える。履歴を残す表は持たない。
- 他人の作業名は出さない。

### 2.4 色（地図）

作業名未選択のときは工程2どおり、進捗色なし（形の線だけ）。選んでいるときの塗りつぶしは次とする。

| 状態 | 色 |
|---|---|
| 未 | `#c8c8c8` |
| 一部 | `#e6b800` |
| 済 | `#2e7d32` |

色の意味は基本設計書 §4.5 のとおりである。下地と作業場所の初期表示は工程2のままとする。

## 3. 処理の規則

### 3.1 誰が塗るか

- その圃場の `user_id` がログイン中の利用者であること。
- 圃場が0枚なら、塗る対象が無い。作業名候補も空である。
- 下地画像そのものへは保存しない。POST の GeoJSON は圃場形との交差だけを残す。

### 3.2 確定

- 下書きを画面上で重ね、1回の確定で GeoJSON を1つ POST する。一筆ごとに API は呼ばない。
- サーバは JTS で (1) 作業名を正規化 (2) 圃場内に切る (3) 面積が取れること (4) `paints` に1行足す。
- 同じ圃場・同じ作業名に複数行あってよい。面積は、JTS でそれらの和集合を圃場内で取った面積とする。

### 3.3 全面完了

- その圃場・その作業名の既存塗り行を消し、圃場の `geojson` をコピーした1行を足す。
- 以降の `status` は、形が圃場と同じなので `done` とする。

### 3.4 削除

- 1つの塗り ID を消せる。全部消しは `DELETE .../paints?work_name=`。
- 作業名の改名はしない。別名で塗るのは別の行になる。

### 3.5 分割・合筆・境界

- 分割・合筆は、対象圃場に塗りがあれば拒否する。
- 境界の修正は許す。保存後にその圃場の塗りを内側へ切り直す。

## 4. 残す情報（工程3）

工程2の表は壊さない。足す単位は次とする。

### 4.1 塗り `paints`

| 列 | 型 | 内容 |
|---|---|---|
| `id` | INTEGER 主キー | |
| `field_id` | INTEGER | `fields.id` |
| `work_name` | TEXT | 正規化した作業名 |
| `geojson` | TEXT | Polygon または MultiPolygon。圃場の内側 |
| `created_at` | TEXT | UTC |

面積列は持たない。全面完了フラグは持たない。`user_id` は圃場から辿る。

作業名専用の表は持たない。候補は `paints.work_name` の重複なし一覧である。

## 7. 完了として満たすこと（詳細）

基本仕様書 §3.8 に加え、次を満たす。

- 「田植え」と「田植」が別の `work_name` として残る。
- 地図を開き直すと作業名未選択で、色が付いていない。
- 分割・合筆 API が、塗りのある圃場で `field_has_paint` を返す。
- 圃場を消すと、その塗りも残らない。
