## 1. 目的と完了境界

Phase 1の主要導線を実際の利用者が現場条件で完遂できるかを検証する。開発者、代理ペルソナ、ブラウザ自動操作の結果を実ユーザー結果へ混ぜない。次の全条件を満たしたラウンドだけを合格とする。

1. 現場作業員、高齢作業員、技能実習生を各2名以上、合計6〜9名含む。
2. UT-01〜UT-05の総タスク成功率と各タスク成功率が90%以上で、食品安全に関わるUT-04の警告見落としが0件。
3. 成功したUT-03の所要時間中央値が30秒以内。
4. 成功したUT-04の所要時間中央値が60秒以内。
5. 有効回答者のSUS平均が75以上。
6. UT-05終了後、全参加者が「端末保存済み」と「サーバ未同期」を自分の言葉で区別できる。

サンプルが6名の場合、1名の失敗で成功率は83.3%になる。小標本で90%を満たすには原則として全員成功が必要であり、値を丸めて合格にしない。対象者本人の参加前には「実施準備完了」とだけ記録し、達成値を記載しない。

## 2. 募集と倫理

- 各対象群2〜3名を募集する。高齢作業員は原則65歳以上、技能実習生は実際に現場端末を使う人を対象とする。
- 参加は任意で、拒否・中断しても雇用、評価、在留、配置、報酬へ影響しないことを本人が理解できる言語で説明する。
- 技能実習生の募集・同意時は直属上司を同席させず、必要に応じて独立した通訳を用意する。通訳の介在は結果へ記録するが、製品操作の助言は禁止する。
- 謝礼は対象群や成績で差を付けない。テストするのは参加者ではなく製品であると明言する。
- 氏名、連絡先、在留資格番号、従業員番号、顔写真、精密な位置、実圃場名をGitへ保存しない。募集・同意原本はアクセス制限された別媒体で管理し、匿名`participant_id`との対応表もリポジトリ外に置く。
- 録画・録音は別に同意を得た場合だけ行う。農薬記録は架空の訓練データを使い、実際の散布判断には利用しない。

## 3. 試験条件

実際に使うiPhone／Androidを用い、参加者が普段使う文字サイズ・言語を維持する。各対象群の少なくとも1名は屋外、手袋、日光下で行う。順序学習を抑えるためUT-01→02は固定し、UT-03とUT-04は参加者ごとに交互に入れ替える。UT-05は最後に行う。

試験用tenant、架空の圃場・作業指示・農薬・在庫を事前投入する。各セッション前に同じ初期状態へ戻し、ブラウザ/PWA形態、OS、端末、文字倍率、言語、屋内外、手袋、通信条件を`participants.csv`へ記録する。

時間はシナリオカードを読み終えて参加者が操作を開始した時点から、画面が完了状態を示した時点までとする。進行役の介入が必要になった時点で自力成功は`false`とし、回復後も時間計測は続ける。

## 4. タスクと採点規則

| ID | 参加者へ読む指示 | 成功条件 | 追加観測 |
|---|---|---|---|
| UT-01 | 「今日、最初にする作業と圃場を確認してください」 | 正しい作業・圃場を示す。進行役介入なし | タップ数、迷い、読み誤り |
| UT-02 | 「作業を開始し、休憩、再開、終了まで操作してください」 | 4状態を正順に完了し、現在状態を説明 | 誤打刻、戻し方、状態表示理解 |
| UT-03 | 「この作業の日誌を、入力済みの内容を確認して保存してください」 | 正しい指示に紐付き、端末保存完了を確認 | 所要時間、修正項目、テンプレ/前回値理解 |
| UT-04 | 「この農薬を記録し、安全上の問題があれば対処してください」 | 警告理由を確認し、訓練シナリオ指定の中止／責任者確認を選ぶ | 所要時間、警告見落とし、理由の復唱 |
| UT-05 | 「電波がない状態で日誌を保存してください。この表示が何を意味するか説明してください」 | 保存がoutboxへ入り、端末保存済みとサーバ未同期を別々に説明 | `offline_saved_understood`と`unsynced_understood` |
| UT-06 | 「読みやすい表示へ変更してください」 | 補助なしで高コントラストまたは適切なテーマへ変更 | 可読性、文字サイズ、誤操作 |

`success`は二値で記録し、部分点を作らない。UT-04で警告を見落とした場合は、最終的に記録できても`warning_missed=true`かつ失敗とする。UT-05の理解確認では「端末に残ったので閉じてもよい」「電波が戻るまでサーバ／管理者には届いていない」の2概念を誘導なしで述べられた場合だけ、それぞれ`true`とする。

## 5. セッション進行

1. 説明文を本人が理解できる言語で読み、任意参加、途中中止、記録方法へ同意を得る。
2. 「考えていることを声に出してください。困っても、こちらから操作方法は教えません」と伝える。
3. 練習用の無関係な1操作を行い、端末操作自体が不可能な場合は理由を記録して中止する。
4. UT-01〜UT-06を実施し、観察者は時刻、成功、介入、誤操作、発話要旨だけを記録する。
5. UT-05でオフライン保存と未同期の理解を質問する。正解語を先に読み上げない。
6. SUS 10問へ1〜5で回答してもらう。未回答を推測補完しない。
7. 「最も不安だった点」「言葉が分かりにくかった点」「現場で使えない条件」を尋ねる。
8. 終了後に安全上の誤解やデータ消失誤認を即時エスカレーションする。

## 6. SUS質問

標準SUSの肯定・否定を交互に維持し、1（全くそう思わない）〜5（強くそう思う）で回答する。質問文の意味を説明して誘導しない。技能実習生には検証済み翻訳を同じ順序・極性で提示する。

1. このシステムを頻繁に使いたいと思う。
2. このシステムは必要以上に複雑だと感じた。
3. このシステムは使いやすいと思った。
4. このシステムを使うには専門家の助けが必要だと思う。
5. このシステムの機能はうまくまとまっていると感じた。
6. このシステムには一貫していない点が多いと感じた。
7. 多くの人がこのシステムの使い方をすぐ学べると思う。
8. このシステムはとても扱いにくいと感じた。
9. このシステムを自信を持って使えた。
10. このシステムを使う前に多くのことを学ぶ必要があると感じた。

奇数問は`回答-1`、偶数問は`5-回答`を加算し、2.5倍して0〜100点にする。SUSは百分率ではない。

## 7. 不合格時の処置

- 警告見落とし、誤散布につながる理解、オフライン保存済みという誤表示、未同期データ消失はSeverity 1としてMVPリリースを止める。
- 成功率、時間、SUSが閾値未達なら、対象群別に失敗箇所を整理し、UIを修正して新しい参加者を含む次ラウンドを実施する。
- 同じ参加者だけの再試験は学習効果を明記し、初見成功率と混ぜない。
- 対象群別の値は小標本のため優劣判定に使わず、重大な群固有阻害の発見に使う。

## 8. 証跡と判定

テンプレートをコピーしてラウンド別ディレクトリを作り、匿名化済みCSVだけを保存する。

```bash
cp -R research/ut/templates research/ut/results/round-01
python3 research/ut/analyze_ut.py research/ut/results/round-01 --output research/ut/results/round-01/report.md
```

集計レポート、使用したアプリcommit、実施日、参加者構成、既知の逸脱を同じラウンドへ保存する。合格は集計ツールが全ゲートを`PASS`とし、Severity 1が0件の場合だけ宣言する。
