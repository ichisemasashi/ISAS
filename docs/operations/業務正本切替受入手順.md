# 業務正本切替受入手順

本手順は、KSAS等の既存正本からISASへ切り替える際の最終受入である。local test、fixture、simulator、担当者が作成した推測値は証跡に含めない。選択したProduction hostと同じOS（macOS／Linux／FreeBSD）、同じartifact、同じsource commitを隔離Stagingへ配備して実施する。

## 必須証跡

1. 実由来CSVによる圃場→作業記録→農薬履歴の移行・再投入・RLS・出力照合
2. 現場作業員、高齢作業員、技能実習生各2名以上によるUT
3. iOS／Android実機matrixとoffline・失効・共有端末試験
4. 実TLS、実BFF、PostgreSQL 16＋PostGIS、実networkによるSLO・手動WCAG・独立penetration
5. 月次隔離restore、四半期DR、起動・停止・rolling restart・障害対応
6. blocking alarm、signal欠落、Sev-1/2、未解決High/Mediumが0件の24時間Staging観測

各証跡JSONにはRelease candidateと同じ`source_commit`、`deployment_id`、`host_os`を記録する。受入indexの`documents.<name>.digest`には、対応するJSON byte列の`sha256:` digestを登録する。

```bash
shasum -a 256 /secure/evidence/migration.json

node ops/check-business-cutover-acceptance.mjs \
  /secure/evidence/cutover-index.json \
  /secure/release/release-candidate.json \
  /secure/evidence/migration.json \
  /secure/evidence/user-acceptance.json \
  /secure/evidence/device.json \
  /secure/evidence/quality.json \
  /secure/evidence/operations.json \
  /secure/evidence/staging-bake.json
```

PASSしたindexだけを改変不能な証跡保管先へ保存し、Release candidateの`gates.business_cutover_acceptance`へ同じ`source_commit`、31日以内の`collected_at`、indexのURIを登録する。このgateを含む全gateがPASSしなければ`assemble-release-manifest.mjs`はREADY manifestを生成しない。

現時点では実CSV、参加者、実機、独立security試験、実restore／DR、24時間観測を実施していない。このため、本手順と検査器の存在だけをProduction受入完了またはKSASからの切替承認として扱わない。
