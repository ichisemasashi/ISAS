## 2. Command記入規則

各操作へ次の5点を必ず記入する。

1. copy&pasteできる非対話command。暗黙のcurrent contextに依存させない。
2. 正常時の終了codeと、確認できる出力例。
3. timeoutと失敗判定。無限に待たない。
4. data、session、outbox、trafficへの影響。
5. 失敗時の停止位置、rollback、連絡先。

secretはcommand line、shell履歴、証跡へ直接書かず、承認済みsecret参照を使う。

## 3. 通常起動

| 手順 | 実command／期待結果 |
|---|---|
| 1. 対象context表示 | `<provider-cli context show>`／台帳のaccount・region・clusterと完全一致 |
| 2. 依存先状態 | `<db/queue/object/kms/idp status commands>`／全必須依存先がready、DBはread-write primary一意 |
| 3. migration状態 | `<migration status command>`／承認済みversionと一致。起動時の暗黙migrationは禁止 |
| 4. BFF起動 | `<service start-or-scale command>`／期待instance数へ到達 |
| 5. BFF readiness | `<readiness command>`／全instanceがready、timeout値も記入 |
| 6. Web配備 | `<web rollout command>`／承認digest一致 |
| 7. 合成確認 | `<synthetic login/read/push/pull command>`／RLS範囲内で全検査0終了 |
| 8. traffic復帰 | `<traffic enable command>`／段階比率とSLOを確認 |

## 4. 通常終了

利用者影響を承認したmaintenance時だけ実行する。DB、object、queue、KMSはWeb/BFFと同時に停止しない。

| 手順 | 実command／期待結果 |
|---|---|
| 1. 変更凍結・告知 | `<maintenance enable command>`／新規管理write停止、offline記録の扱いを告知 |
| 2. traffic drain | `<traffic drain command>`／新規request 0、in-flightがtimeout内に0 |
| 3. queue確認 | `<queue/outbox server status command>`／未処理数と最古時刻を証跡化 |
| 4. BFF停止 | `<service stop-or-scale command>`／instance 0 |
| 5. 停止確認 | `<readiness and listener check>`／接続失敗またはmaintenance応答が仕様どおり |
| 6. 保全確認 | `<wal/backup/audit flush check>`／WAL、監査、recovery set欠落なし |

端末側outboxは削除しない。DB停止が必要な保守は別のDB provider手順とbackup／restore手順で、standby、WAL、RPOを確認して行う。

## 5. 再起動・rolling restart

| 手順 | 実command／期待結果 |
|---|---|
| precheck | `<instance count, P0 health, error budget command>`／余力あり、release freezeなし |
| 1台ずつ再起動 | `<rolling restart command>`／同時停止数上限を明記 |
| 進行確認 | `<rollout status command with timeout>`／timeout内に完了 |
| postcheck | `<synthetic and SLO command>`／login、RLS read、push/pull、P0が合格 |
| abort | `<rollout pause/rollback command>`／burn、5xx、同期失敗時に実行 |
