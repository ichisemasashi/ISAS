# ISAS 開発工程表（第1版）

- 版: 0.21
- 日付: 2026-09-13
- 要求の正本は [要求仕様書.md](要求仕様書.md) とする。工程ごとの振る舞いは [基本仕様書.md](基本仕様書.md) とする。第1版の論理構成は [基本設計書.md](基本設計書.md) とする。本紙は、第1版をどの順で作るかと、毎回の作業手順だけを定める。
- 日程の日付は置かない。工程は番号順に進め、次工程の先取りをしない。

## 1. 作業手順

毎回、次の順で仕事する。

1. **要求を先に見る。** 作るものは [要求仕様書.md](要求仕様書.md) に書いてあることに限る。§2 の対象外は作らない。
2. **今の工程だけを終わらせる。** 完了条件を満たしたら次へ進む。先の工程の画面やデータ構造を「ついで」に作らない。
3. **仕様変更は文書が先。** 動きを変えたくなったら、実装より先に要求仕様書を直して合意する。工程の振る舞いが変わるなら [基本仕様書.md](基本仕様書.md) も同じ合意で直す。論理構成が変わるなら [基本設計書.md](基本設計書.md) も同じ合意で直す。工程表の工程名・完了条件が変わるなら、本紙も同じ合意で直す。
4. **How の部品名は工程の着手時に最小限。** 第1版の論理構成は [基本設計書.md](基本設計書.md) とする。地図ライブラリや保存先の製品名は、その工程で迷うときだけ書く。全体の基盤製品を先に完成させない。
5. **終わりに実機で確認する。** パソコン工程はパソコンで、スマホ工程はスマホでも、完了条件を一通り操作して確かめる。論理の確認項目は基本試験仕様書（基本設計の表が目次）、経路と API の確認項目は詳細試験仕様書（詳細設計の表が目次）とする。ソースのカバレッジはこれらに代えない。
6. **工程の成果物は動くこと。** レビュー記録や運用書の整備を工程の完了条件にしない。第1版の受入は工程6だけとする。

## 工程1　招待とログイン

基本仕様: [基本仕様書.md](基本仕様書.md#工程1-招待とログイン) の工程1

基本試験: [基本試験仕様書_工程1.md](基本試験仕様書_工程1.md)

詳細設計: [詳細設計書_工程1.md](詳細設計書_工程1.md)

詳細試験: [詳細試験仕様書_工程1.md](詳細試験仕様書_工程1.md)

**目的:** イチセが1つのISASを置き、知っている相手だけが入る。

**作るもの**

- 動くWebアプリケーションの入れ物（処理は Clojure、画面は ClojureScript、間は JSON API）
- SQLite（`data/isas.sqlite`）に残す招待アカウントとパスワードによるログイン
- 置くマシン上の設定ファイル（`data/isas.conf`）による最初の管理者とSMTP。Git にはサンプル値を置く
- 再設定案内はSMTP。公開登録はしない
- 圃場ゼロの利用者もログインできること

**完了条件**

- 招待していない人は入れない。
- 招待した人がログインできる。
- 圃場を1枚も持たないアカウントで入れる。

**この工程でやらないこと**

- 地図、ガント、指示、日英切替の本実装。
- 外部IdP、多要素認証、公開サインアップ。

## 工程2　圃場台帳と地図下地

基本仕様: [基本仕様書.md](基本仕様書.md#工程2-圃場台帳と地図下地) の工程2

基本試験: [基本試験仕様書_工程2.md](基本試験仕様書_工程2.md)

詳細設計: [詳細設計書_工程2.md](詳細設計書_工程2.md)

詳細試験: [詳細試験仕様書_工程2.md](詳細試験仕様書_工程2.md)

**目的:** 自分の農地を、名前と形で地図に載せられる。

**作るもの**

- 圃場台帳（名前と形。面積は形から自動）
- 境界の手描きと修正、分割、合筆、削除
- GeoJSON 等の取込（eMAFF／筆ポリゴンの自動取得と手作業ファイル）
- 下地画像（標準／空中写真／衛星）の自動取得と切替。画像は `data/basemaps/` に置く。手作業取込も残す
- 地図の描画は OpenLayers。**作業場所決定では地理院タイルを出す。** 未設定時の初期範囲は東経129〜146・北緯26〜46
- 利用者に紐づく作業場所の空中写真を初期表示とすること。作業場所は地理院タイルで位置と範囲を決め、最終確認に空中写真を使う
- 一覧は ha、詳細は ㎡
- 自分の圃場だけが見える地図

**完了条件**

- パソコンで圃場を描き、名前を付け、面積が出る。削除・分割・合筆ができる。
- 取り込んだポリゴンを直して保存できる。
- 下地を自動取得（または手作業取込）し、標準地図／空中写真／衛星で切り替えられる。
- 作業場所を地理院タイルで決め、最終確認に空中写真を使える。
- 他人の圃場は見えない。

**この工程でやらないこと**

- 塗り、作業名、ガント、指示。
- 農地ナビの画面埋め込み、キャプチャ専用 UI。
- 作物・地番・所有者などの台帳項目。

## 工程3　作業名と塗り

基本仕様: [基本仕様書.md](基本仕様書.md#工程3-作業名と塗り) の工程3

基本試験: [基本試験仕様書_工程3.md](基本試験仕様書_工程3.md)

詳細設計: [詳細設計書_工程3.md](詳細設計書_工程3.md)

詳細試験: [詳細試験仕様書_工程3.md](詳細試験仕様書_工程3.md)

**目的:** 作業結果の正本を地図に置く。

**作るもの**

- 作業名（完全一致。前後空白のみ無視。候補は自分の履歴だけ）
- ブラシ入力 → 下書きを重ねて1回確定でポリゴン → 面積。切り取りと和集合は JTS
- 圃場内の分割塗り。同じ圃場・同じ作業名の塗り面積の合算。全面完了
- 作業名を選んだときの地図色（未 `#c8c8c8`／一部 `#e6b800`／済 `#2e7d32`）。未選択なら形だけ
- 所有者だけが塗れること
- 確定した塗りの個別削除と全削除
- 塗りがある圃場は分割・合筆できないこと

**完了条件**

- 同じ圃場に「田植え」と「田植」を別実績として塗れる。
- 一部塗りと全面完了で、色と面積が変わる。
- 圃場ゼロの利用者は塗れない。

**この工程でやらないこと**

- ガント、パーセントサークル、指示、日誌。
- 作業名の同義語吸収や日英の二本立て。

## 工程4　ガントと進捗％

基本仕様: [基本仕様書.md](基本仕様書.md#工程4-ガントと進捗) の工程4

基本試験: [基本試験仕様書_工程4.md](基本試験仕様書_工程4.md)

詳細設計: [詳細設計書_工程4.md](詳細設計書_工程4.md)

詳細試験: [詳細試験仕様書_工程4.md](詳細試験仕様書_工程4.md)

**目的:** 自分の予定を工程ガントで持ち、選んだ行の面積％を見る。

**作るもの**

- ガント（行＝タスク、時間軸＝日時、時刻まで）。時間軸とバーは ClojureScript。専用製品は置かない。時間軸の向き（横／縦）を切替えられる
- 開いたときの時間軸は今日 0:00 から 72 時間。週・8週・月へ広げられる
- 題名と作業名の別欄
- 自分の圃場だけを対象に付けられること
- 対象圃場がある行は作業名必須。両方無い行はメモ（％なし）。作業名だけの行も％なし
- 行はソフト削除できる。重なりは許す。圃場が1枚以上ある利用者だけが使う
- 日次確定％の履歴。ログイン／ガント開封時の自動確定と管理者確定
- 選択中ガント行のパーセントサークル（分母＝対象面積、分子＝その作業名の塗り面積）。SVG
- 選択中行の対象圃場を進捗色、他の自分の圃場は薄い色 `#e8e8e8`

**完了条件**

- メモ行および対象圃場が無い行に％が出ない。
- 圃場付き行を選ぶと、工程3の塗りと一致した％と色になる。
- 他人の圃場をガント対象にできない。
- 行をソフト削除できる。圃場が0枚の利用者はガントを使えない。
- 日次％が確定され、振り返りで読める。

**この工程でやらないこと**

- 指示との同期、他人の圃場表示、スマホ専用画面。
- カレンダー専用UI（工程ガント以外）。

## 工程5　指示・日誌・関係・スマホ

基本仕様: [基本仕様書.md](基本仕様書.md#工程5-指示日誌関係スマホ) の工程5

基本試験: [基本試験仕様書_工程5.md](基本試験仕様書_工程5.md)

詳細設計: [詳細設計書_工程5.md](詳細設計書_工程5.md)

詳細試験: [詳細試験仕様書_工程5.md](詳細試験仕様書_工程5.md)

**目的:** 時々の依頼を回し、助っ人がスマホで進捗を見て日誌を書ける。所有者が帰宅後に地図を塗る流れが通る。

**作るもの**

- 指示（日付＝暦日、開始・終了は同じ日の時刻。作業名、依頼文、受け手複数、出した人の圃場のみ複数）
- 出した人が手で閉じる。閉じる前は依頼文と時刻だけ直せる。再開しない
- 任意の日誌（受け手1人1通。パソコンでも狭い画面でも書ける。書いたら直せない。閉じたあとは書けない）
- 一度対象になった相手の圃場だけが以降も見える。その圃場に限り、関係した作業名の進捗色が見える
- 進捗地図は対象が見える位置。自分の作業場所の下地を重なる範囲だけ張る。他人の下地は使わない。作業場所の値は変えない
- 関係の切断は管理者だけ。二人のあいだを双方向で切る。どちらの向きでも進行中の指示があるときは不可
- スマホ: 受けた／出した指示の対象の進捗閲覧と、受けた指示への日誌。塗り・境界・ガント編集は無い

**完了条件**

- 自分だけで地図を塗る流れは、指示無しのまま工程4までどおり動く。
- 招待した相手に指示を出し、相手がスマホで対象圃場の色を見て日誌を書ける。
- 出した人がパソコンで塗り、指示を閉じられる。日誌が無くても閉じられる。
- 対象外の相手圃場は見えない。管理者が二人の関係を双方向で切ると、互いに見えなくなる。
- どちらの向きでも進行中の指示がある二人は、管理者も切れない。

**この工程でやらないこと**

- 通知、写真、チャット。
- 指示とガントの自動紐づけ。
- オフライン下書き。

## 3. 工程をまたいで守ること

- 実績の正本は地図の塗りである。予定はガントと指示の二冊で、混ぜない。
- 作業名は一致キーである。翻訳しない。
- 地図の下地と形の種は eMAFF（自動または手作業）からの取込である。国土地理院タイルは作業場所の決定・最終確認・下地自動生成に使い、圃場編集地図の常時下地にはしない。塗る対象は自分のポリゴンである。
- 一人あたりおおよそ150枚で操作が成立すれば、第1版の規模としては足りる。
