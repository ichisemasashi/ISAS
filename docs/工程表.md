# ISAS 開発工程表（第1版）

- 版: 0.1
- 日付: 2026-09-12
- 要求の正本は [要求仕様書.md](要求仕様書.md) とする。本紙は、第1版をどの順で作るかと、毎回の作業手順だけを定める。
- 日程の日付は置かない。工程は番号順に進め、次工程の先取りをしない。

## 1. 作業手順

毎回、次の順で仕事する。

1. **要求を先に見る。** 作るものは [要求仕様書.md](要求仕様書.md) に書いてあることに限る。§2 の対象外は作らない。
2. **今の工程だけを終わらせる。** 完了条件を満たしたら次へ進む。先の工程の画面やデータ構造を「ついで」に作らない。
3. **仕様変更は文書が先。** 動きを変えたくなったら、実装より先に要求仕様書を直して合意する。工程表の工程名・完了条件が変わるなら、本紙も同じ合意で直す。
4. **How は工程の着手時に最小限。** その工程で迷う決定（地図ライブラリ、保存先など）だけ書く。全体の基盤設計を先に完成させない。
5. **終わりに実機で確認する。** パソコン工程はパソコンで、スマホ工程はスマホでも、完了条件を一通り操作して確かめる。
6. **工程の成果物は動くこと。** レビュー記録や運用書の整備を工程の完了条件にしない。第1版の受入は工程6だけとする。

## 2. 工程の見方

## 工程1　招待とログイン

基本仕様: [基本仕様書_工程1.md](基本仕様書_工程1.md)

**目的:** イチセが1つのISASを置き、知っている相手だけが入る。

**作るもの**

- 動くWebアプリケーションの入れ物
- 招待したアカウント（メール等）とパスワードによるログイン
- 招待（公開登録はしない）
- 圃場ゼロの利用者もログインできること

**完了条件**

- 招待していない人は入れない。
- 招待した人がログインできる。
- 圃場を1枚も持たないアカウントで入れる。

**この工程でやらないこと**

- 地図、ガント、指示、日英切替の本実装。
- 外部IdP、多要素認証、公開サインアップ。

## 工程2　圃場台帳と地図下地

基本仕様: [基本仕様書_工程2.md](基本仕様書_工程2.md)

**目的:** 自分の農地を、名前と形で地図に載せられる。

**作るもの**

- 圃場台帳（名前と形。面積は形から自動）
- 境界の手描きと修正、分割、合筆、削除
- GeoJSON 等の取込（eMAFF 農地ナビ／筆ポリゴン由来のファイルを想定）
- eMAFF から取り込んだ下地画像（標準／空中写真／衛星）の切替
- 利用者に紐づく作業場所の空中写真を初期表示とすること
- 一覧は ha、詳細は ㎡
- 自分の圃場だけが見える地図

**完了条件**

- パソコンで圃場を描き、名前を付け、面積が出る。削除・分割・合筆ができる。
- 取り込んだポリゴンを直して保存できる。
- 下地を、eMAFF から取り込んだ標準地図／空中写真／衛星で切り替えられる。
- 他人の圃場は見えない。

**この工程でやらないこと**

- 塗り、作業名、ガント、指示。
- 農地ナビの画面埋め込み、キャプチャ下地、地理院タイルの直接表示。
- 作物・地番・所有者などの台帳項目。

## 工程3　作業名と塗り

**目的:** 作業結果の正本を地図に置く。

**作るもの**

- 作業名（完全一致。前後空白のみ無視。候補は自分の履歴だけ）
- ブラシ入力 → 確定でポリゴン → 面積
- 圃場内の分割塗り
- 同じ圃場・同じ作業名の塗り面積の合算
- その作業名の全面完了
- 作業名を選んだときの地図色（済／一部／未）。未選択なら形だけ
- 所有者だけが塗れること

**完了条件**

- 同じ圃場に「田植え」と「田植」を別実績として塗れる。
- 一部塗りと全面完了で、色と面積が変わる。
- 圃場ゼロの利用者は塗れない。

**この工程でやらないこと**

- ガント、パーセントサークル、指示、日誌。
- 作業名の同義語吸収や日英の二本立て。

## 工程4　ガントと進捗％

**目的:** 自分の予定を工程ガントで持ち、選んだ行の面積％を見る。

**作るもの**

- ガント（行＝タスク、横軸＝日時、時刻まで）
- 題名と作業名の別欄
- 自分の圃場だけを対象に付けられること
- 対象圃場がある行は作業名必須。両方無い行はメモ（％なし）
- 選択中ガント行のパーセントサークル（分母＝対象面積、分子＝その作業名の塗り面積）
- 選択中行の対象圃場を進捗色、他の自分の圃場は薄い色

**完了条件**

- メモ行（圃場も作業名も無し）に％が出ない。
- 圃場付き行を選ぶと、工程3の塗りと一致した％と色になる。
- 他人の圃場をガント対象にできない。

**この工程でやらないこと**

- 指示との同期、他人の圃場表示、スマホ専用画面。
- カレンダー専用UI（工程ガント以外）。

## 工程5　指示・日誌・関係・スマホ

**目的:** 時々の依頼を回し、助っ人がスマホで進捗を見て日誌を書ける。所有者が帰宅後に地図を塗る流れが通る。

**作るもの**

- 指示（日付、開始・終了時刻、作業名、依頼文、受け手複数、出した人の圃場のみ複数）
- 出した人が手で閉じる
- 任意の日誌（指示1件に対し受け手1人1通。「やった」のみ。％は記録でも地図を上書きしない）
- 一度対象になった相手の圃場だけが以降も見える。その圃場に限り、関係した作業名の進捗色が見える
- 関係の切断（進行中の指示があるときは不可）
- スマホ: 関係した進捗の閲覧と日誌。塗り・境界・ガント編集は無い

**完了条件**

- 自分だけで地図を塗る流れは、指示無しのまま工程4までどおり動く。
- 招待した相手に指示を出し、相手がスマホで対象圃場の色を見て日誌を書ける。
- 出した人がパソコンで塗り、指示を閉じられる。日誌が無くても閉じられる。
- 対象外の相手圃場は見えない。関係を切ると見えなくなる。
- 進行中の指示がある相手は切れない。

**この工程でやらないこと**

- 通知、写真、チャット。
- 指示とガントの自動紐づけ。
- オフライン下書き。

## 工程6　日英切替と第1版の受入

**目的:** 第1版として一通り使えることを確認する。

**作るもの**

- 画面のボタン・見出し・日付表示の日本語／英語切替（データは翻訳しない）
- 工程1〜5を通した受入操作の確認

**完了条件**

- UI言語を切り替えても、作業名と塗りと％は変わらない。
- 要求仕様書 §1 の目的4項を、実データ（自分の圃場と、招待した1人の助っ人）で操作して満たせる。
- 要求仕様書 §2 の対象外が、画面にも工程にも混入していない。

**この工程でやらないこと**

- 対象外機能の復活。
- 運用マニュアルや本番多重化の整備を第1版の必須にしない。

## 3. 工程をまたいで守ること

- 実績の正本は地図の塗りである。予定はガントと指示の二冊で、混ぜない。
- 作業名は一致キーである。翻訳しない。
- 地図の下地と形の種は eMAFF からの取込である。国土地理院タイルは直接表示しない。塗る対象は自分のポリゴンである。
- 一人あたりおおよそ150枚で操作が成立すれば、第1版の規模としては足りる。
