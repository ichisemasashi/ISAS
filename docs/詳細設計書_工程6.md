## 1. この工程で実現すること

画面の日本語／英語を切り替えられるようにする。そのうえで、工程1〜5を実データで一通り操作し、第1版として使えることを確認する。

工程6で動かす論理ブロックは、基本設計書 §10 のとおり、言語切替である。加えて、工程表どおり工程1〜5の受入操作を行う。

### 1.1 工程6の部品

- **入れ物。** 工程1〜5の Clojure / ClojureScript / API / SQLite を足して使う。新しい別アプリは置かない。
- **切替の対象。** ボタン、見出し、案内、日付の出し方、単位のラベル。失敗の `code` に対する画面文言も含む。
- **切替ないもの。** 圃場名、作業名、日誌、依頼文、題名、メールアドレス、ha と ㎡ の数値、塗り面積、パーセントサークルの数値。作業名は一致キーのまま。
- **既定。** 最初に出す言語は日本語とする。端末の `Accept-Language` には合わせない。
- **ログイン前。** 入口ごと（利用者／管理者）に ClojureScript の `localStorage`。キーは `isas_guest_lang_user` と `isas_guest_lang_admin`。値は `ja` / `en`。無い・不正なら日本語。サーバのアカウントには残さない。
- **辞書。** ClojureScript に日本語と英語の対を置く。専用の i18n 製品は置かない。本書に全対訳は列挙しない。工程1〜5の「画面に出す文言」表がキーの正本である。
- **再設定メール。** 依頼したときのログイン前言語に合わせる。画面が英語なら英語の件名と本文を送る。
- **受入。** 別紙の手順書や記録票は必須にしない。本書 §7 を実データで操作して満たす。

## 2. 画面と経路

新しいブラウザ経路は置かない。工程1〜5の画面に切替を足す。

### 2.1 切替を出す場所

- 利用者入口 `/`、再設定 `/reset/request`、`/reset`
- 管理者入口 `/admin`、再設定 `/admin/reset/request`、`/admin/reset`
- ログイン後の利用者画面（ホーム、台帳、地図、ガント、指示、他人の圃場、招待、パスワード）
- ログイン後の管理者画面（ホーム、招待、取消し、関係の切断、パスワード）
- 狭い画面の指示一覧・詳細も同じ（アカウントの言語）

配置のピクセルは定めない。言語は1つの選択（`<select data-select="lang">`）で、選択肢に日本語と English を出し、今の言語が選ばれた状態とする。言語ごとに独立した切替ボタンは置かない。

`html` の `lang` は、今出している言語に合わせる（`ja` または `en`）。

同じ「複数から1つを選ぶ」切替は、ガント横軸（日／週／月）、地図の操作（browse の入口）、下地の種類でも、それぞれ1つの選択にする。機能ごとに並んだ独立ボタンで切替えない。

### 2.2 API（Clojure）

工程1と同じ JSON の形とする。値は `ja` または `en` だけとする。

| 経路 | 方法 | 誰 | ログイン | 役割 |
|---|---|---|---|---|
| `/api/user/session` | GET | 利用者 | 任意 | 工程1に `ui_lang` を足す。入っていれば `"ja"` または `"en"`。未設定は `"ja"`。入っていなければ工程1どおり `unauthorized`（ゲストの言語は返さない） |
| `/api/admin/session` | GET | 管理者 | 任意 | 同上 |
| `/api/user/language` | PUT | 利用者 | 必要 | `{ "ui_lang": "ja" \| "en" }`。アカウントに残す |
| `/api/admin/language` | PUT | 管理者 | 必要 | 同上 |
| `/api/user/password/reset/request` | POST | 利用者 | 不要 | 工程1の `{ "email" }` に任意の `"ui_lang"` を足す。画面は今のログイン前言語を載せる。無い・不正なら日本語のメール |
| `/api/admin/password/reset/request` | POST | 管理者 | 不要 | 同上 |

ログイン前の画面切替は API を呼ばない。`localStorage` だけ変える。アカウントには残さない。

`reset/request` の返事は工程1どおり常に `ok: true` とする。`ui_lang` が不正でも `lang_invalid` は返さない（日本語メールにする）。

失敗の `code` を工程6で足すもの:

| code | 使うとき |
|---|---|
| `lang_invalid` | 言語の PUT で `ja` / `en` 以外 |

### 2.3 ログイン前

- 利用者入口と管理者入口で、言語は別とする。片方を英語にしても、他方は既定の日本語のままとする。
- 残し方は、入口ごとの `localStorage`（§1.1）。アカウントには残さない。
- 同じ入口の再設定画面は、その入口のログイン前言語で出す。
- ログインした直後は、アカウントの `ui_lang` で出す。未設定は日本語。ログイン前が英語でも、アカウントが日本語なら日本語にする。

### 2.4 ログイン後

- 切替えたらすぐ PUT し、そのアカウントに残す。別の端末・別の画面幅でも、次の session 取得から同じ言語になる。
- 管理者と利用者は別アカウントなので、言語も別である。
- ログアウトしたあとの入口は、ログイン前の規則に戻る。アカウントの言語を入口へは書き戻さない。

## 3. 処理の規則

### 3.1 何を訳すか

訳す:

- 工程1〜5の画面文言（見出し、ボタン、案内、未／一部／済、下地の種名、パソコン案内）
- `code` から付ける失敗メッセージ
- 単位のラベル（日本語「㎡」「％」、英語は `m²` と `%`）。`ha` のラテン文字はそのまま
- 日付・時刻の **出し方**。日本語は `2026年9月12日 8:00`（月日はゼロ無し、分は2桁）。英語は `12 Sep 2026 08:00`（分は2桁）。日付だけのときは時刻を付けない（日本語 `2026年9月12日`、英語 `12 Sep 2026`）

訳さない（保存値も応答の生の値もそのまま）:

- 圃場名、作業名、ガントの題名、依頼文、日誌本文、メールアドレス、初期パスワード
- 面積の数値、パーセントサークルの数値（整数％の計算は工程4のまま）
- API の経路、`code` の文字列そのもの、GeoJSON

### 3.2 日付と時刻の値

API の `start_at`、`work_date`、`start_time` などの保存形式は工程4・5のままとする。画面だけ、今の言語で整形して出す。入力欄はこれまでどおり `YYYY-MM-DD` と `HH:MM`（およびガントの `YYYY-MM-DDTHH:MM`）を受けてよい。表示の形は §3.1 のとおりとする。

### 3.3 再設定メール

依頼 API に載った `ui_lang` で件名と本文を出す。リンクの経路は工程1のままとする。アカウントの `ui_lang` は見ない（ログイン前の依頼のため）。

| | 日本語（工程1） | 英語 |
|---|---|---|
| 利用者の件名 | ISAS パスワードの再設定 | ISAS password reset |
| 管理者の件名 | ISAS 管理者パスワードの再設定 | ISAS admin password reset |

本文に含める事実は工程1と同じとする（リンク、24時間で使えなくなること、心当たりが無ければ無視してよいこと）。英語の字面は実装で対を足す。招待メールは送らない。

### 3.4 対象外を足さない

工程6の実装で、要求仕様書 §2 の対象外（農機、GAP、在庫、オフライン、通知、写真、印刷、Excel、公開登録、RTL、日本語・英語以外）の入口も機能も足さない。作業名の日英同義も足さない。

## 4. 残す情報（工程6）

工程1の `users` と `admins` に列を足す。新しい表は持たない。

| 表 | 列 | 型 | 内容 |
|---|---|---|---|
| `users` | `ui_lang` | TEXT 空可 | `ja` / `en`。空または未設定は日本語 |
| `admins` | `ui_lang` | TEXT 空可 | 同上 |

ゲスト用の言語列は持たない。

## 5. 画面に出す文言（工程6）

工程6で足す切替そのものの日本語は次とする。英語の対は実装で足す。

| 場面 | 文言（日本語） |
|---|---|
| 言語の選択ラベル | 言語 |
| 日本語 | 日本語 |
| English | English |
| 今の言語（日本語） | 選択肢「日本語」が選ばれている |
| 今の言語（英語） | 選択肢「English」が選ばれている |

工程1〜5に既にある日本語は残し、同じキーに英語を足す。ここへ再掲しない。

## 6. 工程6で作らないもの

- 日本語・英語以外、RTL、端末言語への追従
- 作業名の日英同義、データの翻訳
- 翻訳文面の別冊、受入手順書の体裁を成果物にすること
- 運用マニュアル、本番多重化、監視
- 要求仕様書 §2 の対象外機能
- 言語専用のブラウザ経路

## 7. 完了として満たすこと（詳細）

基本仕様書 §6.4 と §6.6 を、次の操作で満たす。記録票は必須にしない。データは、イチセの利用者アカウント（自分の圃場）と、招待した助っ人1人とする。

1. 管理者が入り、利用者を招待できる。招待していないメールでは利用者として入れない。
2. 利用者が作業場所を決め、空中写真を初期表示にし、eMAFF 由来の形と下地を取り込み、圃場を描き・直し・削除できる。
3. 所有者がパソコンで作業名を選び、一部塗りと全面完了ができ、色と面積が変わる。
4. 圃場付きのガント行を選ぶと、塗りと一致した％と色になる。メモ行に％は出ない。
5. 助っ人に指示を出し、助っ人が狭い画面で対象圃場の色を見て日誌を書ける。所有者はパソコンで塗り、日誌無しでも指示を閉じられる。
6. 対象外の相手圃場は見えない。指示が無くても 2〜4 が動く。
7. 画面を日英切替えても、作業名と塗りと％の数値は変わらない。ログイン前の利用者入口・管理者入口と、管理者のログイン後画面でも切替えられる。ログイン後に選んだ言語はアカウントに残り、別の端末でも同じになる。ログイン前に英語にして入っても、アカウントが日本語なら日本語になる。英語の入口から再設定を依頼すると、英語の案内メールが飛ぶ。
8. 要求仕様書 §2 の対象外が、画面の入口にも機能にも出ていない。

## 11. 確定した判断

1. **ログイン前の言語の残し方。** 入口ごと（利用者／管理者）に ClojureScript の `localStorage` とする。サーバのアカウントには残さない。
2. **日付・時刻の画面上の出し方。** 日本語は `2026年9月12日 8:00`、英語は `12 Sep 2026 08:00` とする。
3. **再設定メールの言語。** 依頼したときのログイン前言語に合わせる。英語の件名と本文も持つ。画面は今の言語を `ui_lang` として依頼 API に載せる。
