## 1. この工程で実現すること

公開済みの親メモとガント作業（行）を任意で1件まで紐づけられるようにする。紐づけても実行状態・塗り・面積％・作業時間・チェック・指示／日誌は自動では変わらない。あわせて、工程1〜4を通した受入操作で要求 §10 を満たすことを確認する。

### 1.1 部品

- **紐づけ列。** `memos.gantt_id`（NULL＝未紐づけ）。別リンク表は作らない。
- **API。** `PUT` / `DELETE /api/memos/{id}/gantt`。本文の編集窓とは独立。
- **要約。** メモを読める応答に `gantt`（id・表示名・削除フラグ）。実行状態・時間・チェックは含めない。
- **候補。** 利用者は `GET /api/user/gantt`（この工程で圃場0枚も一覧成功）。管理者は `GET /api/admin/gantt/rows`。
- **画面。** 公開済み親メモの詳細（パソコン・狭幅とも）。日次・ガント側の付け外しは必須にしない。

## 2. 画面と経路

### 2.1 メモ詳細（`/memos` の親の詳細。狭幅も同じ）

公開済み親メモに、次を出す。

- **未紐づけ:** 作成者または管理者には「作業を紐づける」。それ以外の閲覧者には紐づけ欄を出さない（または「なし」）。
- **紐づけあり・作業が未削除:** 表示名（`title`）を出す。作成者・管理者は付け替えと外しができる。
- **紐づけあり・作業がソフト削除済み:** 「削除済み」と分かる。表示名が残っていれば併記してよい。作成者・管理者は外すか、未削除の別作業へ付け替えできる。
- 閲覧者から、他人の作業の実行状態・時間・チェックを編集する導線は持たない。

下書き・返信の画面には紐づけ操作を出さない。

候補の選び方は選択リストとする。候補0件のときは「付けられる作業がありません」。

`/daily`・`/gantt`・`/works` に付け外しを必須では置かない。

### 2.2 API

利用者セッションまたは管理者セッションが必要。

| 経路 | 方法 | 役割 |
|---|---|---|
| `/api/memos/{id}/gantt` | PUT | 公開済み親に作業を1件紐づける（既存があれば置き換え） |
| `/api/memos/{id}/gantt` | DELETE | 紐づけを外す |
| `/api/user/gantt` | GET | 自分の未削除作業の候補。この工程から圃場0枚でも成功 |
| `/api/admin/gantt/rows` | GET | 全利用者の未削除作業の候補（管理者のみ） |

メモの GET・タイムラインは工程3のオブジェクトに `gantt` を足す（§2.3）。

#### 2.2.1 PUT 本文

```
{ "gantt_id": 123 }
```

成功時のメモオブジェクトに `gantt` を含めてよい。

`gantt_id` が無い、または整数でないときは `gantt_id_required`。

#### 2.2.2 DELETE

紐づけが無くても成功（冪等）。`gantt_id` を NULL にする。

#### 2.2.3 要約 `gantt`

紐づけが無いときは `null`。

```
{
  "id": 123,
  "title": "東の防除",
  "deleted": false
}
```

作業行がソフト削除済みなら `deleted: true`。`title` は行に残っていれば返す。実行状態・作業時間・チェック・面積％は **返さない**。

#### 2.2.4 管理者の候補

`GET /api/admin/gantt/rows` の各行は少なくとも:

```
{
  "id": 123,
  "title": "東の防除",
  "user_id": 3,
  "user_email": "a@example.com",
  "start_at": "2026-09-21T08:00",
  "end_at": "2026-09-21T17:00"
}
```

未削除のみ。並びは `start_at`、同じなら `user_id`、同じなら `id`。利用者セッションは `forbidden`。

#### 2.2.5 失敗の `code`（この工程で足すもの）

| code | 使うとき |
|---|---|
| `link_not_allowed` | 下書きまたは返信に付け外ししようとした |
| `gantt_id_required` | PUT に有効な `gantt_id` が無い |
| `gantt_not_found` | 行が無い、ソフト削除済み、または利用者から見て他人の行 |
| `forbidden_memo` | 作成者でも管理者でもない者が付け外しした（工程3と同名） |
| `memo_not_found` | メモが無い、または通常操作で見えない（工程3） |

編集窓の外でも、上の成功条件を満たせば `edit_window_closed` にはしない。

## 3. 処理の規則

### 3.1 誰が付け外しできるか

- そのメモの作成者、および管理者。
- それ以外の招待利用者は `forbidden_memo`。

### 3.2 対象

- メモは `status = published` かつ `parent_id` が NULL かつ未削除。
- 作業は `deleted_at` が NULL。
- 利用者は `gantt_rows.user_id` が自分の行だけ。
- 管理者は全利用者の未削除行。
- ソフト削除済み作業への新規紐づけは `gantt_not_found`。既に付いている削除済みは要約の `deleted: true` のまま残す。外す・未削除への付け替えは可。

### 3.3 最大1件

- `PUT` は `gantt_id` を上書きする。履歴表は持たない。
- 1作業に複数メモが付いてよい（複数の `memos.gantt_id` が同じ行を指してよい）。

### 3.4 編集窓との独立

- 付け外しは `content_saved_at` を更新しない。本文・タグ・リンク・添付の30分規則は工程3のまま。

### 3.5 自動連動の禁止

付けても外しても、次を変えない。

- `execution_status`
- 塗り・面積％・地図色・日次確定％
- 作業時間・チェック項目
- 指示・日誌

タグや作業名の一致で `gantt_id` を自動設定しない。

### 3.6 ソフト削除

- **作業をソフト削除:** `memos.gantt_id` は残す。メモ GET では `deleted: true`。メモ自体は消えない。
- **メモをソフト削除:** 工程3どおりメモと子孫が通常操作から消える。`gantt_id` は行に残してよい。ガント／日次に「この作業のメモ」一覧は必須にしない。
- 検索対象は工程3のまま（本文・タグ・ファイル名）。作業名検索・紐づけ有無フィルタは必須にしない。

### 3.7 圃場0枚と候補一覧

- `GET /api/user/gantt` は、この工程から圃場0枚の利用者でも **自分の未削除行の一覧**を成功で返す（空配列可）。`no_fields` にしない。
- 行の作成・更新・削除、実行状態の変更、作業時間・チェックの変更は、圃場0枚では従来どおり解禁しない（`no_fields` のままでよい）。
- パソコンの日次一覧の対象者は工程1のまま（圃場0枚・管理者はパソコン日次を持たない）。狭幅閲覧は工程4のまま。

## 4. 残す情報

`memos` に列を1つ足す。

| 列 | 型 | 内容 |
|---|---|---|
| `gantt_id` | INTEGER | `gantt_rows.id`。NULL＝未紐づけ。外部キーは付けてよいが、作業ソフト削除時に行を消さない（参照を残す） |

起動時に列が無ければ追加する。既存メモは NULL。

作業の物理削除で参照が壊れる運用は、この工程では行わない（ソフト削除のみ）。

## 5. 画面に出す文言

| 場面 | 文言 |
|---|---|
| 紐づける | 作業を紐づける |
| 外す | 紐づけを外す |
| 付け替え | 別の作業に付け替える |
| 削除済み | 削除済み |
| 候補なし | 付けられる作業がありません |
| なし | なし |

## 6. この工程で作らないもの

- 実行状態・塗り・％・時間・チェック・指示／日誌の自動同期
- タグ・作業名による自動紐づけ
- 下書き・返信への紐づけ
- ガント／日次からの付け外し必須、「この作業のメモ」一覧必須
- 紐づいた作業名での必須検索、「紐づけあり／なし」必須フィルタ
- 要求 §2 の対象外、§8 の任意の必須化
- 運用マニュアル・本番多重化を受入必須にすること
- 要約への実行状態・時間・チェックの同梱

## 7. 第2版の受入（操作確認）

実データは、自分の圃場を持つ利用者と、招待した別メンバ（および必要なら管理者）とする。次を一通り操作する。

1. パソコンで今日／今週のガント作業を未着手／着手中／完了に変えられる（工程1）。
2. 面積以外の作業に作業時間とチェックを付けられ、無くても日次が使える（工程2）。実行状態は自動では変わらない。
3. 招待利用者と管理者が、パソコンと狭幅でメモを投稿・閲覧・返信・検索・ブックマークできる（工程3・4）。
4. 狭幅で日次を閲覧できる（変更できない）。下部ナビから指示の進捗色・日誌へ辿れる（工程4）。
5. 公開済み親メモに作業を付け、外し、別作業へ付け替えられる（作成者および管理者。パソコンと狭幅）。下書き・返信には付けられない。
6. 紐づけたあと、塗り・％・実行状態・時間・チェック・指示／日誌が自動では変わっていない。
7. 作業をソフト削除するとメモ側が「削除済み」と分かり、メモをソフト削除すると通常の一覧から紐づきが見えない。
8. 要求 §2 の対象外が画面に無い。§8 の任意が未実装でも受入を止めない。

## 8. 完了として満たすこと（詳細）

- `memos.gantt_id` があり、公開済み親に最大1作業を付け外しできる（PUT は置換、DELETE は冪等）。
- 編集窓の内外を問わない。作成者と管理者のみ。利用者は自分の未削除作業、管理者は全利用者の未削除作業。
- メモを読める人に `gantt` 要約（id・表示名・`deleted`）が見え、実行状態等は含まれない。
- 圃場0枚でも自分の作業一覧を候補にできる。日次変更や作業編集は解禁しない。
- §7 の受入操作を満たす。
- ガント側ハブ・必須検索・自動同期・§8 必須化が、この工程の必須成果に混入していない。
